판타지 용병단 로그라이크 오토배틀러 — 기획 요약

1. 게임 개요

Unity 기반 1인 개발 인디게임.

핵심 컨셉

«판타지 세계를 모험하며 허름한 용병단을 최강의 용병단으로 성장시키는 로그라이크 오토배틀러.»

새로운 시스템의 발명보다 한 런 동안 약한 용병들을 강력한 용병단으로 성장시키는 판타지를 강하게 전달하는 것을 우선한다.

목표 플레이타임은 60~90분, 최대 약 2시간이다.

---

2. 핵심 디자인 원칙

새로운 요소는 다음 기준으로 평가한다.

1. "허름한 용병단 → 최강의 용병단"이라는 판타지를 강화하는가?
2. 60~90분 로그라이크의 빠른 템포를 해치지 않는가?
3. Unity 기반 1인 개발로 현실적인가?

복잡한 경제나 시너지보다 어떤 용병을 영입하고 누구를 집중적으로 성장시킬 것인가가 주요 의사결정이어야 한다.

---

3. 전투

- 3D 실시간 오토배틀
- 6각형 그리드 전장
- 최대 5인 파티
- 자동 이동 및 타겟 선택
- 기본 공격
- 공격 등을 통한 마나 획득
- 마나 충족 시 액티브 스킬 자동 발동
- 기본 전투시간 약 30초
- 필요하면 약 15초의 피버타임 적용

핵심 전투 판타지는:

«내가 잘 키운 용병이 자동으로 전장을 압도하는 모습을 보는 것.»

XCOM식 턴제 전투는 사용하지 않는다.

전투는 이벤트가 발생시키는 결과 중 하나다. 선택지가 있는 이벤트의 선택 결과로 전투가 시작될 수도 있고, 선택지가 없는 일방적인 이벤트에서 즉시 전투가 시작될 수도 있다.

전투에서 승리하면 이벤트의 후속 결과를 적용하고 원정으로 복귀한다. 전투에서 패배하면 즉시 게임오버로 런이 종료되므로, 이벤트는 패배 이후의 분기나 후속 결과를 정의하지 않는다.

---

4. 용병 성장

용병은 최대 4단계로 성장한다.

T1 → T2 → T3 → T4

낮은 티어에서 시작한 용병도 집중적으로 성장시키면 T4까지 도달할 수 있다.

초반에 얻은 약한 용병을 끝까지 캐리로 사용하는 플레이를 적극적으로 허용한다.

용병별 승급 루트는 기본적으로 하나로 고정한다. 분기형 클래스 전직은 현재 사용하지 않는다.

티어별 변화

T1 — 원형

- 용병의 기본 역할 확립

T2 — 강화

- 기존 역할 강화
- 비교적 저비용 변화
- 수치, 투사체, 범위, VFX 등의 변화

T3 — 확장

- 기존 스킬에 새로운 메커니즘 추가
- 관통, 폭발, 처치 효과 등의 변화

T4 — 완성

- 최종 각성
- 확실한 외형 변화
- 강력한 VFX
- 큰 스킬 변화
- 전장을 지배하는 수준의 성장 체감

모든 용병을 T4로 만드는 것보다 한두 명의 강력한 캐리를 만드는 플레이를 중요하게 본다.

용병단의 성장은 크게 세 축으로 구성한다.

- 승급: 용병의 티어를 상승시킨다.
- 아이템: 장착을 통해 용병의 능력이나 전투 메커니즘을 강화한다.
- 축복: 한 런 동안 용병단이나 플레이 방식에 영향을 주는 증강 효과를 제공한다.

세 성장 시스템은 순차적으로 구현한다. 현재 기획에서는 승급을 우선 구체화하며, 아이템과 축복의 상세 규칙은 추후 설계한다.

---

5. 승급 시스템

기본 원칙

승급은 재화를 소비하는 방식이 아니라 이벤트를 통해 이루어진다.

승급 재화를 모아 메뉴나 상점에서 승급하는 방식은 사용하지 않는다.

플레이어가 모험 중 승급 이벤트를 만나고, 해당 이벤트를 통해 용병 한 명을 다음 티어로 승급시킨다.

용병의 티어 상승은 오직 승급 이벤트를 통해서만 가능하다.

승급 이벤트가 발생하면 승급 가능한 현재 용병 중 한 명을 플레이어가 직접 선택한다. 이 방식은 플레이테스트 결과에 따라 변경할 수 있다.

승급 이벤트

다양한 형태의 승급 이벤트를 사용할 수 있다.

예:

- 특정 계열 용병을 승급시키는 이벤트
- 특정 랜드마크에서 발생하는 성장 이벤트
- 특별한 인물에게 가르침을 받는 이벤트
- 특정 전투를 승리하면 제공되는 승급
- 어떤 용병이든 선택할 수 있는 범용 승급 이벤트

승급 기회 보장

승급 보장은 Standalone Event의 강제 배치가 아니라 Main Arc의 진행 구조를 통해 제공한다.

Main Arc는 시작부터 Finale까지 존재하는 모든 유효한 진행 경로가 최소 5개의 Main Arc 주요 Location/Event를 포함하도록 구성한다.

각 유효한 Main Arc 진행 경로에서는 최소 3개의 Main Arc Event가 플레이어에게 승급을 선택할 수 있는 기회를 제공해야 한다.

승급 기회가 있다는 것은 해당 Event에 승급을 결과로 제공하는 Choice가 최소 하나 존재하고, 플레이어가 그 Event에 도달했을 때 해당 Choice를 실제로 선택할 수 있다는 뜻이다.

플레이어는 다른 Choice를 선택하여 승급을 포기할 수 있다. 따라서 보장하는 것은 실제 승급 횟수가 아니라 한 런에서 최소 3번의 승급 선택 기회다.

Main Arc가 분기하더라도 특정 분기를 선택했다는 이유로 이 최소 승급 기회 수가 줄어들어서는 안 된다.

승급 이벤트의 무게

티어가 높아질수록 승급 이벤트 역시 중요도를 높일 수 있다.

- T2: 비교적 간단하고 흔한 성장 사건
- T3: 보다 의미 있는 성장 사건
- T4: 랜드마크, 특별 이벤트, 강한 전투 등을 활용한 최종 각성

최종 승급은 해당 런에서 그 용병의 성장 서사를 완성하는 핵심 보상으로 취급한다.

---

6. 주점

주점은 기본적으로 새로운 용병을 만나는 장소다.

- 게임 시작 장소
- 최대 약 5명의 용병 후보 제시
- 골드를 지불하여 영입
- 골드가 허용하면 여러 명 영입 가능

주점에 지나치게 많은 성장/관리 기능을 넣지 않는다.

현재 기획에서는 벤치를 사용하지 않는다. 파티가 최대 인원에 도달한 뒤 새로운 용병을 어떻게 영입할지는 추후 결정한다.

---

7. 게임 오프닝

초반 3~5분 안에 핵심 루프를 보여준다.

첫 주점 → 용병단 구성 → 작은 사건 발생 → 첫 오토배틀 → 보상/강화 → 월드맵 공개 → 원정 시작

첫 전투는 고블린 습격, 도적 공격, 술집 난투 등 신생 용병단에 어울리는 작은 사건으로 구성한다.

---

8. 월드맵과 진행 구조

고정 판타지 월드맵 + 노드 기반 이동을 사용한다.

오픈월드 방식이나 자유 왕복 탐색은 사용하지 않는다. 플레이어는 현재 Main Arc Node 사이의 Travel 진행에서 이미 지나온 경로로 역행하지 않고, Travel Graph의 이동 선택 지점마다 Segment를 선택하며 앞으로 이동한다. 선택한 Segment들이 누적되어 Actual Route가 형성된다. 다만 Main Arc 진행에 따라 이전에 방문했던 Location이 이후 다시 주요 목적지로 지정되는 것은 허용한다.

월드의 지리와 Location 사이의 연결 관계는 고정되어 있으며, 모든 이동은 이 World Graph 위에서 이루어진다. Main Arc와 이벤트 생성기는 World Graph에 존재하지 않는 지리적 연결을 임의로 만들지 않는다.

주요 랜드마크의 위치와 세계 지리는 고정되어 플레이어가 세계를 기억할 수 있게 한다.

예:

- 마을
- 숲
- 폐광
- 기사단 폐허
- 주점
- 고대 신전
- 요새
- 보스 거점

### Main Arc와 Main Arc Node

Main Arc는 세부 이동 노드를 모두 지정하는 선형 Location 목록이 아니라, 서사적으로 중요한 `Main Arc Node`들로 구성된 유향 그래프다.

각 Main Arc Node는 정확히 하나의 Location과 대응하며, 해당 Location에서 하나의 핵심 Main Arc Event가 발생한다.

```text
Main Arc Node
= Main Arc의 특정 진행 시점
+ 대응하는 Location 1개
+ 해당 Location에서 발생하는 Main Arc Event 1개
```

하나의 Main Arc Node가 여러 Location에 대응할 수는 없다. 반대로 같은 Location이 서로 다른 Main Arc Node에서 다시 사용되는 것은 허용한다. 따라서 Main Arc 진행에 따라 과거에 방문했던 Location이 이후 전혀 다른 서사적 맥락으로 다시 주요 목적지가 될 수 있다.

Main Arc Node 사이의 연결은 Main Arc의 큰 서사 진행을 나타낸다. Main Arc의 구조적 진행과 대분기는 명시적인 Node ID 연결로 정의하며, Choice에 따라 다음 Main Arc Node가 달라질 수 있다. 분기된 진행은 이후 다시 합쳐질 수도 있고, 끝까지 합쳐지지 않은 채 서로 다른 Finale에 도달할 수도 있다.

Tags는 Main Arc의 다음 Node를 결정하는 주 연결 수단으로 사용하지 않는다. Tags는 플레이어가 이전에 어떤 선택과 사건을 겪었는지 기록하는 서사적 State로 사용하며, 같은 Main Arc Node 안에서의 내용과 Choice 변화, Sub Arc와 Standalone Event의 발생 조건과 변주에 활용한다.

예:

```text
                    → Kingdom Front → Orc Capital → Finale: 오크 멸망
Start → Castle ────┤
                    → Orc Camp → Human Capital → Finale: 왕국 멸망
                    → Borderlands → Independent Finale: 양측 배신
```

이러한 분기는 단순한 이동 경로 선택이 아니라 Main Arc 자체의 대분기다. 분기마다 이후 방문하는 주요 Location, 사건과 Finale가 완전히 달라질 수 있다.

서로 연결된 두 Main Arc Node 사이의 실제 이동은 World Graph 위의 Travel Graph를 통해 이루어진다. Main Arc Event는 Main Arc Node의 Location에서 발생하고, 그 사이의 Travel Node는 Sub Arc 또는 Standalone Event가 담당한다.

### Route와 Route Set

`Route`는 두 Main Arc 주요 Location을 연결하는 World Graph 위의 하나의 완주 가능한 이동 경로다. 하나의 Route 안에서는 같은 Location 또는 Travel Node를 두 번 방문할 수 없으며, 순환하는 Route는 허용하지 않는다. World Graph 자체에는 순환 구조가 존재할 수 있다.

예:

```text
Route A: Inn → Road → Village → Castle
Route B: Inn → River → Forest → Castle
Route C: Inn → Hill → Ruins → Castle
```

World Graph가 복잡한 경우 두 Location 사이에 가능한 Route가 매우 많을 수 있다. Main Arc를 생성할 때 이벤트 생성기는 가능한 모든 Route를 사용하지 않고, 유효한 Route 중 일부를 미리 무작위로 선택하여 해당 구간의 `Route Set`을 구성한다. 이 Route Set은 Main Arc 콘텐츠와 함께 사전에 정해진다.

현재 단계에서는 Route의 품질, 위험도나 테마를 평가해 선택하지 않고 무작위 선택으로 시작한다. 플레이테스트에서 필요성이 확인되면 이후 선택 기준을 추가한다.

Route는 플레이어가 그대로 선택해 끝까지 따라가는 고정 코스가 아니라, 해당 Main Arc 구간의 Travel Graph를 구성하기 위한 샘플 경로다. Route Set에 포함된 Route들을 겹쳐 하나의 Travel Graph를 만들며, 이 과정에서 서로 다른 Route가 일부 노드를 공유하거나 중간에서 분기하고 다시 합쳐질 수 있다.

실제 플레이어는 완성된 Route 하나를 처음부터 선택하지 않는다. Travel Graph의 이동 선택 지점마다 다음 Segment를 선택하며 앞으로 진행한다. 이러한 Segment 선택이 누적되어 플레이어가 실제로 지나온 `Actual Route`가 결과적으로 만들어진다. Actual Route는 사전에 선정된 샘플 Route 중 하나와 정확히 일치할 필요가 없다.

현재 Travel 구간에서는 이미 지나온 노드로 되돌아갈 수 없다. Main Arc 자체가 분기하지 않았다면 Segment를 어떤 조합으로 선택하더라도 최종적으로 동일한 다음 Main Arc Node의 Location에 도달해야 한다.

### Travel Graph와 Segment

`Travel Graph`는 하나의 Main Arc 주요 Location 구간에서 Route Set에 포함된 Route들을 겹쳐 표현한 실제 이동 선택 구조다. World Graph 전체가 아니라, 해당 Main Arc 구간에서 플레이어에게 제공되는 Route들만 포함한다.

`Segment`는 Travel Graph 안에서 플레이어가 하나의 이동 방향을 선택한 뒤, 다음 이동 선택이 발생하기 전까지 실제로 진행하게 되는 연속 Travel Node 구간이다. Segment는 그래프를 사전에 고정된 조각으로 분할한 단위가 아니라, 플레이어의 이동 선택에 따라 런타임에 확정되는 진행 단위다.

합류점 자체는 Segment의 경계가 아니다. 합류 후에도 플레이어에게 새로운 이동 선택이 발생하지 않는다면 같은 Segment가 계속된다. 따라서 서로 다른 분기 후보가 정적 Travel Graph에서 같은 노드를 공유하더라도 문제가 되지 않으며, 실제 플레이에서는 선택된 쪽의 Segment만 활성화된다.

예:

```text
         ┌→ 4 ─┐
1 → 2 → 3      → 6 → 7 → 8
         └→ 5 ─┘         ├→ 9
                         └→ 10
```

3에서 4 방향을 선택했다면 다음 이동 선택이 발생하는 8까지의 실제 Segment는 다음과 같다.

```text
Segment: 4 → 6 → 7 → 8
```

3에서 5 방향을 선택했다면 다음과 같다.

```text
Segment: 5 → 6 → 7 → 8
```

6은 합류점이지만 플레이어가 선택할 것이 없으므로 Segment를 끊지 않는다. 8에서 다시 이동 방향을 선택하면 새로운 Segment가 시작된다.

Sub Arc는 이 Segment 단위를 기준으로 배치하며, 해당 Segment가 실제로 확정된 뒤 Unity 런타임이 Sub Arc를 `0~1개` 배치할지 결정한다.

### Travel Node의 콘텐츠

Main Arc 주요 Location 사이의 모든 Travel Node에는 반드시 이벤트가 하나 존재한다. 이벤트가 없는 빈 노드는 허용하지 않는다.

각 Segment에는 Sub Arc가 `0~1개` 배치될 수 있다.

- 해당 Segment에 Sub Arc를 배치할지는 Unity 런타임이 결정한다.
- Segment가 너무 짧거나 적합하지 않다면 Sub Arc를 배치하지 않을 수 있다.
- 하나의 Sub Arc는 하나의 Segment 안에서 시작하고 완결되어야 한다.
- Sub Arc 이벤트가 Segment의 연속된 모든 노드에서 발생할 필요는 없다.
- Sub Arc가 사용하지 않는 모든 노드는 Standalone Event로 채운다.
- 현재 단계에서는 여러 Segment나 여러 Main Arc 구간에 걸쳐 이어지는 Long Sub Arc를 사용하지 않는다.

예:

```text
Segment:
Road1 → Road2 → Road3 → Lake → Road4

배치:
Road1   : Standalone
Road2   : Sub Arc 시작
Road3   : Standalone
Lake    : Standalone
Road4   : Sub Arc 결말
```

따라서 Location 이동 자체가 곧 하나의 사건을 경험하는 진행 단위가 된다.

랜드마크 사이에서 발생하는 사건은 런마다 달라진다.

즉:

«세계는 고정되어 있지만 그 세계에서 벌어지는 모험은 매번 달라진다.»

프로토타입에서는 일러스트 기반 2D 월드맵을 사용한다.

9. 이벤트와 사건군

이벤트 콘텐츠는 Main Arc, Sub Arc, Standalone Event로 구분한다.

### Main Arc

- 한 런에는 정확히 하나의 Main Arc가 존재한다.
- 런 전체의 주요 갈등과 진행 방향, 최종 결말을 담당한다.
- Main Arc는 `Main Arc Node`들로 이루어진 유향 그래프다.
- 각 Main Arc Node는 정확히 하나의 Location과 하나의 핵심 Main Arc Event에 대응한다.
- 같은 Location을 서로 다른 Main Arc Node가 사용할 수 있으며, Main Arc 진행에 의한 의도된 재방문은 허용한다.
- Main Arc의 구조적 진행과 대분기는 명시적인 Main Arc Node ID 연결로 정의한다.
- Main Arc Node의 Choice에 따라 다음 Main Arc Node가 달라질 수 있다.
- Tags는 Main Arc Node 사이의 구조적 연결을 대신하지 않는다. Tags는 이전 선택과 사건을 기록하고, 이벤트 내용과 Choice의 조건 및 변주, Sub Arc와 Standalone Event의 발생 조건에 사용한다.
- Main Arc의 대분기는 이후 주요 Location, 사건과 Finale 자체를 완전히 다르게 만들 수 있다. 분기된 진행은 이후 다시 합쳐질 수도 있고, 합쳐지지 않은 채 서로 다른 Finale에 도달할 수도 있다.
- Main Arc는 하나 이상의 `Finale Node`를 가질 수 있다. Finale Node는 Main Arc의 정상적인 종결을 나타내는 terminal node이며, 각 Finale Node도 정확히 하나의 Location과 하나의 Finale Event에 대응한다.
- 모든 유효한 정상 진행 경로는 하나의 Finale Node에 도달해야 한다. 서로 다른 분기는 서로 다른 Finale Node에서 끝날 수 있다.
- 시작부터 Finale까지의 모든 유효한 Main Arc 진행 경로는 최소 5개의 Main Arc Node/Event를 포함한다.
- 각 유효한 진행 경로에는 승급을 선택할 수 있는 Main Arc Event가 최소 3개 존재한다. 플레이어가 다른 Choice를 선택할 수 있으므로 실제 승급 횟수 자체를 보장하지는 않는다.
- 서로 연결된 Main Arc Node 사이의 실제 이동은 고정 World Graph 위에서 이루어진다.
- Main Arc 생성 시 이벤트 생성기는 두 Main Arc Node의 Location 사이에서 유효한 Route 중 일부를 무작위로 미리 선택해 Route Set을 구성한다.
- Route Set의 Route들은 실제 플레이 코스를 직접 지정하는 것이 아니라 Travel Graph를 만드는 샘플로 사용한다.
- 플레이어는 Travel Graph에서 Segment 단위로 이동 방향을 선택하고, 선택한 Segment들이 누적되어 Actual Route가 만들어진다.
- Main Arc의 Finale Node에 도달해 해당 Finale Event의 결과 처리를 완료하면 런을 `Completed` 상태로 정상 종료한다. Finale의 구체적인 결과가 유리한지 불리한지는 런 완료 여부와 별개이며, Finale 내용과 Tags 등으로 표현한다.

### Sub Arc

- 시작, 진행, 결말을 가진 선택적 퀘스트 라인이다.
- Sub Arc의 배치 단위는 Segment다.
- 하나의 Segment에는 Sub Arc가 0개 또는 1개 배치될 수 있다.
- Sub Arc를 해당 Segment에 배치할지는 Unity 런타임이 결정한다.
- 하나의 Sub Arc는 반드시 같은 Segment 안에서 시작하고 완결되어야 한다.
- Sub Arc의 이벤트들이 연속된 노드에서 발생할 필요는 없다. 중간에 Standalone Event가 끼어들 수 있다.
- 현재 단계에서는 Segment를 넘어가거나 다음 Main Arc 구간까지 이어지는 Long Sub Arc를 사용하지 않는다.
- Segment 단위 제약이 실제 플레이에서 지나치게 작위적이거나 서사를 지나치게 짧게 만든다면 플레이테스트 이후 확장을 검토한다.

예:

```text
Road1 → Road2 → Road3 → Lake → Road4
          ↑                    ↑
       Sub Arc 시작         Sub Arc 결말
```

Road3과 Lake에서는 별개의 Standalone Event가 발생할 수 있다.

### Standalone Event

- Main Arc나 Sub Arc에 속하지 않는 독립 사건이다.
- 다른 Arc를 시작하거나 그 진행 상태를 직접 변경하지 않는다.
- Sub Arc가 차지하지 않은 모든 Travel Node는 Standalone Event로 채운다.
- 따라서 Main Arc 주요 Location 사이에는 이벤트가 없는 빈 Travel Node가 존재하지 않는다.
- Standalone Event도 선택 결과로 승급을 제공할 수 있지만, 현재 승급 기회 보장의 책임은 Main Arc가 가진다.

이벤트는 서사만 전달하는 단위가 아니다. 선택 결과 또는 자동 결과로 전투나 승급 같은 실제 게임플레이를 발생시킬 수 있다.

목표는 매 런마다 정교한 고정 스토리를 제공하는 것이 아니라:

«하나의 짧은 판타지 용병단 연대기를 만드는 것.»

### 런 종료

정상적인 런 종료 조건은 다음 두 가지다.

- 전투 패배: 게임오버로 런을 `Failed` 상태로 종료한다.
- Main Arc의 Finale Node에 도달해 Finale Event의 결과 처리를 완료: 런을 `Completed` 상태로 종료한다.

`Completed`는 서사적으로 좋은 결말이나 승리를 의미하지 않는다. 오크의 멸망, 인간 왕국의 멸망, 양측의 몰락처럼 서로 상반된 결과라도 Main Arc의 유효한 Finale에 도달해 해당 결말을 완료했다면 모두 `Completed`다. 구체적인 결말은 Finale Event와 Tags 등으로 구분한다.

예외적으로 이벤트 구성이 잘못되어 더 이상 진행할 수 없는 상황이 발생하면 안전장치로 런을 강제로 종료할 수 있다. 이 경우는 정상적인 `Completed`나 전투 패배에 의한 `Failed`와 별도의 비정상 종료로 취급한다. Unity 런타임은 이러한 진행 불능 상황이 발생하지 않도록 최대한 방지해야 한다.

10. 의도적으로 제외/보류한 요소

현재 핵심 범위에서 제외하거나 보류한다.

- 복잡한 TFT식 종족/직업 시너지
- 고정 영웅/주인공
- XCOM식 턴제 전투
- 자유 이동 오픈월드
- Heroes식 전략 월드
- 벤치 시스템
- 분기형 용병 전직
- 복잡한 성장 재화 시스템

필요 이상의 시스템 추가보다 용병의 성장 체감을 강화하는 것을 우선한다.

현재 확정된 골드 사용처는 주점에서의 용병 영입이다. 파티 완성 이후를 포함한 추가 사용처는 추후 설계한다.

11. 개발 범위 원칙

가장 경계해야 하는 것은:

용병 수 × 티어 수 × 스킬 변화 × VFX × 외형 변화

에 따른 콘텐츠 제작량 증가다.

따라서 많은 용병을 얕게 만드는 것보다 적은 용병의 성장 전후를 확실하게 만드는 방향을 우선한다.

아트는 Unity Asset Store와 AI 생성 리소스를 적극적으로 활용한다.

12. 프로토타입 우선순위

가장 먼저 검증할 것은 오토배틀 전투와 성장 체감이다.

최초 프로토타입:

- 6각형 전장 1개
- 아군 3~4종
- 적 2~3종
- 자동 이동
- 타겟 선택
- 기본 공격
- 마나
- 액티브 스킬
- 승패 판정
- 간단한 강화
- 집중 성장시킨 캐리 1명

특히 평범한 검사와 강하게 성장한 검사를 비교하여, 성장한 용병이 자동으로 적을 압도하는 모습 자체가 재미있는지 검증한다.

핵심 가설:

«“내가 키운 용병이 알아서 전장을 지배하는 것이 재미있다.”»

이 가설을 먼저 검증한 후 성장 시스템, 월드맵, 이벤트, 주점 등을 결합하여 짧은 전체 플레이 사이클로 확장한다.
