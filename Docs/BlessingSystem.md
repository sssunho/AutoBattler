# 축복 시스템 명세

개정일: 2026-10-17

이 문서는 원정 중 축복을 획득하고 신별 티어를 올리는 규칙을 정의한다. 게임 전체의 성장 구조는 [plan.md](plan.md), 이벤트와 결과 처리는 [EventSystem.md](EventSystem.md), 신과 신성 현상의 세계관은 [World_Premise.md](World_Premise.md)를 따른다.

1~7장은 확정된 규칙과 그 설명이다. 아직 결정하지 않은 사항은 8장에 구분한다. 이 문서의 규칙이 Unity에 구현되어 있다는 뜻은 아니다.

---

## 1. 역할과 기본 방향

축복은 개별 모험가가 아닌 파티 전체에 적용되는 원정 단위 성장이다.

성장 체계에서의 역할은 다음과 같다.

| 성장 요소 | 역할 |
| --- | --- |
| 레벨 성장 | 직업별 레벨 보상과 공용 특성을 통한 개별 모험가 성장 |
| 아이템 | 개별 모험가의 능력과 빌드 강화 |
| 축복 | 파티 전체의 규칙과 플레이 방식 변화 |

축복은 신성 현상을 발견하고 이에 응한 결과로 획득한다. 획득 조건과 신의 테마를 유지하면서, 각 신이 정해진 단계별 효과를 제공한다.

획득 때마다 무작위 축복 후보를 제시하고 그중 효과를 고르는 구조는 사용하지 않는다. 이전의 `BlessingPool`과 신별 `OfferRule`은 현재 규칙의 전제가 아니다.

효과를 구상할 때는 허용(Permission), 변환(Conversion), 연결(Connection), 조건부 보상(Conditional Reward)을 설계 가이드로 참고할 수 있다. 모든 효과를 한 유형에만 넣거나 모든 신이 같은 구성을 따르도록 강제하지 않는다.

---

## 2. 신과 신성 현상

- 신은 실재하지만 인간에게 직접 모습을 드러내거나 대화하지 않는다.
- 플레이어는 신의 직접적인 제안 대신 기적과 신성 현상에 응하는 방식으로 축복을 얻는다.
- 특정 현상이 어느 신과 연관되는지는 관찰과 전승을 통해 구분할 수 있다.
- 축복의 효과가 고정되어 있다는 사실로 신의 의도나 감정을 단정하지 않는다.

신성 현상(Manifestation)은 축복 획득으로 이어지는 현상이고, 축복(Blessing)은 그 결과 파티가 얻는 효과다. 현상을 발생시키는 조건을 충족하는 것과 실제로 축복을 획득하는 것은 구분한다.

---

## 3. 신별 축복과 티어

각 신은 고정된 단계별 축복 효과를 가진다. 파티는 신마다 축복과 티어를 독립적으로 보유한다.

| 획득 전 상태 | 해당 신의 축복을 한 번 받은 결과 |
| --- | --- |
| 축복 미보유 | 1티어 획득 |
| 축복 보유, 다음 티어 존재 | 현재 티어에서 정확히 한 단계 상승 |

- 한 번의 획득으로 여러 티어를 건너뛰지 않는다.
- 서로 다른 신의 축복을 함께 보유할 수 있다. 한 신의 티어 상승이 다른 신의 티어를 바꾸지 않는다.
- 티어가 오르면 기존 효과에 해당 단계의 새 효과가 추가된다.
- 기존 지속 효과는 유지한다.
- 해당 단계에 도달했을 때 지급하는 일회성 효과는 그때 한 번만 실행한다. 이후 티어가 오를 때 과거 단계의 일회성 보상을 다시 지급하지 않는다.
- 별도의 축복 경험치나 강화 재화로 티어를 올리는 구조는 사용하지 않는다.

각 신의 효과와 최고 티어 수는 아직 정하지 않았다. 논의에 사용한 제물의 신 효과와 3단계 예시는 확정 효과나 공통 티어 상한이 아니다.

## 4. 축복 획득 조건과 원정당 1회 규칙

### 4.1 획득 기회의 단위

각 축복 조건은 대상 신과 충족에 필요한 상태를 연결한다. 각 조건은 한 원정에서 한 번만 축복 획득 기회를 제공한다.

일회성 여부를 판단하는 단위는 축복 조건이다. 행동이 새로운지, 방문한 장소가 다른지, 이벤트 ID가 다른지를 공통 판정 기준으로 사용하지 않는다.

- 여러 태그를 함께 요구하는 조건도 그 조건 전체를 한 번의 기회로 센다.
- 같은 조건을 만족하는 태그를 다른 이벤트에서 다시 받아도 기회가 추가되지 않는다.
- 사용한 조건이 거짓이 되었다가 다시 참이 되어도 재사용하지 않는다.
- 다른 미사용 조건이 같은 신에 연결되어 있다면 그 조건을 통해 같은 신의 축복을 다시 받을 수 있다.

하나의 조건 세트 안에서는 AND로 판정하고, 같은 축복 조건을 만족시키는 대안 세트 사이는 OR로 판정한다. 동일한 기회를 만족시키는 여러 OR 대안과, 각각 독립된 기회를 제공하는 별도 축복 조건은 구분해야 한다. 하나의 조건에 포함된 대안을 각각 별도 획득 기회로 세지 않는다. 이를 표현하는 실제 데이터 구조는 미정이다.

이 논리 규칙은 신성 현상의 축복 조건에 관한 것이다. [EventSystem.md](EventSystem.md)의 일반 이벤트 조건은 현재 AND만 지원하며, 축복 조건의 규칙으로 일반 이벤트 JSON에 OR 조건을 추가하지 않는다.

### 4.2 상태와 조건 사용 기록

축복 시스템은 다음 두 정보를 별도로 확인한다.

| 정보 | 의미 |
| --- | --- |
| 현재 Tags·State | 축복 조건을 지금 만족하는가 |
| 조건별 사용 기록 | 이번 원정에서 그 획득 기회를 이미 처리했는가 |

축복 획득이 완료된 조건은 사용 완료로 기록한다. 사용 완료된 조건은 이후 판정에서 제외한다.

태그를 축복의 대가로 소비하거나 제거하지 않는다. 태그가 표현하는 사건의 사실은 그대로 남기고, 조건의 사용 여부를 따로 관리한다.

동시 발생에서 선택되지 않은 조건과 거절한 조건의 사용 기록 정책은 8장의 미정 사항이다.

### 4.3 이벤트와 축복 시스템의 경계

이벤트는 선택 결과로 태그 등 서사 상태를 변경한다. 이 결과에서 축복을 직접 지급하거나 티어를 올리지 않는다.

현재 진행 중인 이벤트와 관련 결과 처리가 끝난 뒤, 축복 시스템이 현재 상태를 만족하는 미사용 조건을 검사한다. 조건이 충족되면 별도의 확률 판정 없이 신성 현상이 발생한다.

이벤트에서 어떤 태그를 얻는 것과 그 태그에 어떤 신의 축복 조건을 연결하는 것은 별개의 정의다. 축복 조건과 사용 기록의 관리는 이벤트 결과 데이터의 책임이 아니다.

장소 진입·전투 종료·개별 행동을 모두 독립 Trigger로 지원하는 범용 확장은 확정하지 않았다.

## 5. 획득 처리 흐름

원정이 계속 진행되는 일반적인 흐름은 다음과 같다.

```text
이벤트 발생 및 플레이어 선택
→ 이벤트와 관련 결과 처리 완료
→ 현재 상태를 만족하는 미사용 축복 조건 검사
→ 신성 현상 발생 및 플레이어 응답
→ 해당 신의 축복 최초 획득 또는 티어 상승
→ 새 단계의 효과 적용 및 해당 조건 사용 완료 기록
→ 원정 진행
```

응답한 신의 다음 단계 효과는 고정되어 있으므로, 이후 별도의 무작위 축복 후보 선택은 없다.

여러 신의 신성 현상이 함께 발생하면 플레이어는 그중 하나에 응할 수 있다. 선택되지 않은 다른 현상은 이번 발생에서 사라진다. 이를 이유로 해당 신의 축복이 원정 전체에서 영구적으로 금지되지는 않는다.

동시 발생을 묶는 정확한 처리 단위, 동일 신의 여러 조건이 함께 충족될 때의 처리, 비선택·거절 조건의 사용 기록 정책은 아직 정하지 않았다. 따라서 비선택 조건을 자동 소비하거나 다음 판정에 자동 재제시한다고 가정하지 않는다.

전투 패배, 목표 이벤트 성공, 시간 소진처럼 원정 종료와 겹치는 경우의 축복 처리 순서는 미정이다. 이 문서의 일반 흐름만으로 기존 이벤트 시스템의 종료 처리 순서를 변경하지 않는다.

## 6. 예시: 숨겨진 작은 성소

이 예시는 태그를 통한 획득 기회 연결과 중복 방지를 설명한다. 구체적인 신, 효과와 실제 콘텐츠 배치는 확정하지 않는다.

1. 파티가 노드를 방문한다.
2. 원래 성소와 관련 없는 장소에서도, 여러 무작위 이벤트 중 「숨겨진 작은 성소를 발견하다」가 발생할 수 있다.
3. 이벤트는 여러 선택지를 제시하며, 그중 하나는 축복을 받을 수 있는 선택지다.
4. 플레이어가 해당 선택지를 고른다.
5. 그 결과는 축복을 즉시 지급하지 않고 `blessed-in-hidden-shrine` 태그만 추가한다.
6. 이벤트와 관련 결과 처리가 모두 끝나면 축복 획득 조건을 검사한다.
7. 해당 태그가 있고 연결된 조건이 미사용이면, 특정 신의 축복 획득 단계를 실행한다.
8. 축복을 획득하면 해당 조건을 사용 완료로 기록한다. 이후 이벤트가 끝나도 이 조건으로 다시 획득하지 않는다.

태그 이름은 설명용이다. 여기서는 성소에서 축복을 받을 수 있는 선택을 했다는 사실을 나타내며, 실제 축복 지급이 이미 완료되었다는 기록이 아니다. 실제 콘텐츠에 사용하기 전에는 이벤트 시스템의 참조 데이터 규칙에 따라 등록해야 한다.

| 시점 | 태그 보유 | 조건 사용 완료 | 결과 |
| --- | --- | --- | --- |
| 성소 이벤트 이전 | 아니요 | 아니요 | 조건 불충족 |
| 선택 결과 적용 후 | 예 | 아니요 | 축복 획득 기회 발생 |
| 축복 획득 완료 후 | 예 | 예 | 최초 획득 또는 한 단계 상승 |
| 이후 다른 이벤트 종료 | 예 | 예 | 다시 발생하지 않음 |

같은 태그를 다른 이벤트에서 다시 받아도 이 조건은 재사용하지 않는다. 같은 신에게 연결된 다른 미사용 조건을 충족하면 별도의 획득 기회가 된다.

## 7. 원정 단위 초기화

축복과 티어는 한 원정 동안만 유지하며, 다음 원정에서는 다음 정보를 초기화한다.

- 신별 축복 보유 상태와 티어
- 축복의 지속 효과 적용 상태
- 축복 조건별 이번 원정의 사용 기록

조건 사용 기록이 초기화되었다고 축복이 자동 지급되는 것은 아니다. 새로운 원정에서 다시 조건을 만족해야 한다.

이 규칙은 축복의 원정 단위 수명에 관한 것이다. 세계의 역사·기억·기록 전체가 초기화된다는 뜻이 아니며, 일회성 보상으로 받은 아이템 등의 원정 간 유지 여부도 이 규칙만으로 결정하지 않는다.

## 8. 미정 사항

### 콘텐츠와 성장량

- 신의 목록, 신별 테마를 구체화한 발생 조건과 단계별 효과
- 신별 최고 티어와 모든 신에 공통 티어 수를 둘지 여부
- 원정당 획득 기회의 배치·빈도와 축복 보유 개수 상한
- 최고 티어에 도달한 신을 획득 후보에서 제외하는 정책과 관련 서사 현상의 처리
- 축복의 교체·제거·효과 간 충돌 처리

### 조건과 동시 발생

- 지원할 상태 조건의 종류, AND·OR 규칙을 표현하는 조건 식과 식별자를 포함한 실제 데이터 구조
- 동일 신의 여러 조건이 함께 충족될 때 획득 횟수와 조건 사용 기록을 정하는 방식
- 여러 신의 현상을 하나의 선택 과정으로 묶는 정확한 범위와 시점
- 아무 현상에도 응답하지 않는 선택의 허용 여부
- 비선택·거절·중단된 획득 기회의 종료 및 사용 완료 기록 시점
- 위 경우 조건별 원정당 1회 원칙을 유지하는 재시도 정책

### 실행 순서와 표시

- 전투 패배·목표 성공·시간 소진과 축복 획득이 겹칠 때의 실행·생략·종료 판정 순서
- 축복 획득으로 상태가 바뀌었을 때 추가 조건을 재평가하거나 연쇄 발생을 허용할지 여부
- 이벤트 종료 외 판정 시점과 Trigger·Conditions 분리의 도입 여부
- 축복 획득 UI, 티어와 효과 정보의 공개 범위, 신성 현상 연출

이 항목은 콘텐츠나 구현 편의에 따라 암묵적으로 확정하지 않는다. 추가 결정이 생기면 관련 상세 규칙은 이 문서를 원본으로 갱신하고, 연결 문서에는 필요한 요약만 반영한다.
