# RaggedBanner 시나리오 프로젝트 안내

이 작업 공간은 RaggedBanner의 이벤트, 스토리와 세계관을 정의하고 발전시키기 위한 문서 프로젝트다. 새로운 세션에서는 아래 핵심 문서를 먼저 읽고, 현재 설정과 시스템 규칙을 파악한 뒤 작업한다.

## 핵심 문서와 읽기 순서

| 순서 | 문서 | 역할 |
| --- | --- | --- |

| 2 | [WorldLore.md](WorldLore.md) | 역사·문화·사회적 관습·지식 체계와 장소 설정의 배경 |

## 현재 게임과 이야기의 방향

RaggedBanner는 전문 탐험가인 모험가들이 아직 대부분이 알려지지 않은 판타지 세계를 여행하는 탐험 로그라이크다. 기본 감정은 호기심과 발견이며, 플레이어가 “저 너머에는 무엇이 있을까?”를 궁금해하도록 만드는 것이 중요하다.

세계에는 평범한 생활과 자연, 따뜻하거나 우스운 사건, 위험한 괴물과 드문 신비가 함께 존재한다. 서로 독립적인 역사와 전설이 공존하며, 모든 장소와 미스터리를 하나의 고대 문명이나 공통 원인으로 연결하지 않는다.

한 런은 중앙 도시의 보상 약속을 계기로 전설의 보물 **왕의 길잡이**를 찾아 떠나는 모험이다. 전투와 파티 성장, 새로운 장소로의 전진이 중심 경험이다. 자유로운 장소 이동과 사전에 설계한 스토리라인을 함께 제공하며, 최소 3개 스토리라인을 콘텐츠 목표로 삼는다. 각 이야기를 별도의 일방통행 이동 루트로 고정하지 않으며, 이 목표가 즉시 구현 범위를 뜻하지는 않는다.

최종 목표 장소는 하나다. 목표노드의 마지막 난관을 넘어 길잡이를 실제로 손에 넣는 순간 성공 결말을 맞는다. 단순 도착·목격이나 전투 승리만으로 보물 획득을 대신하지 않으며, 귀환·납품·포상·즉위·통치 과정은 필수 후속 플레이에 포함하지 않는다. 제한 전에는 언제든 최종 도전에 나설 수 있지만 조기 도전의 별도 보상은 없다. 시간제한은 탐험과 성장의 준비 기간이며, 소진되면 마지막 방문의 이벤트·전투·보상·결과를 마친 뒤 최종 도전으로 강제 전환한다.

World/Local 구분을 없애고 같은 Node 규칙을 사용한다. 각 Node의 parent는 노드들을 소유하는 공간 단위인 Area이며, Area 자체는 Node가 아니다. 같은 Area에서도 명시적인 Edge와 통행 조건에 따라 이동하고, 다른 Area의 노드로 일반 경로를 연결하지 않는다.

게임 화면에는 현재 Area에 속한 노드만 표시하며 이동 목적지도 그 안에서 선택한다. 목적지 Entrance는 입구 이벤트와 결과를 처리하고 일반 탐험이 계속되면 비용 0으로 한 번 전환한 뒤 도착지 이벤트와 결과를 처리한다. 이후에도 일반 탐험 중일 때 시간 소진을 판정한다. 최종 도전 진행 중에는 이 일반 전환이나 시간 소진 재판정을 실행하지 않는다. 전환 도착지가 Entrance여도 자동 재발동하지 않는다. 경유 Entrance는 전환만 생략하고 방문·이벤트 판정을 유지하며, 성공·패배가 확정되면 남은 전환과 이벤트를 중단한다.

흰밀물은 먼 곳을 향한 탐험을 중단시키는 세계의 주기이며, 그 안에 있는 이는 원래 왔던 길로 되돌아간다. 새 시간 소진·최종 도전 전환과 이 귀환 현상을 어떻게 연결할지는 미정이다. 흰밀물을 적이나 모든 신비의 원인으로 바꾸거나 세계·기억·기록의 초기화를 전제하지 않는다.

모험가의 레벨·경험치는 파티가 공유하고 전문화·성장 선택·장비는 개인별로 구분한다. 암살자는 투명화, 도둑은 은신과 방해, 불한당은 상태이상 대상 공격에 특화된다. 신규 기본 직업 기사는 양손 무기·강제 이동 면역·강타와 Lv2 기어스 선택을 사용하며 맹세 위반 시 대응 특성을 영구 몰수한다. 전사 전문화 수호자는 Lv2 방향별 물리 피해 차단과 Lv5 전방 3방향 판정을 얻는다. 공통 은신·투명화, 이동 반응·우선권과 각 직업의 확정·미정 범위는 `MercenarySystem.md`와 `BattleSystem.md`를 따른다. 기획 반영을 코드 구현 완료로 해석하지 않는다.

궁수는 Lv1 패시브로 전투 종료 후 특수화살 1개를 제작하며 종류·사용·보유·제작 대상 종료 결과는 미정이다. 사냥꾼 전문화는 정령궁수 계열로 교체한다. 정령궁수는 한 기본 공격의 네 속성 피해와 정령 부여, Lv5 물리 피해 차단·무속성 범위 사격을 사용한다. 이를 위해 Hex별 지면·공기 슬롯과 환경 반응을 전투 기획에 포함하며 상세 규칙은 전투·용병 명세를 따른다.

장비는 용병당 최대 3개이며 부위 슬롯 없이 동일 장비도 중복 장착할 수 있다. 직업의 기본 공격과 무기 표현은 유지한다. 전투 밖에서는 장소 제한 없이 교체·파티원 간 교환하고, 미장착 장비는 무제한 공용 인벤토리에 보관한다. 장착·보관 장비 모두 원정 종료 시 초기화한다. 상점에서 골드로 사고팔 수 있으며 구매로 줄어든 유한 재고는 원정 중 보충하지 않는다.

일반 장비는 이벤트에서 선택한 한 개를 정해진 특수 장비로 한 번 강화할 수 있다. 특수 장비는 직접 보상으로 얻을 수도 있으며 재강화하지 않는다. 장검·망치·단검·방패·갑옷과 성검·방패파괴자·자비·복수·촛농 갑옷의 효과는 상세 문서를 따른다. 효과·수치는 고정이며 방향 차단은 수호자 Lv2 패시브로 얻고 일반 방패의 물리방어 +1과 구분한다. 검소의 맹세는 착용 장비 2개 이하를 요구한다. 장비 효과의 미정 계산·상호작용은 확정 콘텐츠와 구분한다.

축복은 파티 전체에 적용되는 원정 단위 성장이다. 신별 단계 효과는 고정되어 있으며, 같은 신의 축복을 다시 받으면 티어가 상승한다. 축복·티어·축복 조건 사용 기록은 다음 원정에 초기화한다.

## 이벤트 제작의 기본 구조

- 이벤트는 개발 단계에서 정적으로 제작하며, 런타임에는 LLM이 개입하지 않는다.
- 이벤트는 실제 Node 진입 때 발생할 수 있는 서사 사건이다. 경유 노드도 방문·이벤트 판정 대상이다. 일러스트·본문·선택지 또는 자동 진행·결과 문구·Effect 형식을 유지하며, 상점·영입 등 일반 시설 이용과 상호작용은 별도 시스템·UI가 담당한다.
- 콘텐츠는 Opening, Arc와 독립 사건, 단일 최종 목표의 도전을 다루는 Goal 콘텐츠로 구성한다. 스토리라인의 내용·관계·완주 조건은 별도 설계하며, 최종 도전 진입을 위해 모든 스토리라인 완주를 요구한다고 가정하지 않는다.
- 이벤트 사이의 연결은 State·Tags·Arc Stage로 표현한다. 다음 Event ID를 직접 지정하는 고정 체인을 전제로 하지 않는다.
- 생성기는 서사·조건·결과를 만들고, Unity 런타임은 이동·시간·이벤트 선택·원정 종료를 관리한다.
- 원정 시간은 이동한 Edge의 `weight`만큼 소비한다. 시간 비용이 없는 내부 연결은 `weight = 0`으로 표현하며, 노드 종류로 시간 비용을 구분하지 않는다. 길잡이 획득 성공과 전투 패배는 종료 결과지만, 시간 소진은 최종 도전 진입 계기다. 강제 이동과 목표 이벤트 발생 중 구체 전환 방식은 미정이다.
- 런 시작에 장소 조건으로 노드별 잠재 이벤트 후보를 연결하고, 실제 방문 때 해당 노드 목록의 현재 조건을 검사한다. 초기에는 조건이 맞지 않는 후속 이벤트도 포함하며 상태 변화마다 원격 노드 목록을 교체하지 않는다. 같은 이벤트의 소비 상태는 런 전체에서 공유한다.
- 이벤트 없는 노드 방문은 정상적인 탐험이다. 첫 방문에 유효한 정규 후보가 없으면 이벤트 없이 진행하고, 재방문은 과거 탐험 기회에 후보가 아니었다가 조건에 따라 새로 유효해진 후보가 있을 때만 새 기회를 부여한다. 유효한 기회에 후보가 있으면 별도의 무이벤트 확률 판정 없이 정규 이벤트 1개를 처리한다.
- 한 번의 노드 진입에서 정규 이벤트는 최대 1개다. 해당 기회에 유효했던 후보 전체를 노드별로 기록하여 같은 상태의 반복 왕복으로 미선택 후보를 소진하지 못하게 한다. 새 진입 경로 자체는 공통 이벤트 발생 계기가 아니며, 지도 UI를 열고 닫는 것만으로 노드 재진입을 만들지 않는다.
- Result로 현재 노드의 새 이벤트가 활성화되어도 즉시 연속 실행하지 않고 이후 실제 재진입에서 검사한다. Opening과 최종 도전의 특수 처리, 정규 이벤트의 런당 1회 소비 등 상세 규칙은 `EventSystem.md`를 따른다.
- 축복과 연결된 이벤트는 태그를 제공하고, 관련 이벤트와 결과 처리가 끝난 뒤 축복 시스템이 미사용 조건을 검사한다. 조건별 원정당 1회 제한은 태그를 지우는 방식이 아니라 별도의 사용 기록으로 관리한다.

## 현재 문서 상태와 작업 시 주의점

`WorldLore.md`는 탐험 지식과 기록 체계, 에다 르윈의 빈칸 지도 전통, 왕의 길잡이와 중앙 도시의 의뢰를 다룬다. 길잡이가 왕실의 도로와 숨겨진 통로를 드러낸다는 기능과 왕권 전승은 정해졌지만, 왕권의 실제 작동 원리와 실종된 왕의 마지막 행선지·난관은 미정이다.

프로토타입의 공유 레벨은 1~5이며 전투 승리마다 경험치 1을 얻고, 다음 레벨에 필요한 경험치는 현재 레벨이다. 용병과 공유 성장은 원정 수명이다. Lv3 공용 특성·Lv4 직업 스킬 구조를 유지하며, 도둑 Lv2에는 명시된 선택 보상이 있다. 미확정 수치·세부 동작과 나머지 보상 콘텐츠는 상세 문서에서 구분한다.

`Plan.md`·`EventSystem.md`·`GameState.md`와 구현 로드맵은 단일 최종 목표, 길잡이 획득 결말과 시간 소진 후 최종 도전 흐름을 기준으로 읽는다. 현행 JSON·CSV, 런타임 필드 제안과 필요한 데이터 계약 개정을 구분하며, 문서 개정을 Unity 구현이나 데이터 마이그레이션 완료로 해석하지 않는다.

이미 서 있는 Entrance의 재선택·복귀 조작, Area·Node·Edge·Entrance 목적지·방문·후보 이력의 구체 스키마와 후보 기록 시점, 다른 Area 최종 목표의 안내·접근 UI는 미정이다. 고정/랜덤 이벤트 배치·우선순위, 특정 진입 방향 조건과 이벤트 없는 노드·시설 UI도 별도 검토한다. 시간 소진 전환이 결정되면 0비용 이동으로 일반 탐험을 계속하지 않는다.

전투는 `BattleSystem.md`의 헥스 턴제 전투를 기준으로 하며 현재 구현과 확정 기획을 구분한다. 은신·투명화와 도적 전문화의 문서 반영은 코드·AI·상태효과의 구현 완료를 의미하지 않는다.

총 준비 시간, 최종 도전의 강제 전환 방식·복귀·실패 후 처리, 스토리라인의 선방문·중단·동시 진행은 미정이다. 특별 장소의 영구 기록·해금 개념은 유지하지만 새 종료 구조에서의 확정 시점과 실패 시 보존은 별도 설계한다. 길잡이 획득 이후 자유 탐사나 납품 과정은 현재 모험 범위에 추가하지 않는다.

축복의 동시 발생에서 비선택 조건을 처리하는 방식, 원정 종료와 축복 후처리의 정확한 순서 등은 `BlessingSystem.md`의 미정 사항으로 관리한다. 개별 효과와 티어 수의 논의용 예시를 확정된 콘텐츠로 사용하지 않는다.

이 안내는 프로젝트의 진입점이다. 구체적인 작업에서는 관련 핵심 문서의 최신 본문과 `AGENTS.md`를 함께 확인한다.
