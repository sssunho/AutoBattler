# 용병 데이터 시스템 설계

- 기준일: 2026-10-21
- 기획 개정일: 2026-11-07 — 궁수 Lv1 특수화살 제작과 정령궁수 Lv2·Lv5 보상, 환경효과 연결 반영
- 범위: 직업 기반 용병의 정적 데이터, 원정 런타임 데이터와 전투 데이터의 연결
- 상태: ClassDefinition·AbilitySettings·MercenaryDataList의 코드와 프로토타입 에셋, 데이터 검증을 구현했다. GameData의 목록 초기화·전역 조회 코드도 구현했다. 직업 식별자는 MercenaryClass로 통일했다. GameData의 Scene 배치와 에셋 할당은 사용자가 수행한다. 에셋의 전투 연결과 용병 런타임 데이터·계산 구조는 미구현이며 설계 중이다. 컴파일·빌드·Unity 테스트 실행 여부는 별도 검증 결과로 확인한다.

## 1. 목적과 문서 기준

용병의 데이터 역할, 소유권, 생명주기와 시스템 간 연결 규칙을 정한다. 미리 제작된 고유 캐릭터와 적·소환물을 포함하는 범용 캐릭터 시스템은 현재 범위에 포함하지 않는다.

관련 문서는 [Plan.md](Plan.md), [BattleSystem.md](BattleSystem.md), [EventSystem.md](EventSystem.md), [BlessingSystem.md](BlessingSystem.md)다. 용병의 원정 수명, HP 유지와 파티 공유 성장에 관해서는 이 문서의 확정사항을 우선한다.

| 상태 | 의미 |
| --- | --- |
| 확정 | 이번 용병 설계에서 합의한 규칙. 구현 완료를 의미하지 않는다. |
| 제안 | 검토할 설계 방향. 실제 스키마나 동작으로 확정하지 않는다. |
| 미정 | 이후 논의가 필요한 항목. 예시만으로 확정하지 않는다. |

Plan의 오토배틀·마나 관련 전투 본문은 개정 전 내용이다. 이번 설계는 현재 BattleSystem의 턴제·AP 규칙을 기준으로 한다. 기존 문서의 테스트값과 현재 구현값을 최종 밸런스로 취급하지 않는다.

## 2. 용병 생성과 생명주기 — 확정

- 용병은 직업 템플릿 기반으로 생성한다.
- 같은 직업의 용병은 기본 능력치와 성장 규칙을 공유한다.
- 각 용병은 독립적인 인스턴스로 존재한다. 레벨과 경험치는 파티가 공유하고, 전문화와 성장 보상의 선택 결과는 용병별로 가진다.
- 용병은 한 번의 원정에서만 유지한다.
- 원정이 끝나면 파티의 공유 레벨·경험치와 용병별 전문화·장비·성장 선택 기록 등 런타임 데이터를 폐기한다.
- 연대기나 통계에 기록을 남길 수는 있지만, 다음 원정에서 동일한 용병을 유지하지 않는다.

이 규칙은 기존 문서에서 미정으로 남아 있던 원정 간 성장 유지 문제를 용병 런타임 데이터의 범위에서 확정한다.

## 3. HP와 전투 불능

### 3.1. 확정 규칙

- 현재 HP는 전투 사이에도 유지한다. 전투가 끝나도 자동으로 완전 회복되지 않는다.
- HP가 0이면 전투 불능이며, 용병은 원정 파티에 그대로 남는다.
- HP가 0인 동안에는 다음 전투에 참여할 수 없다. HP가 회복되면 다시 참여할 수 있다.
- 전투 불능이 되어도 전문화·장비·성장 선택은 유지하며, 파티 공유 레벨을 적용받는다. 개인 레벨이나 경험치가 뒤처지는 구조는 두지 않는다.
- HP 0으로 인한 전투 불능은 영구적인 사망이 아니다.
- 전투 유닛 제거와 원정 용병 제거는 서로 다른 작업이다.

### 3.2. 제안과 미정 사항

별도의 전투 불능 상태를 저장하기보다 `CurrentHP == 0`으로 판정하는 구조를 우선 검토한다.

일반 회복으로 HP 0인 용병을 회복할 수 있는지, 별도의 소생 수단이 필요한지는 미정이다. 전투 중 전장에서 제거된 유닛의 복귀 규칙도 확정하지 않는다.

BattleSystem의 직업별 초기 테스트 표는 HP를 ‘전투 시작 시의 HP’로 설명한다. 이번 규칙에서는 최대 HP와 전투 시작 현재 HP를 구분한다. 프로토타입에서는 전사 10·도적 8·궁수 8을 직업 기본 최대 HP로 사용하기로 확정했다. 매 전투 현재 HP를 이 값으로 초기화하지 않으며, 생성 시 현재 HP 설정 규칙은 미정이다.

## 4. 기본 능력치와 적용 범위 — 확정

현재 설계의 기본 목록은 아래 11개 항목으로 한다. 우선권은 새 기획이며 7절의 기존 프로토타입 스키마에 추가 구현된 필드는 아니다. 최종 수치와 밸런스는 미정이다.

| 구분 | 항목 | 역할 |
| --- | --- | --- |
| 유닛 능력치 | 최대 HP | 현재 HP가 가질 수 있는 상한. 현재 HP 자체는 별도 런타임 상태다. |
| 유닛 능력치 | 이동력 | 자신의 턴에 사용할 이동량의 기준. 남은 이동력과 구분한다. |
| 유닛 능력치 | 우선권(Initiative) | 모든 유닛이 보유하며 라운드 턴 순서와 동시 이동 반응의 처리 순서를 결정한다. 실제 수치는 미정이다. |
| 유닛 능력치 | 치명타 확률 | 강제 치명타 조건이 없을 때 사용하는 일반 확률이다. |
| 유닛 능력치 | 물리 방어력 | 물리 피해를 줄이는 수치다. |
| 유닛 능력치 | 물 방어력 | 물 피해를 줄이는 수치다. |
| 유닛 능력치 | 불 방어력 | 불 피해를 줄이는 수치다. |
| 유닛 능력치 | 전기 방어력 | 전기 피해를 줄이는 수치다. |
| 유닛 능력치 | 독 방어력 | 독 피해를 줄이는 수치다. |
| 기본 공격 수치 | 기본 공격 피해 | 기본 공격의 치명타·방어력 적용 전 피해다. |
| 기본 공격 수치 | 기본 공격 사거리 | 기본 공격이 도달할 수 있는 최대 헥스 거리다. |

무속성 방어력은 존재하지 않는다. 속성별 방어력의 고정 수치 차감과 최소 피해 0 규칙은 BattleSystem을 따른다.

기본 공격 피해와 사거리는 기본 공격 전용 수치로 구분한다. 기본 공격 피해를 모든 스킬에 자동 적용하는 범용 공격력으로 취급하지 않는다. 스킬이 기본 공격 피해나 사거리를 참조할 필요가 있다면 해당 스킬의 규칙에서 관계를 명시한다. 스킬별 피해·사거리의 상세 구조는 미정이다.

이 구분은 적용 범위에 대한 합의이며, 데이터를 반드시 별도 객체나 파일로 나눈다는 뜻은 아니다.

라운드 턴 오더는 우선권이 높은 유닛부터 구성한다. 동률 유닛의 상대적 순서는 라운드 시작 때 무작위로 정하고 그 라운드 동안 유지한다. 동시 이동 반응도 같은 우선권 순서와 해당 라운드의 동률 순서를 사용한다. 기존 전체 무작위 턴 오더는 새 기획에서 대체하며, 우선권의 직업별·유닛별 값과 저장 구조는 미정이다.

## 5. 일반 능력치, 직업 능력과 공통 규칙 — 확정

### 5.1. 일반 능력치와 직업 능력

숫자를 포함하는지보다 무엇을 판단하거나 변경하는지에 따라 구분한다.

| 사례 | 분류 | 이유 |
| --- | --- | --- |
| 전사의 물리 방어력 1 | 일반 능력치 | 물리 피해 계산에 사용하는 수치다. |
| 수호자의 방향별 물리 피해 무효화 | 전문화 능력 | Lv2 고정 패시브로 공격 속성·방향·확률에 따라 판정한다. 일반 방패의 물리방어 +1과 별개다. |
| 전사의 기회 공격 | 직업 능력 | 인접한 적이 일반 이동으로 인접 상태를 벗어나려 할 때 이동 전에 기본 공격 한 번을 가한다. |
| 도적의 높은 이동력 | 일반 능력치 | 이동량의 차이로 표현한다. |
| 도적의 후면 강제 치명타 | 직업 능력 | 상대와의 위치 관계에 따라 치명타 판정을 바꾼다. |
| 궁수의 기본 공격 사거리 3 | 기본 공격 수치 | 현재 정해진 차이는 사거리로 표현한다. |
| 궁수의 특수화살 제작 | 직업 능력 | Lv1 기본 패시브로 전투 종료 후 전투에서 사용할 특수화살 1개를 제작한다. 긴 사거리와 구분한다. |

기본 수치는 BattleSystem의 초기 테스트 기획을 따르며 최종 밸런스가 아니다. 전사의 기회 공격과 수호자 Lv2의 방향 차단은 새 기획이며 기존 코드·에셋 변경 완료를 뜻하지 않는다. Lv1 액티브는 6.3.1절, 궁수의 Lv1 패시브와 정령궁수 보상은 6.8절, 장비 효과는 6.10절, 기사는 6.11절의 확정 범위를 따른다.

방향 차단의 무효화 확률처럼 특성 내부에 숫자가 있더라도 모두 공통 능력치로 만들지 않는다. 직업 능력·특성·장비는 일반 능력치를 변경할 수도 있으며 효과를 얻는 출처와 효과가 변경하는 대상을 구분한다.

능력치 계산은 사용할 수치를 산출하고, 공격 시 판정은 방향·속성·직업 능력 등을 확인하여 실제 피해를 결정한다. 조건부 판정까지 모두 하나의 최종 능력치 값으로 환산하지 않는다.

### 5.2. 공격 설정과 공통 전투 규칙

- 기본 공격 속성은 수치형 능력치가 아닌 공격 설정이다. 기본 직업 상태의 전사·도적·궁수는 물리 공격을 사용하며 정령궁수는 6.8.3절의 전문화 효과로 기본 공격의 피해 구성을 교체한다.
- 치명타 추가 피해는 현재 공통 규칙인 +2를 따른다. 직업별 기본 능력치로 중복하지 않는다.
- AP 시작량, AP 상한과 턴당 AP 지급량은 공통 BattleRules에 둔다. 기본 공격 비용은 직업에 지정된 기본 공격 SkillDefinition의 ActionPointCost를 사용하며 1 AP 이상이어야 한다.
- 무속성을 포함한 모든 속성의 공격에 치명타를 허용하는 기존 규칙을 유지한다.

Plan의 ‘치명적인 마법’ 등 공용 특성 예시는 확정 콘텐츠가 아니며, 기존 치명타 규칙을 변경하지 않는다.

## 6. 성장 규칙 — 확정

### 6.1. 파티 공유 레벨과 경험치

- 레벨과 경험치는 용병 개인이 아닌 원정 파티가 소유한다.
- 파티의 모든 용병은 같은 레벨을 적용받는다. 용병별 레벨·경험치 진행도는 두지 않는다.
- 프로토타입의 파티 시작 레벨은 1, 최대 레벨은 5다.
- 프로토타입에서는 전투 승리마다 파티 경험치를 고정 1 지급한다. 참가자 수나 생존자 수를 곱하거나, 개인별로 나누어 지급하지 않는다.
- 최대 레벨 미만에서 현재 파티 레벨이 L이면 다음 레벨까지 필요한 경험치는 `L`이다. 이는 현재 레벨에서 다음 레벨로 오르는 데 필요한 양이며, 원정 전체의 누적 경험치 기준값이 아니다. Lv5에서는 더 이상 레벨업하지 않는다.
- 파티 레벨이 오르면 각 용병은 자신의 직업별 레벨 보상표에 따라 성장한다. 선택 보상은 용병별로 선택하고 기록한다.
- 전투 참가 여부나 전투 불능 여부에 따른 개인 경험치 차이는 없다. 보상 선택·적용의 구체적인 시점은 별도로 정한다.

| 레벨업 | 필요한 파티 경험치 | 시작 경험치 0일 때 누적 승리 |
| --- | ---: | ---: |
| Lv1 → Lv2 | 1 | 1승 |
| Lv2 → Lv3 | 2 | 3승 |
| Lv3 → Lv4 | 3 | 6승 |
| Lv4 → Lv5 | 4 | 10승 |

시작 경험치를 0으로 가정하면 첫 전투 승리 직후 Lv2에 도달하며, 누적 10승에 최대 레벨인 Lv5에 도달한다. 한 원정에서 레벨업은 최대 네 번 경험한다. 위 예시의 시작 경험치 0은 아직 제안이며, 모든 원정에서 최대 레벨에 도달해야 한다는 조건은 아니다.

시작 경험치, 레벨업 후 경험치 기록 방식과 초과 경험치 처리, 최대 레벨 도달 후 경험치 처리는 미정이다. 중도 영입 시에도 파티 공유 레벨을 기준으로 하되, 이전 레벨의 보상을 지급하고 선택하는 절차는 별도로 정한다.

### 6.2. 용병별 성장 보상

직업별 레벨 보상표는 다음 세 가지 보상 방식을 사용한다.

1. 직업별 고정 보상
2. 직업 내 선택 보상
3. 직업 공통 특성 보상

모든 레벨에 동일한 보상을 지급하지 않는다. 프로토타입의 Lv1~Lv5 성장 흐름은 6.3절을 따른다. 수호자·개척자의 Lv2·Lv5 보상은 6.6절, 도적 전문화의 보상은 6.7절, 궁수 Lv1 패시브와 정령궁수 Lv2·Lv5 보상은 6.8절, 기사의 Lv1·Lv2는 6.11절의 확정 범위를 따른다. 암살자 Lv5 액티브는 기존안을 철회하여 새 효과가 미정이다. 그 밖의 실제 보상과 수치·세부 동작은 이후 설계한다.

매 레벨 능력치를 일괄 상승시키는 자동 성장식을 전제하지 않는다. 레벨 성장에 의한 능력치 변화는 보상표에 명시된 보상으로 반영한다.

여기서 공용 특성은 용병 개인의 전투·성장 특성이다. EventSystem의 `Trait` 및 `Data/Traits.csv`가 표현하는 파티의 서사적 성향 태그와 다른 개념이다.

같은 직업의 용병도 전문화·선택 보상·장비를 달리할 수 있다. 파티가 레벨을 공유한다는 것은 성장 단계의 공유이며, 용병별 선택 결과나 최종 능력치까지 동일하다는 뜻은 아니다.

Lv2는 성장 방향, Lv3는 공용 특성, Lv4는 직업 스킬, Lv5는 전문화 강화 단계다. Lv1 액티브를 추가해도 Lv4를 삭제하거나 그 보상을 Lv1으로 옮기지 않는다. 매 레벨 액티브·패시브 중 선택하거나 Lv3를 공용 능력 전반의 선택으로 넓히는 안은 미확정이다. Lv4 스킬의 실제 내용·지급 방식과 각 보상의 최종 밸런스는 미정이다.

#### 6.3.2. 기회 공격과 경계사격의 이동 반응

두 능력은 적의 일반 이동을 구성하는 각 1칸 step이 선언된 직후, 실제 위치가 바뀌기 전에 검사한다. 강제 이동과 돌진·도약·밀치기·끌기 등 기술이나 효과에 의한 위치 변경에는 발동하지 않는다.

- 조건을 만족한 반응이 있으면 현재 1칸 이동을 취소하고 그 step의 이동력을 소모하지 않는다. 남은 예약 경로도 폐기하여 해당 이동 명령을 종료한다. 반응 후 이동 주체가 생존하고 계속 행동할 수 있으면 새 입력을 받는다.
- 같은 이동 선언에 조건을 만족한 기회 공격·경계사격을 모두 예약하고, 높은 우선권부터 처리한다. 동률은 해당 라운드에 이미 정해진 상대적 순서를 따른다.
- 앞선 반응으로 이동 주체가 사망하면 남은 예약 반응은 실행하지 않는다. 미실행 기회 공격은 대상별 사용 기록을 남기지 않으며 미실행 경계사격은 경계 상태를 유지한다.
- 실제 반응 공격은 기본 공격과 같이 대상을 향해 Facing을 바꾼 뒤 수행한다. 바뀐 Facing은 이후 방향 판정에 남는다.

기회 공격은 인접한 적이 일반 이동으로 전사와의 인접 상태를 벗어나려 할 때 발동하며 AP를 소모하지 않는다. 보유자 한 명은 같은 대상에게 같은 라운드 동안 최대 한 번 발동할 수 있다. 서로 다른 대상에는 각각 발동하고 라운드 총횟수 상한은 없다. 새 라운드 시작에 대상별 사용 기록을 초기화한다.

경계사격은 현재 영역 안에 적이 없어도 빈 방향을 선택하여 준비할 수 있다. 영역은 사용자의 현재 Hex 중심을 꼭짓점으로, 선택 방향을 중심축으로 좌우 60°씩 총 120°이며 경계선을 포함한다. 인접 6칸 중 정면과 좌우 앞쪽의 총 3칸이 포함된다. 최대 사거리는 기본 공격 사거리와 같으며 영역과 사거리를 모두 만족해야 한다. 판정은 이동 전 적의 현재 위치를 기준으로 한다. 영역 밖에서 들어오는 그 step에는 발동하지 않고, 진입한 뒤 다음 일반 이동을 선언하면 다시 판정한다.

경계사격 발동에는 추가 AP를 쓰지 않으며 기본 공격 피해·속성·치명타·방어력 계산과 기본 공격에 적용되는 효과를 동일하게 적용한다. 실제 공격 한 번이 발동하면 종료하고, 한 번도 발동하지 않았다면 사용자의 다음 자기 턴 시작에 종료한다. 사용자가 강제 이동되거나 외부 효과로 Facing이 강제로 바뀌어도 즉시 종료한다. 한 번 제한은 준비 한 번당 발동 횟수이며 전투당 사용 제한이 아니다.

은신·투명화 대상의 지정·감지, 지형 사선·차폐, 예약 뒤 공격자의 행동 가능 상태가 바뀐 경우와 실패·취소의 세부 처리는 후속 설계한다. 경계사격의 확정된 120° 영역을 공통 은신의 시야 형상으로 자동 대체하지 않는다.

### 6.4. 전문화 선택과 유지

- 전문화는 직업 안에서 선택하는 성장 갈래다.
- Lv2에서 각 용병은 전문화 하나를 선택한다. 파티 전체가 하나의 전문화를 공유하지 않는다.
- 선택한 전문화는 해당 원정 동안 유지하며, 원정 중 다른 전문화로 변경하지 않는다.
- Lv2에서는 전문화 선택에 따라 정해진 보상을 배운다. 고정 보상은 각각 다시 선택하지 않는다. 도둑의 비열한 행동처럼 선택 보상으로 명시한 항목만 후보 중 하나를 선택하며, 다른 전문화에 선택 보상을 자동 추가하지 않는다. 기사는 6.11절의 기어스·대응 특성 한 쌍을 선택하며 별도 신규 스킬 지급을 자동 추가하지 않는다.
- Lv5에서는 선택한 전문화에 맞는 강력한 스킬과 특성을 배운다. 전문화를 다시 선택하는 단계는 아니다.
- 전문화는 용병별 성장 선택이며, 원정 종료 시 다른 용병 런타임 데이터와 함께 폐기한다.

공용 특성은 전문화 보상과 구분한다. Lv3에서는 공용 특성 풀에서 플레이어가 직접 선택하며, 구체적인 후보 제시 방식·선택 조건·효과는 이후 설계한다.

현재 기획 목표는 전사·도적·궁수·마법사·기사 5직업이다. 전사·도적·궁수는 각각 3종의 전문화를 설계하며, 마법사는 기상술사·마공학자·사령술사 3종을 우선 설계한다. 기존 네 직업의 12종에 더해 기사는 6.11절의 네 기어스·특성 쌍을 전문화 선택지로 둔다. 마법사의 전문화 수를 3종으로 제한하지 않으며 추가 전문화의 종류와 도입 시점은 미정이다.

전사의 전문화는 6.6절, 도적은 6.7절, 궁수는 6.8절, 마법사는 6.9절, 기사는 6.11절을 따른다. 수호자·개척자·도적 전문화·정령궁수의 Lv2·Lv5 보상은 각 절의 확정 범위를 따르며, 암살자 Lv5 액티브의 대체 효과와 무사·명사수·샤프슈터·마법사의 실제 전문화 보상은 미정이다. 이 기획은 현재 구현된 직업이나 정적 데이터의 범위를 변경하지 않는다. 중도 영입 용병의 전문화 및 이전 레벨 보상을 선택하는 절차도 별도로 정한다.

### 6.5. 보상 콘텐츠 설계 시 검토할 방향 — 제안

- Lv2 보상만으로 전문화의 핵심 플레이가 성립하고, Lv5는 이를 강하게 확장하는 방향을 검토한다.
- 전문화가 반드시 특정 공용 특성을 골라야 작동하도록 만들기보다, Lv3 특성이 강화·보완·변형을 제공하는 방향을 검토한다.
- Lv4 스킬을 고정 지급하는 직업은 모든 전문화에서 활용할 수 있는지 확인한다. 전문화에 따라 필요한 행동이 크게 다르면 선택 보상을 검토한다.
- 파티 전체가 동시에 성장하므로, 한 번의 레벨업에 필요한 선택량과 탐험 흐름의 중단 시간을 함께 살펴본다.

### 6.6. 전사의 공통 정체성과 전문화 — 기획 확정

이 절은 전사의 공통 정체성·기회 공격과 수호자·개척자의 전문화 보상을 정의한다. 방향별 물리 피해 차단은 수호자 Lv2 고정 패시브로 배치한다. 코드·에셋 반영 완료를 뜻하지 않고 전사의 물리 방어력 1 등 기본 수치를 변경하지 않는다. 세계관은 [World_Premise.md](World_Premise.md)를 따른다.

#### 6.6.1. 전사의 공통 정체성

전사는 호위와 경비, 구조와 괴물 퇴치의 현장에서 무장 전투를 익혀, 일행이 위험에 맞설 수 있게 하는 사람들이다. 훈련과 실전 경험으로 다른 사람들이 맡은 일을 수행할 수 있도록 싸움을 담당한다. 무기 숙련은 이들의 전문 기술이며, 출신을 하나의 군대·학교·조직으로 한정하지 않는다.

상단 호위대, 성문 경비대, 변경 마을의 무장대나 선배 모험가에게 기술을 배운 사람 등 다양한 배경이 가능하다. 이는 배경의 예시이며 특정 조직의 존재나 소속을 필수 조건으로 확정하지 않는다.

전사는 근접 무기를 능숙하게 다루고 공격 기회를 활용하는 전투원이다. 전사 전체를 방어적인 직업이나 탱커로 전제하지 않으며, 방어와 동료 보호의 전문성은 수호자에 집중한다.

전사의 새 기본 패시브는 **기회 공격**이다. 인접한 적이 일반 이동으로 인접 상태를 벗어나려 할 때 AP 소비 없이 기본 공격 한 번을 가한다. 보유자·대상별 라운드 한 번 제한과 이동 전 취소·복수 반응 처리·Facing 변경은 6.3.2절을 따른다. 강제 이동과 기술 이동에는 발동하지 않는다.

방향별 물리 피해 차단은 **수호자 Lv2 고정 패시브**다. 일반 방패는 6.10절의 물리방어 +1을 제공하며 방패를 장착해도 이 패시브를 얻지 않는다. 차단은 들어오는 물리 피해를 방향별 확률로 무효화하고, 성공 시 그 피해는 0이 된다. 무효화되지 않으면 정상적으로 물리 방어력을 적용한다. 정면 50%·측면 10%·후면 0%를 테스트 기준으로 사용하며 최종 밸런스는 추후 조정한다. 전사의 기본 기회 공격은 유지한다.

전문화는 이 공통 기반 위에서 싸우는 목적과 역할을 구분한다. 과거 경력이 전문화를 자동으로 결정하는 것은 아니며, Lv2의 선택은 이미 익힌 기술 중 이번 원정에서 집중할 역할을 정하는 것으로 해석한다.

#### 6.6.2. 세 전문화의 역할

| 전문화 | 역할 | 정체성과 동기 | 전투 방식 |
| --- | --- | --- | --- |
| 수호자 | 보호 | 사람들을 지켜온 전사. 맡은 일행의 무사 도착과 귀환을 우선한다. | 지킬 사람과 위험 사이에 서서, 일행이 안전하게 행동하거나 이동할 공간을 확보한다. |
| 개척자 | 돌파 | 위험한 길의 앞에 서온 전사. 자신과 동료들이 나아갈 길을 연다. | 막힌 접근로와 적의 배치를 살펴 진입할 지점을 고르고, 동료들이 따라 움직일 틈을 만든다. |
| 무사 | 제거 | 스스로 강해지기 위해 위험에 몸을 던지는 전사. 강적과 맞서 자신의 한계를 넘으려 한다. | 위협적인 상대에게 집중하고, 맞붙은 뒤 공격 기회를 놓치지 않으며 제압한다. |

#### 6.6.3. 수호자 — 맡은 사람을 도착시키는 전사

상단과 여행자, 탐험대를 보호해온 사람들이다. 이들에게 성공한 싸움은 맡은 일행이 무사히 길을 계속 갈 수 있게 된 싸움이다. 적을 쫓는 것보다 지킬 대상과 위치를 의식하며, 일행이 움직일 시간을 확보하고 필요하면 함께 물러난다.

누구를 보호하고 어디를 지킬 것인지가 역할의 중심이다. 방향별 물리 피해 차단과 상위 단계의 정면 확장, 숨은 적을 드러내는 액티브, 밀치는 돌진, 파티 방어·행동 지원으로 동료의 안전에 기여한다. 방향 차단과 방향 확장은 방패 장착과 관계없이 전문화 레벨 보상으로 얻는다.

| 레벨 | 보상 | 확정 효과 |
| --- | --- | --- |
| Lv2 | 고정 패시브 | 방향별 확률로 물리 피해를 무효화한다. 정면 50%·측면 10%·후면 0%를 테스트 기준으로 사용한다. 실패하면 정상적으로 물리 방어력을 적용한다. |
| Lv2 | 고정 액티브 | 정면에 있는 모든 은신한 적을 드러낸다. |
| Lv2 | 고정 액티브 | 원하는 방향으로 직선 3칸 돌진하고 경로에 있던 적을 밀어 넘어뜨린다. |
| Lv5 | 고정 패시브 | 자신의 정면과 정면 양옆을 모두 정면으로 취급한다. 인접 6헥스 중 정면 1칸과 좌우 앞쪽 2칸, 총 3방향을 정면으로 판정한다. |
| Lv5 | 고정 액티브 | 모든 아군에게 방어력을 부여하고 각 아군이 다음 자신의 턴을 시작할 때 보너스 AP를 얻는다. |

Lv5의 정면 확대는 자신의 정면 판정 자체를 변경하므로 방향 차단과 정면 기준 스킬에도 적용한다. 인접 6칸은 정면 3칸·측면 2칸·후면 1칸이다. 후면을 측면으로 바꾸던 효과와 정면 인접 3칸의 상시 은신 해제는 폐기한다. 수호자의 실제 후면에서 공격하는 도적에게는 기존 후면 강제 치명타가 성립한다.

먼 타일의 확장 정면·측면 영역과 경계는 미정이며 감지 거리를 늘리지 않는다. Lv2 탐지 액티브의 거리·범위·드러냄의 지속·해제와 투명화 적용 여부는 별도 설계한다. 돌진의 밀치는 방향·거리·복수 적·벽·유닛·맵 끝 처리, 넘어짐 효과·지속·피해는 미정이다. 돌진·밀치기는 일반 이동이 아니므로 기회 공격과 경계사격을 유발하지 않는다.

지원의 방어력 종류·수치·지속, 보너스 AP 수치·중첩·상한 처리와 시전자 포함 여부는 미정이다. 모든 속성 방어력이나 AP 상한 초과로 확정하지 않는다. 각 액티브의 AP 비용·사용 제한·장비 또는 특성 의존 여부·실패·취소와 비용 처리·정식 명칭도 미정이며 경계·방패 돌진·넓은 방어는 가칭이다.

#### 6.6.4. 개척자 — 동료가 나아갈 길을 여는 전사

탐험과 구조의 현장에서 위험한 길의 앞을 맡아온 사람들이다. 막힌 통로를 뚫고, 고립된 사람에게 접근하고, 동료가 들어오거나 빠져나갈 길을 확보하는 경험과 연결된다.

자신과 적의 위치를 바꾸어 동료가 공격하거나 이동할 공간을 만든다. 자신이 접근할지 적을 당길지 선택하며 상위 단계에서는 적의 착지 위치를 직접 지정한다.

| 레벨 | 보상 | 확정 효과 |
| --- | --- | --- |
| Lv2 | 고정 패시브 — 틈새 전진(가칭) | 자신의 기술로 자신 또는 적의 위치를 실제로 바꾸면 남은 이동력을 일부 회복한다. 자신의 턴마다 한 번 발동하며 일반 이동이나 위치 변경 실패로는 발동하지 않는다. |
| Lv2 | 고정 액티브 — 끌려가기(가칭) | 지정한 적 쪽으로 자신이 끌려가 접근한다. |
| Lv2 | 고정 액티브 — 끌어오기(가칭) | 지정한 적을 자신 쪽으로 당긴다. |
| Lv5 | 고정 패시브 — 거침없는 발걸음(가칭) | 자신의 이동으로 적의 기회 공격을 유발하지 않는다. |
| Lv5 | 고정 액티브 — 내던지기(가칭) | 인접한 적 하나를 범위 내 지정한 빈칸으로 던진다. |

초안의 밀어내기는 끌려가기로 교체했으며 추가 보유 스킬로 남기지 않는다. Lv2 패시브는 적뿐 아니라 자신의 기술에 의한 자기 위치 변경도 포함한다. 이동력 회복은 AP 회복이나 턴 시작 이동력 증가가 아니다. 회복량·상한·발동 시점과 각 기술의 AP 비용·사거리·이동 거리·피해·사용 제한은 미정이다.

끌려가기 착지 칸, 끌어오기 정지 위치, 내던지기 범위·경로와 중간 유닛·장애물·막힌 경로·맵 끝·점유 칸, 실패·취소와 비용 처리는 별도 설계한다. 갈고리 등 장비 요구·이동 수단과 대상 제한·넘어짐 등 추가 상태이상을 확정하지 않는다.

Lv5 패시브는 자신의 일반 이동에 대한 기회 공격을 막는 효과이며 경계사격까지 막는다고 확정하지 않는다. 끌려가기·끌어오기·내던지기 같은 기술 이동과 강제 이동은 Lv5 이전에도 공통 규칙에 따라 기회 공격·경계사격을 유발하지 않는다.

#### 6.6.5. 무사 — 위험 속에서 자신을 단련하는 전사

스스로 강해지기 위해 위험에 몸을 던지는 사람들이다. 강적과의 대결을 자신의 기량을 시험하고 부족함을 발견하는 기회로 받아들인다. 탐험 중 만나는 위험은 이들이 자신의 한계를 넘어설 수 있는 도전이 된다.

반드시 난폭하거나 죽음을 두려워하지 않는 인물일 필요는 없다. 두려움을 느끼면서도 성장을 위해 도전을 택할 수 있다. 무사의 중심 동기는 전문적인 토벌 업무가 아니라 자기 단련이다.

전투 역할은 위협적인 상대에게 집중하여 제거하는 것이다. 위험을 감수한다는 테마만으로 낮은 HP 유지·자해·분노 자원 등의 세부 규칙을 도입하지 않는다. 공격 기회를 붙잡고 상대를 압박하는 구체적인 방법은 이후 설계한다.

### 6.7. 도적의 공통 정체성과 전문화 — 기획 확정

이 절은 도적의 테마·역할과 세 전문화의 Lv2·Lv5 보상을 정의한다. 명시된 보상 효과와 레벨 배치는 기획 확정이며, 암살자 Lv5 액티브의 대체 효과는 미정이다. 코드·에셋 구현 완료를 뜻하지 않는다. 수치·비용과 명시하지 않은 세부 동작·장비 제한은 미정이다. 기존 초기 테스트 능력치나 후면 강제 치명타를 변경하지 않는다. 세계관의 기본 분위기는 [World_Premise.md](World_Premise.md), 은신·투명화와 전투 처리 규칙은 [BattleSystem.md](BattleSystem.md)의 4.6~4.7절을 따른다.

#### 6.7.1. 도적의 공통 정체성

도적은 사람과 장소의 허점을 읽고, 정면으로 해결하기 어려운 일을 기교와 임기응변으로 풀어온 사람들이다. 감시를 피해 움직이고 상대의 주의를 돌리며, 위험한 상황에서 빠져나오는 데 익숙하다.

이러한 기술은 원정에서도 접근하기 어려운 장소를 조사하거나 적의 경계를 뚫는 전문성이 된다. 범죄와 가까운 경력을 가질 수 있지만, 모든 도적의 현재 성격이나 도덕성을 동일하게 규정하지 않는다.

전투에서는 상대가 대응하기 어려운 순간과 위치를 이용한다. 기존 후면 강제 치명타는 세 전문화가 공유하는 이 숙련을 표현한다. 전문화는 빈틈을 이용하는 공통 기반 위에서, 무엇을 노리고 어떤 방식으로 싸우는지를 구분한다.

은신은 주변 배경에 몸을 숨기는 공통 기술로 모든 직업이 사용할 수 있다. 도둑 전용 습득 스킬로 두지 않는다. 사용 시 어떤 적의 시야에도 닿아 있지 않아야 하며, 2 AP와 현재 이동력 2를 지불한다. 사용 후 AP나 이동력이 남아 있으면 턴을 끝내지 않고 계속 행동할 수 있다. 시야의 기본 형상은 적의 정면과 정면 양옆으로 펼쳐지는 기존 BattleSystem 구상을 유지하며 이번 결정으로 새 형상을 추가하지 않는다.

- 은신 캐릭터나 적이 일반 이동 또는 강제 이동으로 1칸 이동한 뒤, 적의 Facing이 바뀐 뒤마다 발각을 검사한다. 한 명 이상의 적 시야에 닿으면 즉시 은신을 해제한다. 도둑의 기존 발각 보정은 유지한다.
- 은신 중 피해를 받으면 즉시 해제한다. 은신 진입 이외의 AP 소비 행동은 조건 판정과 효과 처리를 모두 마친 뒤 해제한다. 그 행동은 처리 완료까지 은신 조건과 은신에서 얻는 효과를 사용할 수 있다.
- 은신 상태의 이동력 페널티는 현재 검증용으로 -1이다. 턴 시작에 지급하는 이동력에만 적용하며, 턴 도중 진입해도 이 상태 페널티로 남은 이동력을 추가 차감하지 않는다. 진입 비용인 이동력 2는 정상 지불한다. 이동 애니메이션 속도나 한 칸 이동 비용을 바꾸지 않는다.

투명화는 은신 상태로 취급하여 은신 조건을 충족한다. 적의 시야를 무시하고 은신의 이동력 -1 페널티를 받지 않는 점을 제외한 나머지 상태 규칙은 일반 은신과 같다. AP 소비 행동은 처리 후 투명화를 해제하며 피해를 받으면 즉시 해제한다. 암살자의 능력명은 계속 투명화로 표기한다. 투명화를 얻는 개별 스킬·패시브의 비용과 지급 계약은 그 능력의 설계를 따른다.

AI는 은신한 적을 보이지 않는 것으로 취급한다. 정확한 시야 거리·차폐/장애물과 도둑 발각 보정의 세부 적용, 마지막 목격 위치 수색·범위 공격 같은 고급 대응은 후속 범위다. 은신 -1과 암습 +2는 밸런싱 과정에서 조정할 수 있다.

#### 6.7.2. 세 전문화의 역할

| 전문화 | 역할 | 살아온 방식 | 전투에서 노리는 것 |
| --- | --- | --- | --- |
| 암살자 | 투명화·후방 기습 | 은밀하게 접근해 특정 상대를 제거하는 일을 해온 사람 | 투명화로 접근하고 후방을 기습한 뒤, 처치로 다음 투명화 기회 확보 |
| 도둑 | 은신·방해 | 경비와 잠금, 사람들의 부주의를 이용해 물건을 훔쳐온 사람 | 시야를 피해 적의 방향과 대응을 흐트러뜨릴 기회 |
| 불한당 | 상태이상 대상 근접 압박 | 뒷골목의 시비와 난투 속에서 몸으로 살아남은 사람 | 해로운 상태이상이 있는 적에게 추가 피해와 AP 이득 확보 |

#### 6.7.3. 암살자 — 목표를 정하고 기회를 기다리는 사람

암살자는 누구를 제거해야 일이 끝나는지 판단하고, 접근 경로와 상대의 경계를 살핀다. 기회가 왔을 때 확실하게 행동하는 데 익숙하다.

전투에서는 투명화로 접근하고 적의 후방을 기습하며, 적을 처치한 뒤 다시 투명화하여 다음 기회를 잡는다. 전사의 무사가 강적과 맞서며 자신을 단련한다면, 암살자는 정해진 목표를 처리하는 데 집중한다.

| 레벨 | 보상 | 확정 효과 |
| --- | --- | --- |
| Lv2 | 고정 패시브 | 전투 시작 시 투명화 상태가 된다. |
| Lv2 | 고정 액티브 | 적의 뒤로 도약한 뒤 공격한다. 투명화 여부와 관계없이 사용할 수 있다. |
| Lv2 | 고정 액티브 | 투명화 상태가 된다. |
| Lv5 | 고정 패시브 | 적을 처치하면 투명화 상태가 된다. |
| Lv5 | 고정 액티브 — 교체 예정 | 기존 방어력 무시 물리 공격과 투명화 유지 효과를 철회했다. 더 화려한 기술로 재설계하며 실제 효과는 미정이다. |

투명화는 진입 행동을 제외한 AP 소비 행동의 조건 판정과 효과 처리를 모두 마친 뒤 해제한다. AP를 사용하지 않는 일반 이동은 이 해제 조건에 해당하지 않으며 피해를 받으면 즉시 해제한다. 기존 Lv5 공격의 투명화 유지 예외는 철회했으며 새 기술에 자동 승계하지 않는다. 투명화 부여 스킬은 자신의 AP 비용 때문에 새로 부여한 투명화가 즉시 해제되지 않도록 처리한다. AP 소비 행동으로 적을 처치하여 새 투명화를 얻는 경우의 상태 갱신·해제 순서와 실패·취소 처리는 별도 설계한다.

Lv5 액티브의 새 효과·사용 조건·비용·피해·대상·이동·투명화 해제 여부는 모두 별도 설계한다. 그림자 연쇄·처형의 순간·일섬과 연속 기습·처치 후 재사용·경로 공격·순간이동·분신은 채택하지 않았다. 기존 기술을 도적 Lv1 암습으로 그대로 이전하는 결정도 아니다. Lv5 처치 후 투명화 패시브와 Lv2 보상은 유지한다.

보상의 정식 스킬명은 미정이다. 잠행·배후 기습·몸 숨기기·흔적 지우기는 가칭이며, 개별 스킬의 AP 비용·피해·사거리·사용 횟수 제한, 도약 경로·착지 가능 조건, 투명화의 지속 시간·대상 지정 제한과 시야 외의 특수 탐지 효과는 미정이다. 직접 지정 불가·범위 피해 허용을 확정하지 않는다. 피해 시 즉시 해제와 AP 행동 처리 후 해제는 6.7.1절의 공통 상태 규칙을 따른다.

#### 6.7.4. 도둑 — 원하는 것을 손에 넣는 사람

도둑은 경비가 무엇을 보고 있는지, 어떤 물건이 방치되어 있는지, 어디로 들어가고 나올 수 있는지를 살피며 살아왔다. 손재주뿐 아니라 관찰과 주의 분산, 빠른 판단이 중요한 사람들이다.

전투에서는 공통 은신을 강화하고 상대의 방향과 대응을 흐트러뜨려 자신과 동료에게 기회를 준다. 은신과 방해에 특화된 전문화다.

| 레벨 | 보상 | 확정 효과 |
| --- | --- | --- |
| Lv2 | 고정 패시브 | 도둑이 은신 중이면 감지하는 적의 정면 직선상의 칸에서만 시야로 발각된다. 정면 양옆 구역에서는 발각되지 않는다. |
| Lv2 | 고정 액티브 — 주의 돌리기 | 지정한 지점으로 적 하나의 바라보는 방향을 바꾼다. |
| Lv2 | 선택 액티브 — 비열한 행동 | 모래뿌리기(실명), 급소공격(약화), 발걸기(넘어짐) 중 하나를 선택하여 습득한다. |
| Lv5 | 고정 패시브 | Lv2의 정면 직선 발각 제한에 거리를 더하여 정면 직선 1~2칸 안에서만 시야로 발각된다. 원래 적의 감지 거리가 더 짧으면 늘리지 않는다. |
| Lv5 | 고정 액티브 — 무기 빼앗기(가칭) | 은신 상태에서 인간형 적 하나의 무기를 빼앗는다. 투명화도 사용 조건을 충족한다. |

Lv2에서는 패시브 1개·고정 액티브 1개·선택 액티브 1개를 함께 얻는다. 주의 돌리기와 비열한 행동은 서로 대체하지 않는다. 은신 자체를 별도로 배우거나, 은신의 이동력 감소를 완화하거나, Lv5 방해 스킬 뒤 이동력을 회복하는 보상은 두지 않는다. 모래뿌리기는 Lv2 선택지이며 Lv5 고정 보상이 아니다.

발각 패시브는 해당 도둑을 발견하는 시야 범위만 좁힌다. 적의 실제 시야나 다른 동료의 발각 범위를 변경하지 않으며, 투명화를 정면 1~2칸에서 발각되는 상태로 바꾸지 않는다. 주의 돌리기는 방향 변경이며 도발이나 강제 공격 대상 지정이 아니다.

실명·약화·넘어짐의 정확한 효과·지속 시간·중첩과 각 스킬의 AP 비용·사거리·피해 여부·사용 제한·실패 및 취소 처리는 미정이다. 급소공격의 기절 효과와 오물투척·구역질 후보는 폐기한다. 급소공격과 불한당이 동일한 약화 상태를 사용하면 중첩·갱신을 공통 상태이상 규칙과 맞춰야 한다. 주의 돌리기로 적의 Facing이 바뀌면 발각을 검사하며, AP를 소비하는 경우 행동 처리 후 은신·투명화를 해제한다. 그 밖의 사용 조건은 별도 설계한다.

무기 빼앗기의 실제 아이템 획득 여부, 무기를 잃은 적의 공격·스킬 변화와 무기가 없는 인간형 적에게 사용 가능한지는 미정이다. AP를 소비하면 행동 처리 후 은신·투명화를 해제하며, 사용 조건은 처리 완료까지 유지한다. 무기 빼앗기와 패시브의 정식 명칭은 미정이다.

#### 6.7.5. 불한당 — 싸움의 주도권을 놓치지 않는 사람

불한당은 위협과 허세, 반칙이 오가는 뒷골목에서 싸움을 익혔다. 상대가 겁먹었는지, 무리하고 있는지, 언제 몰아붙이면 무너지는지를 읽는 데 능숙하다.

전투에서는 해로운 상태이상으로 빈틈이 생긴 적을 집요하게 공격하여 추가 피해와 AP 이득을 얻는다. 동료가 부여한 상태이상을 활용하거나 직접 약화를 부여하여 근접 압박을 시작할 수 있다. 대화에서 사용한 ‘불량배’는 이 전문화를 가리키며 별도의 도적 전문화가 아니다. 정식 명칭을 변경할지는 별도로 정하고 이 문서에서는 불한당을 유지한다.

거친 수단을 쓰면서도 동료에게 의리를 지키거나 약자를 감싸는 인물일 수 있다. 이런 성격의 가능성을 특정 행동이나 도덕적 성향의 필수 조건으로 고정하지 않는다.

| 레벨 | 보상 | 확정 효과 |
| --- | --- | --- |
| Lv2 | 고정 패시브 — 약한 놈부터(가칭) | 해로운 상태이상이 하나 이상 걸린 적에게 직접 공격으로 추가 피해를 준다. |
| Lv2 | 고정 액티브 — 비열한 일격(가칭) | 적 하나에게 물리 피해를 준 뒤 약화를 부여한다. 약화된 적은 공격 피해가 감소한다. |
| Lv5 | 고정 패시브 — 기세 몰기(가칭) | 해로운 상태이상이 걸린 적을 공격하여 피해를 주면 AP를 일부 회복한다. 자신의 턴마다 한 번 발동한다. |
| Lv5 | 고정 액티브 — 난타(가칭) | 적 하나를 연속으로 두 번 물리 공격한다. 각 타격에 상태이상 대상 추가 피해와 물리 방어력을 적용한다. |

추가 피해는 해로운 상태이상의 개수만큼 증가하지 않으며 독 등의 지속 피해에 자동 적용하지 않는다. 각 타격 시 대상의 상태이상을 확인한다. 피해를 준 뒤 부여하는 상태이상은 앞선 피해의 추가 피해 근거가 될 수 없지만, 다른 해로운 상태이상이 이미 있으면 그 조건으로 적용할 수 있다.

기세 몰기는 실제 피해를 주어야 발동하며 모든 공격이 자신의 턴당 한 번 제한을 공유한다. 난타의 두 타격으로 AP를 두 번 회복하지 않는다. 회복에는 기존 최대 AP를 적용하며, 회복과 발동 횟수 소모의 정확한 시점은 미정이다.

모든 능력명은 가칭이다. 추가 피해량·AP 회복량·스킬 비용·사거리·기본 피해·사용 제한, 약화의 감소량·지속 시간·중첩, 판정 대상인 해로운 상태이상의 목록·분류는 미정이다. 독의 지속 피해에 추가 피해를 적용하지 않는다는 규칙과 독에 걸린 적이 직접 공격의 추가 피해 조건을 충족하는지는 구분한다.

추가 피해의 속성·치명타·방어력 계산 순서, 약화의 공격 피해 감소 범위·계산 순서와 각 타격의 치명타·피해 무효화 판정은 기존 전투 규칙과 대조하여 정한다. 난타 첫 타격으로 대상이 제거됐을 때의 후속 타격, 실패·취소와 비용 처리는 미정이며 다른 적으로 자동 전환하거나 비용을 환불한다고 가정하지 않는다. 강제 도발이나 특정 대상 공격을 강요하는 규칙도 추가하지 않는다.

### 6.8. 궁수의 공통 정체성과 전문화 — 기획 확정

이 절은 궁수의 테마, Lv1 기본 패시브와 정령궁수의 Lv2·Lv5 고정 보상을 정의한다. Lv1 직업 액티브 경계사격의 확정 범위는 6.3.1~6.3.2절을 따른다. 명사수·샤프슈터의 실제 보상과 각 기술의 미정 비용·지속·세부 처리는 이후 설계한다. 정령궁수의 기본 공격 교체는 전문화 효과이며 기존 프로토타입 직업 수치·에셋이 변경되었다는 뜻이 아니다. 세계관의 기본 분위기는 [World_Premise.md](World_Premise.md)를 따른다.

#### 6.8.1. 궁수의 공통 정체성

궁수는 멀리 있는 움직임을 읽고, 거리와 지형을 활용해 위험에 대응해온 사람들이다. 사격 솜씨뿐 아니라 관찰하고, 자리를 고르고, 쏠 때를 판단하는 숙련을 공유한다.

긴 기본 공격 사거리는 직업의 기본 수치·공격 특성으로 유지하며 별도의 Lv1 패시브로 취급하지 않는다. Lv1 기본 패시브는 전투 외 준비 능력으로, 전투가 종료되면 전투에서 사용할 수 있는 **특수화살 1개를 제작**한다.

특수화살의 종류·효과·사용 방법·보유 한도·중복 보유·적용 공격·소비 시점, 제작을 유발하는 종료 조건이 승리만인지 패배 등을 포함하는지와 제작 주체의 참가·생존 조건은 미정이다. 아이템·탄약 스키마, 보관 주체·인벤토리 구조와 수명도 별도 설계한다. 일반 장비의 3개 장착·공용 보관 규칙을 특수화살에 자동 적용하지 않으며, 이 제작 개념을 정령궁수의 다음 기본 공격 강화와 같은 소비 자원으로 확정하지 않는다.

전문화는 같은 원거리 전투 기반 위에서 속성과 환경, 사격 조건, 이동 중의 기회 중 무엇에 집중하는지를 구분한다. 전문화 이름만으로 특정 무기의 사용을 강제하지 않는다.

#### 6.8.2. 세 전문화의 역할

| 전문화 | 역할 | 살아온 방식 | 전투의 핵심 판단 |
| --- | --- | --- | --- |
| 정령궁수(명칭 조정 가능) | 다속성 사격·환경 간섭 | 정령의 힘을 화살과 사격에 싣는 사람 | 어떤 속성과 경로로 전장에 간섭할 것인가 |
| 명사수 | 정밀 사격·원거리 지원 | 중요한 순간에 정확히 맞히는 솜씨로 신뢰를 얻어온 사람 | 어디서 어떤 순간을 기다릴 것인가 |
| 샤프슈터 | 기동 사격·측면 지원 | 위험한 현장을 돌아다니며 짧은 사격 기회를 붙잡아온 사람 | 어디로 움직여 다음 공격 기회를 만들 것인가 |

명사수와 샤프슈터는 일상적인 의미가 가까운 이름이지만, 게임에서는 준비된 위치에서 정밀하게 사격하는 역할과 이동하며 공격 기회를 잡는 역할로 구분한다.

#### 6.8.3. 정령궁수 — 정령의 힘으로 전장에 간섭하는 궁수

기존 사냥꾼 전문화는 폐기하고 정령궁수 계열로 교체한다. 정식 명칭은 추후 조정할 수 있다. Lv2는 속성 분산과 환경 간섭, Lv5는 물리 피해 방어와 무속성 범위 사격으로 확장한다.

| 레벨 | 보상 구분 | 확정 효과 |
| --- | --- | --- |
| Lv2 | 고정 패시브 | 기본 공격의 기존 물리 피해를 제거하고 한 번의 공격에 물·불·전기·독 피해를 각각 1씩 가한다. 한 공격에 네 피해 성분이 있는 구조이며 네 번의 공격으로 처리하지 않는다. 각 성분에는 해당 속성 방어력을 개별 적용한다. 치명타이면 기존 치명타 추가 피해 +2를 무속성 피해로 한 번만 추가한다. |
| Lv2 | 고정 액티브 | 불·물·전기·독 정령 중 하나를 선택하고 다음 기본 공격 1회에 그 정령의 특수 효과를 추가한다. 아래 표를 따르며 Lv2 패시브의 네 속성 기본 피해를 유지한다. |
| Lv5 | 고정 패시브 | 처음 받는 물리 피해 1회를 완전히 무효화한다. 발동 후 소모되며 이후 이 용병 자신의 턴 3회마다 다시 충전된다. 물·불·전기·독·무속성 피해에는 적용하지 않는다. |
| Lv5 | 고정 액티브 | 사용한 턴 동안 자신이 가하는 모든 기본 공격의 피해 속성을 무속성으로 바꾸고, 매 기본 공격이 착탄 지점을 중심으로 범위 1의 모든 적을 공격한다. 같은 턴에 기본 공격을 여러 번 하면 매번 적용한다. Lv2 액티브로 부여한 정령의 경로·상태이상 등 특수 효과는 유지한다. |

| 선택 정령 | 다음 기본 공격 1회에 추가하는 효과 |
| --- | --- |
| 불 | 화살 경로에 불붙은 지면과 연막을 남기고 최종 대상에게 추가 화염 피해와 화상을 부여한다. |
| 물 | 화살 경로에 젖은 지면을 남기고 최종 대상에게 젖음을 부여한다. |
| 전기 | 화살 경로상의 모든 적에게 전기 피해를 가하고 최종 대상에게 감전을 부여한다. |
| 독 | 화살 경로에 독 지면을 남기고 최종 대상에게 독을 부여한다. |

Lv2 치명타는 네 성분에 각각 +2를 더하지 않는다. 추가 공격력·장비·축복의 보정 배분과 공격·피격 효과의 발동 단위는 별도 설계한다. 전기 정령의 경로상 다중 피해가 공격 1회인지와 대상별 발동·구체 피해량도 미정이다. Lv2 액티브의 선택·준비·소비 시점, 준비 중 재사용·실패·취소·전투 종료, 경계사격 등 기본 공격을 수행하는 반응과의 연결 및 AP 비용·사용 제한은 정하지 않았다.

Lv5 패시브의 물리 피해 1회 판정·피해 0 처리·복수 성분 및 다른 차단 효과와의 순서, 자기 턴 3회의 시작/종료 기준·발동 중인 현재 턴 포함·추가 턴 처리, 전투 시작·종료 시 충전 상태는 미정이다. 촛농 갑옷의 피해 1회 차단·자기 5턴 재충전 규칙과 같은 능력으로 합치지 않는다.

Lv5 범위 1은 착탄 헥스와 인접 헥스를 뜻하는 방향으로 사용하되 아군 피해·장애물·지형 효과 적용 범위는 별도 설계한다. 무속성으로 바뀐 네 피해 성분의 통합 여부·계산과 치명타·장비 효과, 범위 내 대상별 처리 순서·추가 효과의 전파, Lv5 액티브 비용·지속의 턴 경계·실패·취소는 미정이다. Lv5가 교체하는 것은 기본 공격의 피해 속성이며, Lv2 정령의 경로·상태이상 등 특수 효과를 제거하지 않는다.

불붙은 지면·연막·젖은 지면·독 지면을 생성하는 요구로 환경효과를 전투 기획 범위에 포함한다. 각 Hex의 독립된 지면 슬롯 1개·공기 슬롯 1개, 각 슬롯의 단일 상태와 확정된 환경 반응은 [BattleSystem.md](BattleSystem.md)를 따른다. 전기 지면·전기 구름 후보와 전기 정령의 직접 피해는 구분하며 전기 정령이 그 환경을 자동 생성한다고 확정하지 않는다. 화상·젖음·감전·독의 세부 효과·지속, 화살 경로 산정과 환경·캐릭터 상태의 상호작용, 환경의 지속·중첩·연쇄 반응 재평가 및 남은 변환은 후속 설계한다.

구현 후에는 특수화살 제작과 정령 부여를 구분하고, Lv2의 한 공격·네 성분·개별 방어·무속성 치명타 +2 한 번, Lv5 물리 피해만 무효화·자기 턴 재충전과 매 기본 공격의 무속성 범위화를 확인한다. 미정 계약을 먼저 정한 뒤 환경 경로·상태이상과의 연결을 검증한다. 이는 향후 확인 기준이며 실행 결과가 아니다.

#### 6.8.4. 명사수 — 중요한 순간을 맡길 수 있는 사람

명사수는 먼 거리의 위협에 대응하거나 동료를 엄호하는 상황에서 정확한 사격으로 인정받아온 사람이다. 좋은 위치와 사격 조건을 확보하고, 필요한 순간에 확실한 공격을 제공한다.

전투의 중심은 준비와 판단의 정확성이다. 가만히 서 있는 것 자체보다 어디에서 어떤 순간에 사격해야 동료에게 필요한 지원이 되는지를 판단한다. 상황이 바뀌면 더 적절한 사격 위치를 선택할 수 있다.

준비와 정밀 사격을 표현할 구체적인 행동·비용·효과 및 수치는 이후 설계한다. 이 테마만으로 고정 위치나 특정 무기의 사용을 요구하지 않는다.

#### 6.8.5. 샤프슈터 — 움직이는 상황에서도 기회를 잡는 사람

샤프슈터는 호송과 정찰, 야외의 교전처럼 상황이 계속 변하는 현장에서 사격을 익힌 사람이다. 적과 아군의 움직임에 맞춰 위치를 바꾸고, 잠깐 드러난 틈을 공격한다.

이동과 사격을 연결하는 임기응변이 중심이다. 새로운 공격 기회가 생기는 위치를 찾아 측면에서 지원하고, 상대의 접근과 아군의 움직임에 맞춰 거리를 조절한다.

기동 사격의 세부 스킬·특성, 이동과 공격을 연결하는 방식 및 자원 규칙은 이후 설계한다. 기존의 AP·이동력 규칙을 이 테마만으로 변경하지 않는다.

### 6.9. 마법사의 공통 정체성과 전문화 — 기획 방향 확정

이 절은 마법사의 공통 정체성과 우선 설계할 전문화의 테마·역할 방향을 정의한다. 세부 스킬·특성, 전투 효과와 수치, 사령술의 구체적인 설정은 미정이다. 세계관의 기본 분위기는 [World_Premise.md](World_Premise.md)를 따르며, 전문화 이름만으로 기존 마법의 한계를 확대하거나 구현된 기능으로 취급하지 않는다.

#### 6.9.1. 마법사의 공통 정체성

마법사는 마법을 지식과 훈련으로 익혀, 자신이 탐구하는 힘을 현실에서 다루는 사람들이다. 연구하는 대상과 마법을 사용하는 방식에 따라 서로 다른 경력과 전문성을 갖는다.

기상술사·마공학자·사령술사를 우선 설계 대상으로 삼되, 마법사의 전문화를 이 세 종류로 고정하지 않는다. 향후 다른 연구 대상과 전투 역할을 가진 전문화를 추가할 수 있으며, 구체적인 추가 계획은 아직 정하지 않는다.

#### 6.9.2. 우선 설계할 세 전문화의 역할

| 전문화 | 어떤 사람들인가 | 싸우는 방식 | 역할 방향 |
| --- | --- | --- | --- |
| 기상술사 | 바람과 구름, 비와 번개의 흐름을 관찰하고 다루어온 사람 | 전장의 여러 지점에 영향을 주며 유리한 상황을 만든다. | 범위 압박·전장 환경 조절 |
| 마공학자 | 마법의 작용을 장치와 도구로 구현하려는 사람 | 준비한 장치를 배치·운용하여 필요한 기능을 제공한다. | 설치·거점 확보·전술 지원 |
| 사령술사 | 죽은 자의 흔적과 죽음 이후에 남는 힘을 연구하는 사람 | 사령이나 죽음의 힘을 통해 적을 압박하고 약화하는 방향을 검토한다. | 지속 압박·약화. 소환은 검토 후보이며 확정하지 않는다. |

역할은 콘텐츠 설계의 방향이며, 날씨 변화·설치 장치·소환 등 구체적인 전투 시스템이 확정되었다는 뜻은 아니다. 특히 사령술사는 소환 중심인지 저주 중심인지 등 실제 전투 방식이 열려 있다.

#### 6.9.3. 기상술사 — 대기의 흐름을 읽고 다루는 사람

바람과 구름, 비와 번개의 변화를 관찰하며 지식을 쌓아온 마법사다. 선원과 여행자의 곁에서 날씨를 살피거나, 높은 곳에서 대기의 변화를 연구해온 배경을 가질 수 있다.

전투에서는 바람이 통하는 방향과 적들이 모인 위치 등 전장의 흐름을 살핀다. 여러 지점에 영향을 주어 적을 압박하고, 일행이 유리하게 싸울 조건을 만드는 역할을 지향한다.

날씨를 다룬다는 테마만으로 넓은 지역의 기후를 자유롭게 바꾸거나 흰밀물을 통제할 수 있다고 정하지 않는다. 실제로 다룰 현상과 범위·지속 시간·효과는 이후 설계한다.

#### 6.9.4. 마공학자 — 마법을 장치와 도구로 구현하는 사람

마공학자는 마법을 반복해서 사용할 수 있는 형태로 만들려는 사람이다. 공방에서 실험하거나 탐사 현장에 필요한 도구를 제작하며 지식을 쌓아온 배경이 어울린다.

전투에서는 무엇을 어디에 준비하고 운용할지 판단한다. 장치와 도구로 필요한 기능을 제공하고, 아군이 활용할 거점과 전술적 기회를 만드는 방향을 지향한다.

표현은 전근대적인 세계 분위기를 따른다. 부적·각인·결정·기구 등은 표현 후보이며, 총기나 보편적인 기계화 기술을 전제하지 않는다. 구체적인 장치의 종류와 배치·운용·회수 규칙, 자원과 수치는 미정이다.

#### 6.9.5. 사령술사 — 죽음이 남긴 것을 연구하는 사람

사령술사는 죽은 자의 흔적과 죽음 이후에 남는 힘을 연구하는 사람이다. 장례와 매장지, 죽은 자가 남긴 현상을 조사하거나 그로 인한 문제를 해결해온 배경이 가능하다.

금기나 공포의 대상으로 받아들여질 가능성은 있지만, 사회 전체의 평가를 확정하거나 모든 사령술사를 악인으로 규정하지 않는다.

전투에서는 사령이나 죽음의 힘을 통해 적에게 지속적인 압박을 주고 약화하는 방향을 검토한다. 사령을 부리는 소환 중심인지, 산 자를 약화하는 저주 중심인지 또는 다른 방식인지는 이후 결정한다.

영혼의 실체, 죽은 자와 대화할 수 있는지, 시신을 움직이는 힘과 영혼이 같은 것인지 등 사령술의 구체적인 설정은 미정이다. 이 테마만으로 소환·시신 조작·부활·죽은 자와의 대화를 확정하지 않으며, 용병의 HP 0 회복 규칙도 별도 설계 대상으로 유지한다.

### 6.10. 장비·거래·강화 — 기획 확정·미구현

#### 6.10.1. 장착과 원정 수명

- 용병마다 장비를 최대 3개 장착한다. 왼손·오른손·방어구 같은 부위별 슬롯을 나누지 않는다. 기사에게는 6.11절의 검소의 맹세를 지키기 위한 최대 2개 조건이 별도로 존재한다.
- 같은 종류와 완전히 동일한 장비의 중복 장착을 모두 허용한다. 동일 장비 세 개나 동일 특수 장비 세 개를 집중 배치할 수 있다.
- 장비를 바꿔도 직업의 기본 공격 방식과 무기 표현은 유지한다. 도적에게 대검 장비를 장착해도 단검 전투를 유지한다.
- 장비마다 효과와 수치가 고정되며 무작위 옵션·수치를 붙이지 않는다. 일반 장비는 단순 능력치 효과를 중심으로 하되 망치 같은 짧은 기능성 효과도 포함한다.
- 전투 중에는 장비를 변경하지 못한다. 전투 밖에서는 장소 제한 없이 장착·해제·파티원 간 교환이 가능하다.
- 미장착 장비는 파티 공용 인벤토리에 보관하며 보관 수량을 제한하지 않는다.
- 장착·보관 장비 모두 해당 원정에서만 유지하고 원정 종료 시 초기화한다. 다음 원정으로 이월하지 않으며 새 원정의 시작 장비 구성·지급 방식은 미정이다.

동일 장비 장착 허용과 효과 계산은 구분한다. 합산·곱연산·확률·발동 횟수·상한의 공통 중첩 규칙은 미정이며, 아래에 명시한 자비·복수의 개별 규칙만 확정한다. 고정 장비 수치는 설계값이며 출시 밸런스 검증을 마쳤다는 뜻이 아니다.

#### 6.10.2. 상점 거래

장비는 상점에서 골드로 구매하며 유한한 판매 재고에서 구매 수량만큼 차감한다. 같은 원정 동안 재고를 보충하지 않고 재방문으로 소진 재고를 복구하지 않는다. 보유 장비를 상점에 판매하면 골드를 얻는다.

상점별 판매 목록·초기 수량·생성 시점·가격·되사기와 판매품의 재고 편입 여부는 미정이다. 특수 장비의 상점 판매도 일반 구매 허용만으로 확정하지 않는다. 장비의 장착·해제·파티원 교환 자유와 상점에서 수행하는 거래는 구분한다.

#### 6.10.3. 고정 강화

일반 장비를 강화하면 그 장비에 정해진 특수 장비가 된다. 결과는 하나로 고정하고 선택 분기·무작위 결과를 사용하지 않는다. 동일한 일반 장비는 동일한 특수 장비로 강화된다. 기존 능력치를 삭제하거나 낮추지 않고 정해진 특수효과를 추가한다. 이 원칙은 강화에 따른 능력치 증가를 금지하지 않는다.

각 장비는 한 번만 강화할 수 있으며 특수 장비는 추가 강화할 수 없다. 강화 기회는 기본적으로 이벤트에서 제공하고 플레이어가 장착 또는 보관 중인 강화 가능한 장비 한 개를 직접 선택한다. 동일 장비가 여러 개 있어도 선택한 한 개만 강화한다. 특수 장비는 보상으로 직접 획득할 수도 있으며 이 경우에도 재강화 불가·중복 장착·원정 종료 초기화 규칙을 적용한다.

공통 강화 비용·조건·빈도와 이벤트 외 강화 경로는 미정이다. 다른 강화 경로를 전면 금지하지 않는다. 결과 미리보기·선택 취소·대상 없음 처리, 이벤트 결과와 대상 선택의 적용 순서·저장 계약은 별도 설계한다.

#### 6.10.4. 일반 장비와 고정 강화형

| 일반 장비 | 일반 효과 | 강화형 | 강화형 효과 |
| --- | --- | --- | --- |
| 장검 | 물리공격력 +1 | 성검 | 최종 물리공격력 보너스 +2, 적의 물리방어력을 무시한다. |
| 망치 | 공격 피해 계산 후 대상의 물리방어 1을 누적 파괴한다. 이번 공격은 파괴 전 방어력, 후속 공격은 감소한 방어력을 사용한다. | 방패파괴자 | 공격당 물리방어 2를 누적 파괴한다. 적의 물리방어를 0으로 만들면 대상이 1턴 기절한다. 누적 파괴와 피해 계산 후 파괴 순서를 유지한다. |
| 단검 | 치명타 대미지 +1 | 자비 | 기존 치명타 대미지 +1을 유지한다. 공격 피해 적용 후 살아 있는 대상의 현재 체력이 기준 이하이면 처형한다. |
| 방패 | 물리방어 +1. 방향 차단은 부여하지 않는다. | 복수 | 기존 물리방어 +1을 유지한다. 물리 피해를 받으면 자신의 물리방어력만큼 공격자에게 물리 피해를 준다. |
| 갑옷 | 체력 +2 | 촛농 갑옷 | 기존 체력 +2를 유지한다. 전투 시작에 다음 피해 한 번을 막는 효과가 충전되며 발동하여 소모되면 착용자의 자기 턴 5턴 후 재충전한다. |

성검 1개의 최종 물리공격력 보너스는 +2이며, 방패파괴자 1개의 공격당 최종 물리방어 파괴량은 2로 확정한다. 강화 시 일반 장비의 값 1을 각각 2로 대체한다.

- 자비의 처형 기준은 장착 1개일 때 현재 체력 3 이하, 2개면 4 이하, 3개면 5 이하다. 기준치를 3씩 합산하지 않는다.
- 복수는 장착한 각 장비가 개별 발동한다. 물리방어력 4에 복수 3개면 물리 피해 4의 반격 세 번이며 피해 12 한 번으로 합치지 않는다. 우선 이 규칙으로 검증하고 강하면 별도 결정으로 변경한다.
- 촛농 갑옷은 전체 라운드가 아니라 착용자의 자기 턴으로 센다. 추가 자기 턴이 발생하면 그것도 세되 이 규칙만으로 추가 턴 획득 기술을 새로 도입하지 않는다.

공격력 보너스가 기존 기본 공격 피해와 스킬 피해에 적용되는 범위, 단검의 치명타 대미지 계산 위치, 갑옷의 체력 효과와 최대·현재 HP 연결은 별도 계약이다. 장비가 직업의 공격 표현을 유지한다는 사실로 모든 공격에 같은 수치 공식을 적용하지 않는다.

방어 파괴의 유지 기간·하한·중복 장착·공격 범위·다단 발동 단위, 방패파괴자의 양수→0 전환·초과 파괴·이미 0인 대상과 기절의 행동 제한·해제 시점은 미정이다. 하한 0이나 전투 종료까지 유지를 임의 확정하지 않는다. 복수의 반격 연쇄·0 피해 발동·방어력 참조 시점·피해 계산·다른 장비와의 연결, 촛농 갑옷의 중복 소모·개별 재충전·턴 시작/종료 충전·발동 중인 현재 턴 포함 여부도 미정이다. 공격 종류별 발동·효과 순서와 처형의 처치 연계는 BattleSystem 4.10절에서 구분한다.

이 다섯 장비와 강화형만 이번에 구체화했다. 이전 논의의 추격자의 장검·분쇄자의 망치·흡혈 단검·보복의 방패·불굴의 갑옷은 채택하지 않는다. 다른 아이템 목록이나 특수효과 예시를 확정 콘텐츠로 추가하지 않는다.


#### 6.10.5. 구현 후 확인 기준

아래는 향후 확인 기준이며 구현·실행 결과가 아니다. 전투 효과의 확인 기준은 BattleSystem 4.10.4절을 따른다.

- 동일 장비를 포함해 최대 3개를 장착하고 부위별 슬롯을 요구하지 않는다. 전투 밖에서 장소와 관계없이 장착·해제·파티원 교환이 가능하며 전투 중에는 변경할 수 없다.
- 미장착 장비를 수량 제한 없이 공용 보관하고, 장착·보관 상태와 관계없이 원정 종료 시 초기화하여 다음 원정으로 이월하지 않는다.
- 상점 구매 수량만큼 유한 재고가 감소하고 같은 원정의 재방문으로 복구되지 않는다. 보유 장비 판매 시 골드를 얻는다.
- 같은 일반 장비는 항상 같은 특수 장비로 강화된다. 장착 또는 보관 중인 동일 장비가 여러 개여도 플레이어가 선택한 한 개만 바뀐다.
- 강화로 기존 능력을 삭제하거나 낮추지 않으며 직접 보상으로 얻은 경우를 포함해 특수 장비의 재강화를 허용하지 않는다.

### 6.11. 기사의 공통 정체성과 기어스 — 기획 확정·미구현

기사는 데스메리온에게 맹세하여 특별한 힘을 얻은 신규 기본 직업이며 양손 무기를 사용한다. 스스로를 구속하는 기어스와 그 대가로 얻는 특성을 직업 성장에 연결한다. 데스메리온의 맹세 로어는 [GodsLore.md](GodsLore.md)를 따른다. 양손 무기라는 직업 표현은 장비 부위 슬롯을 추가하거나 장비마다 기본 공격 표현을 바꾸는 규칙이 아니다.

#### 6.11.1. Lv1 시작 능력

- **고정 패시브:** 이 캐릭터를 강제로 이동시킬 수 없다.
- **강타(가칭):** 양손 무기로 강하게 공격한다. 기본 쿨타임은 3턴이다. 기본 AP 비용을 지불한 뒤 남은 모든 AP를 추가로 소모하여 피해를 증가시킨다.

강타의 기본 AP 비용·추가 AP당 피해 증가량·정확한 피해 공식과 쿨타임 갱신 시점·카운트는 미정이다. 강제 이동 면역과 자발적 기술 이동의 경계, 이동을 막았을 때 부수 효과·실패 비용, 강타의 사거리·공격 속성·세부 대상 지정은 별도 설계한다. 기사 기본 능력치와 직업 식별자·스키마·에셋은 아직 정하지 않았다.

#### 6.11.2. Lv2 기어스와 대응 특성

Lv2에서는 기어스와 대응 특성이 일대일로 묶인 다음 네 쌍 중 하나를 전문화로 선택한다. 기어스를 위반하면 그 기어스로 얻은 대응 특성을 영구적으로 몰수하며 기사의 기본 Lv1 능력은 유지한다.

| 기어스 | 지켜야 하는 조건 | 대응 특성 |
| --- | --- | --- |
| 불살의 맹세 | 플레이어의 능동적 선택으로 적을 직접 죽음에 이르게 해서는 안 된다. 반격으로 죽이는 것은 위반이 아니며 플레이어가 선택한 공격에 딸린 처형으로 죽이는 것은 위반이다. | 강타 피해 2배 |
| 감시의 맹세 | 특정 방향을 등지지 않는다. | 강타가 기사 자신을 중심으로 사방 2칸 범위 안의 모든 적을 타격한다. |
| 검소의 맹세 | 장비를 최대 2개까지만 착용한다. | 강타 쿨타임이 1턴으로 감소하여 자기 차례마다 한 번 사용할 수 있다. |
| 퇴마의 맹세 | 마법사와 팀을 이룰 수 없으며 전투에 마법사가 있다면 반드시 마법사를 먼저 공격해야 한다. | 강타가 적중한 적에게 침묵을 부여한다. |

불살의 맹세에서는 선택한 공격에 연계된 자비의 처형도 위반이며 반격으로 적이 죽은 경우는 위반이 아니다. 선택 행동·반격·처형의 원인을 판별할 데이터 계약과 그 밖의 간접 피해·연쇄 효과 판정은 미정이다.

감시의 특정 방향을 정하는 방법과 위반 판정 시점은 미정이다. 일반 이동·공격과 이동 반응 공격의 Facing 변경이 맹세에 미치는 영향을 함께 설계한다. 감시 강타의 사방 2칸은 자기 중심 범위이며 경계사격의 전방 120° 영역으로 바꾸지 않는다. 퇴마의 마법사 분류·우선 공격 충족 조건·도달 불가 대상·범위 공격 처리와 침묵의 지속·적용 범위도 미정이다.

검소의 맹세 선택 당시 이미 장비 3개를 착용한 경우와 위반의 검사 시점, 위반 이후 제약을 계속 적용하는지와 몰수 상태의 저장 계약은 별도 설계한다. 영구 몰수는 대응 특성이 자동 복구되는 효과로 해석하지 않는다. 원정 종료 후 기록 보존 여부와 다음 원정에 대한 영향은 미정이며, 용병의 원정 수명 자체를 변경하지 않는다. 기사의 Lv3~Lv5 세부 보상·기존 전문화 보상 틀과의 연결은 별도 설계하고 이번에 추가 스킬을 자동 지급하지 않는다.

#### 6.11.3. 향후 확인 기준

아래는 구현 후 확인할 기준이며 실행 검증 결과가 아니다.

- 강제 이동 면역과 강타의 기본 AP 지불 후 잔여 AP 전부 소모를 확인한다. 미정 피해 공식·쿨타임 갱신 기준을 먼저 정한다.
- Lv2에서 기어스·특성 한 쌍을 선택하고 해당 기어스 위반 시 대응 특성만 몰수하며 Lv1 능력을 유지한다.
- 불살의 선택 공격 연계 처형과 반격 사망을 구분하고, 감시의 자기 중심 범위·검소의 착용 2개 조건 및 자기 차례당 강타 한 번·퇴마의 우선 공격과 침묵을 확인한다.

## 7. 데이터 책임과 정적 스키마

ClassDefinition은 7.4절의 프로토타입 스키마를 구현했다. 능력 종류의 보유 목록과 공통 기본 설정을 분리하며, AbilitySettings의 책임과 저장 구조는 7.5절을 따른다. 직업 식별자와 정적 데이터 목록은 7.6절을 따른다. 그 밖의 데이터 이름과 필드는 역할을 설명하는 제안이며 최종 스키마가 아니다.

### 7.1. 정적 데이터

| 데이터 | 책임 |
| --- | --- |
| ClassDefinition | 직업별 기본 능력치, 기본 공격 설정과 보유 능력 enum 목록 |
| AbilitySettings | 능력 종류별 공통 기본 설정을 하나의 ScriptableObject에서 관리 |
| MercenaryDataList | MercenaryClass 키와 ClassDefinition 참조의 대응 및 공통 AbilitySettings 참조 |
| ClassLevelTable | 직업별 레벨 보상표 |
| SkillDefinition | 스킬의 조건, 비용, 사거리와 효과 |
| TraitDefinition | 용병 개인 공용 특성의 조건과 효과 |
| ItemDefinition | 고정 장비 효과·수치와 일반 장비의 고정 강화 결과 정의. 필드·타입은 미정 |

같은 직업의 인스턴스는 읽기 전용 직업 정의를 공유하며, 개별 용병의 성장 결과로 직업 기본값 자체를 변경하지 않는다. 직업 능력의 초기 보유와 레벨 보상에 의한 획득을 어떻게 연결할지는 이후 구체화한다.

### 7.2. MercenaryInstance — 원정 수명·제안

MercenaryInstance는 아직 구현하지 않았다. 파티 공유 레벨·경험치는 원정 파티 데이터가 소유하며 MercenaryInstance에 중복 저장하지 않는다. 파티 데이터의 구체적인 타입과 필드명은 별도 설계한다.

| 데이터 후보 | 역할 |
| --- | --- |
| InstanceId | 용병 인스턴스의 고유 식별자 |
| Name | 용병 이름 |
| Class | MercenaryClass 타입의 직업 식별자. MercenaryDataList에서 직업 정적 데이터를 찾는 키 |
| CurrentHP | 전투 사이에도 유지하는 현재 HP |
| SelectedRewardIds | 파티 레벨업에 따라 용병별로 선택한 성장 보상 |
| EquippedItemIds | 용병이 장착한 최대 3개 장비의 참조. 동일 정의의 여러 개를 구분하는 표현은 미정 |

전문화 선택은 용병별 원정 데이터에 기록해야 한다. 전문화 식별자를 별도로 둘지 기존 선택 보상 기록에 포함할지 등 실제 저장 구조는 미정이다.

직업별 고정 보상은 해당 용병의 직업과 파티 공유 레벨로, 전문화별 고정 보상은 선택한 전문화와 파티 공유 레벨로 계산하여 중복 저장을 피하는 방향을 검토한다. 선택 보상의 식별 방식과 선택 횟수·보상 위치를 표현하는 방법은 미정이다.

장착 장비는 최대 3개이며 부위별 슬롯을 사용하지 않는다. 미장착 장비는 수량 제한 없는 파티 공용 인벤토리에 보관한다. 동일 장비 여러 개 중 선택한 한 개만 강화할 수 있어야 하므로 개별 장비를 구분해야 한다. 정적 정의 ID만으로 개별 보유품을 동일시하지 않되 식별자·아이템 인스턴스 타입·소유자·장착/보관 참조와 강화 상태의 실제 저장 구조는 미정이다. 장착·보관 장비와 상점 재고는 원정 상태로 관리하며 소유권 제안은 GameState를 따른다.

최대 HP 등 계산 가능한 최종 능력치는 별도의 영구 저장값보다 정적 데이터와 현재 성장 상태를 조합해 산출하는 방향을 검토한다. 캐시 여부와 재계산 시점은 확정하지 않는다.

### 7.3. BattleUnit — 전투 수명·제안

- 전투 유닛 ID와 원본 용병 참조
- 전투 시작 시 적용할 능력치
- 전투 중 HP
- AP와 남은 이동력
- Hex 좌표와 바라보는 방향
- 전투 중에만 유지되는 상태효과

전투 중 상태는 전투 시스템이 관리하고, 종료 후 필요한 결과만 원정 데이터에 반영하는 방향을 제안한다. AP·좌표·방향 등은 다음 전투로 그대로 넘기지 않는다. 현재 구현의 HexCharacter와 이 초안의 구체적인 대응 관계는 아직 정하지 않는다.

장착 목록은 전투 중 고정하며 촛농 갑옷의 충전·남은 자기 턴은 전투 상태로 구분한다. 기회 공격의 보유자·대상별 라운드 사용 기록, 경계사격 준비 상태, 은신·투명화와 강타 쿨타임도 공유 정의와 구분할 런타임 상태다. 공유 장비 정의나 AbilitySettings에 개별 발동 상태를 저장하지 않는다. 구체적인 상태 소유자·필드·저장과 전투 결과 반영은 미정이며, 방어 파괴의 유지 기간은 별도 결정 전까지 전투 수명으로 단정하지 않는다. 기사 기어스 선택·위반·특성 몰수는 한 전투의 임시 상태와 구분해야 하며 저장·수명 계약은 6.11절의 미정을 따른다.

정령궁수의 다음 기본 공격에 적용할 정령, 물리 피해 무효화의 충전·자기 턴 카운트와 사용한 턴의 무속성 범위 사격 상태도 공유 정의와 구분한다. Hex의 지면·공기 상태는 전장 환경이며 용병의 상태이상과 동일한 목록으로 간주하지 않는다. 각 상태의 소유자·필드·갱신·초기화와 특수화살 제작·보관·소비의 저장 계약은 별도 설계하며 기존 클래스에 필드가 추가되었다고 기록하지 않는다.

### 7.4. ClassDefinition — 프로토타입 코드·에셋 구현

같은 직업의 용병이 공유하는 기본 전투 설정을 정의한다. 적용 범위는 전사·도적·궁수를 생성하여 기본 전투를 진행하는 프로토타입이다. 파티의 현재 레벨·경험치와 개별 용병의 현재 HP·장비·성장 선택은 포함하지 않는다.

아래 필드를 ScriptableObject로 저장한다. BaseStats는 ClassBaseStats, BasicAttack은 BasicAttackDefinition 직렬화 struct다. 정수 수치는 int, 확률은 float로 저장하며, Abilities는 AbilityType 배열로 일반 직렬화한다. 외부에는 읽기 전용 프로퍼티와 능력 개수·인덱스 조회를 제공한다.

| 필드 | 형식 | 역할 |
| --- | --- | --- |
| DisplayName | 문자열 | UI에 표시할 직업 이름 |
| BaseStats | 능력치 묶음 | 성장·장비·축복 적용 전의 기본 유닛 능력치 |
| BasicAttack | 기본 공격 설정 | 기본 공격의 피해·사거리·속성 |
| Abilities | 능력 종류 enum 목록 | 프로토타입에서 해당 직업이 제공하는 능력 종류. 설정값은 포함하지 않는다. |

ClassDefinition에는 문자열 Id나 직업 enum 필드를 두지 않는다. 직업 식별자는 MercenaryDataList의 MercenaryClass 키 한 곳에서 관리한다. 에셋 이름이나 표시 이름을 바꿔도 해당 키와 에셋의 연결은 유지된다.

#### 7.4.1. BaseStats

| 필드 | 형식 | 단위·유효 범위 |
| --- | --- | --- |
| MaxHP | 정수 | 1 이상 |
| Movement | 정수 | 턴당 이동량, 0 이상 |
| CriticalChance | 실수 | 0~1. 0.05는 5% |
| PhysicalDefense | 정수 | 0 이상 |
| WaterDefense | 정수 | 0 이상 |
| FireDefense | 정수 | 0 이상 |
| LightningDefense | 정수 | 0 이상 |
| PoisonDefense | 정수 | 0 이상 |

프로토타입의 기본 방어력은 음수를 허용하지 않는다. 향후 취약성이나 방어력 감소를 도입할 때 최종 방어력의 음수 허용 여부를 별도로 정한다.

#### 7.4.2. BasicAttack

직업 정의 안에 포함하는 설정 묶음이다. 현재 범위에서는 별도의 BasicAttackId나 공유 공격 데이터를 두지 않는다.

| 필드 | 형식 | 단위·유효 범위 |
| --- | --- | --- |
| Damage | 정수 | 치명타·방어력 적용 전 피해, 1 이상 |
| Range | 정수 | 최대 헥스 거리, 1 이상 |
| DamageType | AttackAttribute | 물리·물·불·전기·독·무속성 중 하나. 전기는 Electricity 값에 대응한다. |

기본 공격 비용은 직업에 지정된 기본 공격 SkillDefinition의 ActionPointCost를 사용한다. 다른 스킬에 기본 공격의 비용·피해·사거리를 자동 적용하지 않는다.

#### 7.4.3. Abilities

각 항목은 능력 종류를 나타내는 AbilityType enum 값이다. 설정값이나 능력 에셋 참조는 목록에 저장하지 않는다. 같은 능력 종류는 직업에 관계없이 AbilitySettings의 공통 기본 설정을 사용한다. 향후 전투 연결에서는 직업 이름 대신 능력 종류에 따라 처리한다. 현재 전투의 직업별 능력 판정은 아직 에셋에 연결하지 않았다.

AbilityType은 Unity에 의존하지 않는 RaggedBanner.Mercenaries 어셈블리에 둔다. 능력 보유 여부는 전투뿐 아니라 이벤트에서도 검사할 수 있는 용병 데이터다. 전투 판정과 이벤트 조건의 실행은 각 시스템이 담당하며, 이벤트에서의 구체적인 사용 방식은 아직 정하지 않는다.

직업별 설정 덮어쓰기나 같은 능력 종류의 설정 변형을 선택하는 구조는 현재 범위에 두지 않는다. 임의의 조건·효과를 조립하는 범용 구조도 만들지 않는다.

| 능력 enum 항목 | AbilitySettings의 공통 설정 | 동작 |
| --- | --- | --- |
| DirectionalPhysicalNegation = 1 | 정면·측면·후면 무효화 확률 | 방향에 따라 물리 피해를 무효화한다. |
| RearGuaranteedCritical = 2 | 추가 설정 없음 | 후면에서 공격하면 강제 치명타가 발생한다. |

무효화 확률은 각각 0~1이며, 서로 다른 방향에 적용하므로 합계가 1일 필요는 없다. 측면은 BattleSystem의 ‘그 외 방향’에 해당한다. 방향 판정과 피해 처리 순서는 기존 공통 전투 규칙을 따른다.

후면 강제 치명타는 기본 공격 전용 설정에 넣지 않는다. 기존 규칙에 따라 적용 대상 공격의 사거리 안에서 후면 조건을 검사한다.

능력 목록은 비어 있을 수 있다. null 배열, 정의되지 않은 enum 값과 같은 능력 종류의 중복 등록을 거부한다. AbilityType은 Flags enum이 아니며 0은 정의하지 않는다.

Abilities는 프로토타입 초기 제공 능력을 뜻한다. 실제 게임의 1레벨 보상이나 영구 고정 능력으로 확정하지 않는다. 레벨 성장과 연결할 때 같은 능력을 중복 지급하지 않도록 획득 출처를 정한다.

#### 7.4.4. 프로토타입 직업 데이터

기존 테스트 수치를 사용하며, HP는 직업 기본 최대 HP로 해석한다. 최종 밸런스는 아니다. 아래 Abilities는 현재 프로토타입 에셋의 기록이며, 새 기획의 전사 기회 공격·방향 차단 특성·장비 효과·Lv1 액티브 연결은 7.4.7절의 미구현 범위를 따른다.

| 항목 | 전사 | 도적 | 궁수 |
| --- | --- | --- | --- |
| MercenaryDataList의 키 | MercenaryClass.Warrior = 0 | MercenaryClass.Rogue = 1 | MercenaryClass.Archer = 2 |
| DisplayName | 전사 | 도적 | 궁수 |
| MaxHP | 10 | 8 | 8 |
| Movement | 2 | 4 | 2 |
| CriticalChance | 0.05 | 0.15 | 0.10 |
| PhysicalDefense | 1 | 0 | 0 |
| WaterDefense | 0 | 0 | 0 |
| FireDefense | 0 | 0 | 0 |
| LightningDefense | 0 | 0 | 0 |
| PoisonDefense | 0 | 0 | 0 |
| BasicAttack.Damage | 3 | 3 | 3 |
| BasicAttack.Range | 1 | 1 | 3 |
| BasicAttack.DamageType | 물리 | 물리 | 물리 |
| Abilities | DirectionalPhysicalNegation | RearGuaranteedCritical | 빈 목록 |

방향별 무효화 확률은 이 직업 표에 저장하지 않고 7.5절의 AbilitySettings에서 관리한다. 생성 시 현재 HP를 최대치로 채울지는 용병 생성 규칙에서 별도로 정한다.

#### 7.4.5. 사용 흐름과 검증

1. MercenaryDataList의 직업 키·정의 참조와 공통 AbilitySettings를 읽고 각각의 데이터 및 능력 설정 연결을 검증한다.
2. 향후 용병 인스턴스는 MercenaryClass 타입의 Class로 직업을 참조한다. MercenaryInstance 자체는 미구현이다.
3. 능력치 산출 과정이 직업 기본값을 읽고, 이후 파티 공유 레벨에 따른 직업 보상·용병별 성장 선택·장비 등의 효과를 반영한다. 구체적인 계산 구조는 8절의 설계 대상이다.
4. 연결부는 보유 능력 enum에 필요한 공통 설정을 확인하여 전투에 전달한다. 전투 시스템은 산출된 수치와 능력 종류·설정으로 판정을 수행한다.

직업 정의는 실행 중 공유하는 읽기 전용 원본으로 취급한다. 피해나 버프, 성장 때문에 원본을 변경하지 않는다.

ClassDefinition.Validate는 비어 있거나 공백뿐인 표시 이름, 기본 수치의 유효 범위, 공격 속성과 능력 enum의 유효성, 같은 능력 종류의 중복 여부를 검증한다. 확률은 NaN·무한대를 허용하지 않는다. 직업 키와 정의 참조의 검증은 7.6절의 목록 검증이 담당한다. 공통 능력 설정은 AbilitySettings.Validate에서 검증한다. 검증은 첫 오류에서 false와 원인 문자열을 반환하며 잘못된 값을 보정하거나 로그를 출력하지 않는다.

레벨 보상표, 외형·프리팹, 스킬 목록과 장비 데이터는 이 프로토타입 스키마에 포함하지 않았다. 장비 최대 3개와 부위 슬롯 없음은 6.10절의 새 기획이며 스키마 구현 완료가 아니다. 정적 데이터 코드·에셋과 검증, GameData에서 참조된 목록을 초기화하는 코드는 구현했으며 전투 연결은 미구현이다.

#### 7.4.6. 저장 형식 — ScriptableObject

- 직업당 ScriptableObject 에셋 하나를 두며, 전사·도적·궁수의 정의를 각각 작성한다.
- BaseStats와 BasicAttack은 해당 직업 에셋 내부에 포함한다.
- Abilities는 능력 enum 목록으로 직업 에셋 내부에 저장한다. SerializeReference와 능력별 ScriptableObject 에셋 참조를 사용하지 않는다.
- 능력의 설정값은 직업 에셋에 복사하지 않고 하나의 AbilitySettings ScriptableObject에서 관리한다.
- 직업 식별자는 MercenaryDataList의 MercenaryClass 키로만 관리하고 ClassDefinition 안에 중복 저장하지 않는다.
- 직업 정의의 원본은 ScriptableObject로 관리한다. 같은 데이터를 CSV에서도 수동 관리하는 이중 원본은 두지 않는다.

저장 형식과 전투 로직의 데이터 형식은 구분한다. GameData가 참조된 에셋을 검증하며, 기존 전투 로직의 순수 C# 구조를 유지하도록 필요한 일반 C# 데이터로 전달하는 방향을 제안한다. 구체적인 전투 전달 타입과 용병 생성 방식은 이후 설계한다.

ScriptableObject 자체가 불변성을 보장하지는 않는다. 공유 에셋은 읽기 전용 원본으로 취급하고, 현재 HP·버프·성장 결과는 런타임 데이터에서 관리한다. 직업 에셋은 Assets/GameData/Mercenaries의 Warrior.asset·Rogue.asset·Archer.asset이다.

#### 7.4.7. 새 직업·장비 능력과의 연결 — 기획 확정·구조 미정

현재 ClassDefinition의 전사 Abilities에 있는 DirectionalPhysicalNegation과 프로토타입 확률 표는 기존 구현 현황이다. 새 기획의 전사 기본 패시브는 기회 공격이며 방향 차단은 수호자 Lv2 고정 패시브로 옮긴다. 정면 50%·측면 10%·후면 0%를 새 패시브의 테스트 기준으로 사용한다. 일반 방패의 물리방어 +1과 구분하며 전문화 습득을 데이터에 연결하는 실제 구조는 미정이다.

ClassDefinition은 직업의 시작 능력, 성장 보상은 레벨·전문화로 얻는 능력, 장비 정의는 고정 장비 효과와 강화 결과를 담당하는 방향으로 책임을 구분한다. AbilitySettings는 공통 설정을 보유하며 개별 장비 상태나 전투의 발동 횟수·재충전 상태를 맡지 않는다. 우선권과 기사 직업·기어스, 이동 반응·은신·새 능력의 표현과 기존 AbilityType 연결은 별도 설계하며 코드·에셋·새 필드가 구현됐다고 해석하지 않는다. 7.4~7.6절의 BaseStats와 MercenaryClass 세 항목은 기존 프로토타입 구현 현황이다.

궁수의 특수화살 제작과 정령궁수의 다성분 기본 공격·정령 부여·물리 피해 무효화·무속성 범위 사격도 새 기획이다. 기존 BasicAttack의 단일 속성·피해나 AbilityType·AbilitySettings가 이를 이미 표현한다고 해석하지 않으며 필요한 데이터 계약을 별도로 설계한다.

### 7.5. AbilitySettings — 프로토타입 코드·에셋 구현

능력 종류별 공통 기본 설정을 하나의 ScriptableObject 에셋에 저장한다. ClassDefinition은 어떤 능력을 보유하는지만 선언하며, 같은 능력 종류는 모든 직업에서 같은 기본 설정을 사용한다.

현재는 능력별로 이름 붙은 설정 묶음을 일반 직렬화하여 에셋 내부에 포함한다. 능력별 독립 에셋, enum과 에셋을 연결하는 별도 등록 목록, 다형적 설정 목록은 두지 않는다. 능력 종류에 따른 명시적인 분기로 필요한 설정을 사용한다.

| 능력 종류 | 공통 설정 | 프로토타입 값 |
| --- | --- | --- |
| DirectionalPhysicalNegation | 정면·측면·후면 무효화 확률 | 정면 0.50·측면 0.10·후면 0 |
| RearGuaranteedCritical | 추가 설정 없음 | 설정 묶음이나 빈 에셋을 만들지 않는다. |

DirectionalPhysicalNegationSettings struct의 FrontChance·SideChance·RearChance를 float로 저장한다. 무효화 확률은 각각 유한한 0~1로 검증하며, 합계가 1일 필요는 없다. 모두 0이어도 유효하다. 설정이 없는 RearGuaranteedCritical을 누락된 설정으로 취급하지 않는다.

AbilitySettings는 읽기 전용 설정 데이터다. 발동 횟수·남은 시간·판정 결과 등 용병별 또는 전투별 런타임 상태를 보유하지 않으며, 능력 실행을 담당하는 전역 매니저로 사용하지 않는다. 전투에서 능력의 발동과 대상·방향 판정은 전투 로직의 책임이다.

공통 기본 설정을 변경하면 이후 해당 설정을 사용하는 모든 직업에 적용된다. 실행 중 에셋 변경의 즉시 반영은 이번 설계에 포함하지 않는다. 성장·장비·일시 효과에 의한 능력 보정이 필요할 경우 원본 설정 변경과 구분하여 별도로 설계한다.

공통 에셋은 Assets/GameData/Mercenaries/AbilitySettings.asset이며 MercenaryDataList가 참조한다. GameData가 목록 에셋을 참조·검증하고 GameData.Mercenaries로 공개한다. 전투에 전달할 일반 C# 데이터의 구체적인 구조는 미정이다.

### 7.6. 직업 식별자와 MercenaryDataList — 코드·에셋 구현

MercenaryClass는 RaggedBanner.Mercenaries 어셈블리가 소유하는 순수 C# enum이다. Warrior = 0, Rogue = 1, Archer = 2로 정의하며, 기존 BattleUnitClass도 이 타입으로 통일한다. 직업 식별자가 필요한 전투·이벤트 등은 용병 도메인을 참조한다. Mercenaries는 전투나 Unity 에셋 계층을 참조하지 않는다.

ClassDefinition·AbilitySettings·MercenaryDataList와 에셋 검증은 RaggedBanner.MercenaryData 어셈블리에 둔다. MercenaryData는 Mercenaries의 직업·능력 enum과 Combat의 기존 AttackAttribute를 사용한다.

MercenaryDataList는 다음 참조를 보관하는 ScriptableObject다.

| 필드 | 형식 | 역할 |
| --- | --- | --- |
| _classes | SerializableDictionary<MercenaryClass, ClassDefinition> | 직업 식별자와 해당 직업 정의의 연결 |
| _abilitySettings | AbilitySettings 참조 | 모든 직업이 공유하는 능력 기본 설정 |

SerializableDictionary는 키와 값이 짝을 이루는 Entry 목록을 직렬화 원본으로 둔다. 조회용 Dictionary는 비직렬화 캐시이며 Entry 목록으로부터 만든다. 직렬화 원본과 캐시를 각각 수동 관리하지 않는다. 목록 검증은 원본 Entry를 확인하므로 중복 키나 잘못된 항목이 캐시 생성 과정에서 숨겨지지 않는다. 공유 원본의 실행 중 변경은 이번 범위에 포함하지 않는다.

MercenaryDataList.Validate(out error)가 성공한 이후에만 TryGetDefinition으로 직업 정의를 조회할 수 있다. 검증 전이나 검증 실패 후에는 조회에 실패한다. 목록의 OnEnable·OnValidate는 검증 상태와 조회 캐시를 무효화하고, SerializableDictionary의 OnAfterDeserialize는 조회 캐시를 무효화한다. 다시 사용하려면 명시적으로 검증한다. 검증과 캐시 무효화는 직렬화된 Entry 원본을 보정하거나 덮어쓰지 않는다.

SerializableDictionary와 MercenaryDataList의 검증은 다음을 확인한다.

- 직업 목록이나 원본 Entry 목록이 null이면 오류다.
- 모든 정의된 MercenaryClass가 정확히 한 번씩 등록되어야 한다. 빈 목록이나 직업 누락은 오류다.
- 정의되지 않은 enum 키, 중복 키, null인 ClassDefinition 참조는 오류다.
- 동일한 ClassDefinition 에셋을 여러 직업 키에 연결하면 오류다.
- 등록된 모든 ClassDefinition의 개별 데이터가 유효해야 한다.
- AbilitySettings가 연결되어 있으면 자체 데이터를 검증한다.
- DirectionalPhysicalNegation을 가진 직업이 하나라도 있으면 AbilitySettings 참조가 필수다. 설정 없이 사용하는 RearGuaranteedCritical이나 빈 능력 목록만으로는 공통 설정 참조를 요구하지 않는다.

MercenaryDataList.asset은 Warrior·Rogue·Archer 키에 각각의 직업 에셋을 연결하고 기존 AbilitySettings.asset을 참조한다. Assets/GameData/Mercenaries의 프로토타입 에셋은 직업 3개·공통 설정 1개·목록 1개로 총 5개다. 런타임의 목록 초기화와 공개는 7.7절의 GameData가 담당하며, 전투 초기화 연결은 아직 구현하지 않았다.

### 7.7. GameData — 목록 초기화·전역 조회 코드 구현

GameData는 RaggedBanner.MercenaryData의 MonoBehaviour이며 Assets/Scripts/MercenaryData/GameData.cs에 둔다. 직렬화된 _mercenaryDataList로 목록 에셋을 참조하고, 하나의 static _instance로 소유자를 관리한다. 외부에는 읽기 전용 static MercenaryDataList 프로퍼티인 GameData.Mercenaries를 제공한다.

- Awake에서 루트 GameObject인지, 목록 에셋이 할당되어 있는지, 목록 검증이 성공하는지 확인한다. 모두 통과하면 DontDestroyOnLoad로 유지한 뒤 전역 참조를 공개한다.
- 기존 소유자가 있으면 중복 GameData는 자신의 GameObject를 파괴한다.
- OnDestroy는 자신이 현재 소유자인 경우에만 전역 참조를 해제한다. 중복 객체의 파괴가 기존 소유자를 해제하지 않는다.
- SubsystemRegistration에서 정적 참조를 초기화한다.
- 초기화가 완료되기 전에 GameData.Mercenaries에 접근하면 InvalidOperationException이 발생한다.

사용자가 Scene의 루트 GameObject에 GameData를 배치하고 MercenaryDataList.asset을 할당한다. GameData 초기화 이후에 소비 코드가 접근해야 한다. Scene 로드·전환 순서의 제어와 전투·이벤트 소비 코드 연결은 이번 구현에 포함하지 않는다. BattleUnitStats.ForClass의 하드코딩된 수치와 기존 전투 동작은 유지한다.

## 8. 최종 능력치 계산 구조 — 설계 예정

필요한 효과를 다음 출처에서 가져오는 방향을 검토한다.

- 직업 기본 능력치
- 파티 공유 레벨에 따른 직업 보상과 용병별 성장 선택
- 장비 효과
- 공용 특성과 직업 능력
- 파티 축복
- 전투 중 일시적 효과

이 목록은 합산 순서가 아니다. 모든 효과가 수치 보정인 것도 아니며 구체 계산식·합산 순서·반올림·범위 제한은 미정이다. 장비 중첩도 원칙적으로 별도 설계하되 자비의 1/2/3개 기준 3/4/5와 복수의 장비별 개별 발동은 6.10절의 확정 예외다. 이를 다른 장비의 공통 중첩 규칙으로 확대하지 않는다.

축복은 파티가 보유하는 원정 단위 효과다. 각 MercenaryInstance에 복사하여 소유시키지 않고 계산에 필요한 파티 효과를 참조하는 방향을 제안한다. 구체적인 축복 효과가 미정이므로 축복만을 이유로 기본 능력치를 추가하거나 범용 효과 분류를 확정하지 않는다.

BlessingSystem에서 정한 지속 효과와 일회성 지급은 구분해야 한다. 능력치를 재계산하는 행위가 일회성 지급을 다시 실행해서는 안 된다. 회복이나 아이템 지급을 일회성 효과로 채택할 경우에도 같은 원칙을 적용하며, 이 예시 자체가 축복 콘텐츠를 확정하지는 않는다.

최대 HP 변경 시 현재 HP를 어떻게 조정할지는 별도 결정 사항이다. 능력치 재계산만으로 자동 회복이나 소생이 발생한다고 가정하지 않는다.

## 9. 전투 시스템과의 연결 — 제안

현재 전투의 직업 타입은 MercenaryClass로 통일했지만 BattleUnitStats.ForClass의 하드코딩된 테스트 수치와 기존 전투 동작은 유지한다. ClassDefinition·AbilitySettings·MercenaryDataList를 전투에서 읽어 적용하는 연결은 아직 구현하지 않았다.

1. 전투 시작 전 파티에서 HP가 1 이상인 용병을 참여 후보로 판정한다.
2. 실제 참가자의 능력치와 현재 HP를 바탕으로 BattleUnit을 생성한다.
3. 전투 중 HP·AP·남은 이동력 등의 변경은 전투 시스템이 관리한다.
4. HP가 0인 유닛은 기존 전투 규칙에 따라 전장에서 제거한다.
5. 승리 시 참가자의 최종 HP를 원정 용병 데이터에 반영한다.
6. 전투 불능 용병의 MercenaryInstance는 유지하며, 회복 전까지 이후 전투에서 제외한다.

전장에서 제거된 참가자도 결과 반영 대상에 포함되어야 한다. 남은 전장 유닛 목록만으로 결과를 구성하여 HP 0인 용병이 누락되지 않도록 설계해야 한다. 결과 기록의 소유자와 전달 인터페이스는 아직 정하지 않는다.

BattleSystem의 현재 `Waiting` 상태는 승리·패배 판정이 아니며, 전투 종료와 결과 전달 구현이 완료되었다고 가정하지 않는다.

승리가 확정되면 파티 경험치 1을 지급하는 성장 규칙을 적용한다. HP 결과 반영, 경험치 지급·레벨업, 성장 보상 선택과 이벤트 후속 결과의 구체적인 처리 순서는 미정이다.

궁수 Lv1 패시브는 전투 종료 후 특수화살 1개 제작을 요구한다. 승리만 해당하는지와 패배·무승부 등을 포함하는지, 참가·생존 조건 및 다른 결과 처리와의 순서는 미정이다. 결과 조회·UI 재표시·능력치 재계산을 별도의 전투 종료로 취급해 추가 제작하지 않도록 종료 처리와 연결해야 하며, 실제 저장·중복 방지 계약은 후속 설계한다.

EventSystem의 확정 규칙에 따라 전투 패배는 원정 종료로 연결한다. 일반적인 다음 전투 준비나 패배 이후 이벤트 후속 결과 적용으로 연결하지 않는다.

## 10. 이벤트 시스템과의 연결

장비 강화 기회를 이벤트에서 제공하고 보상으로 특수 장비를 직접 획득할 수 있는 기획은 확정했다. 장착·보관 장비 한 개의 직접 선택과 강화 처리는 6.10절을 따른다. 현행 이벤트 조건·Result·Effect가 개별 장비 선택·지급·강화를 이미 지원한다는 뜻은 아니며, 대상 없음·취소·전투 및 다른 결과와의 적용 순서·저장 계약은 EventSystem에서 별도로 설계한다. 일반 장비 상점 거래는 시설 시스템의 책임과 연결한다.


현재 EventSystem의 조건과 결과는 개별 용병의 직업·스킬·HP 판정 및 HP 변경·영입을 지원하지 않는다. 현재 단계에서 개별 용병 ID에 의존하는 이벤트를 도입하지 않는다.

다음은 향후 검토 후보이며 확정 기능이 아니다.

- 특정 직업이나 능력·스킬 보유 여부에 따른 이벤트 선택지
- 이벤트 결과로 용병 HP 회복
- 이벤트를 통한 용병 영입

개별 용병의 HP를 변경하려면 기존 Result 및 Effect 구조의 확장이 필요하다. 마을 시설 등을 통한 회복은 이벤트 시스템과 별도로 구현할 수도 있다.

## 11. 미정 사항

- 용병의 이름과 외형 생성 규칙
- 프로토타입 이후의 직업별 기본 수치와 최종 밸런스, 추가 능력치의 필요성
- 초기화 순서를 포함한 Scene 로드·전환 흐름과 용병 생성 구조
- ClassDefinition·AbilitySettings를 전투에 전달할 일반 C# 데이터 구조
- 생성 시 현재 HP 설정

## 12. 다음 설계 순서

1. GameData.Mercenaries로 공개된 직업·능력 데이터 목록을 전제로 소비 코드의 초기화 순서 및 전투 데이터 전달 방식을 구체화한다.
2. 파티 공유 레벨·경험치와 MercenaryInstance의 개별 성장 선택을 구분하고, 생성 시 현재 HP 등 초기화 규칙을 정한다.
3. 원정 중 변경값과 전투 임시값, 전투 연결 시 전달할 데이터의 경계를 구체화한다.
4. 성장·장비 등의 기능을 연결할 때 필요한 능력치 계산·중첩 규칙과 HP 상태값 처리 방식을 결정한다.

기본 능력치의 역할 구분, ClassDefinition의 ScriptableObject 저장 및 능력 enum 목록, 하나의 AbilitySettings를 통한 능력별 공통 기본 설정 관리는 합의했다. 기존 정적 데이터와 검증, MercenaryClass를 키로 사용하는 MercenaryDataList 및 프로토타입 에셋 5개를 구현했다. 새 기획의 기본 목록은 우선권을 포함한 11개이며 기사와 기어스·이동 반응·은신·수호자·궁수 특수화살·정령궁수 개정까지 기존 코드에 반영했다는 뜻은 아니다. 성장 규칙은 파티 공유 레벨·경험치와 용병별 보상 선택, 프로토타입 시작 Lv1·최대 Lv5, 승리당 파티 경험치 1 및 다음 레벨 필요 경험치 `현재 레벨`로 확정했다. 용병 인스턴스·전투 연결과 나머지 스키마·계산 규칙은 필요한 범위부터 설계하며, 구현은 별도 요청 후 진행한다.
