# 전투 우선 구현·검증 로드맵

> 개정일: 2026-11-08  
> 문서 성격: 승인된 전투 우선 개발 방향, 단계별 구현 범위와 재미 검증 기준을 관리한다. 게임 규칙의 상세 명세나 구현 완료 보고서가 아니다.  
> 현재 위치: C4 대표 Lv2 전문화 비교 단계. 개척자·암살자·정령궁수의 주요 기능과 공통 스킬·쿨타임·9칸 스킬바·환경 피해·연막·타격 이벤트·실제 비행 투사체를 구현했다. 최근 타격 이벤트·투사체 연결은 Unity 컴파일 오류 0건, 관련 EditMode 테스트 205/205 통과, 독립 리뷰 Pass 및 사용자 정상 동작 확인을 받았다. 세부 검증 범위는 8절에 기록한다. 상태이상·Lv5·장비 조합은 후속 범위이며 기능 동작 확인을 C1~C4 전체 완료나 재미·밸런스 검증 완료로 확대하지 않는다.

## 1. 개발 목표와 우선순위

탐험과 전투는 게임의 가장 큰 두 축이다. 탐험은 현재 재미 검증에서 기대한 결과를 얻지 못해 수정 중이며, 당분간은 **탐험 없이 전투만 반복해도 재미있는가**를 먼저 확인한다.

현재 개발 순서는 다음과 같다.

**반복 가능한 단독 전투 → 전사·궁수의 이동 반응 → 공통 은신·도적 암습 → 대표 Lv2 전문화 비교 → 장비 조합 → 다양한 전투 구성과 조정**

원정 용병의 HP 유지, 실제 경험치 지급, 영입·상점·이벤트·지도·최종 도전 연결은 전투 개발의 선행 조건에서 제외한다. 전투에 필요한 직업·능력·장비 효과는 테스트 편성에 직접 지정하여 검증한다.

먼저 반복할 흐름은 다음과 같다.

`테스트 편성과 시작 조건 설정 → 전투 → 결과와 판단 복기 → 같은 조건으로 재시도 또는 한 요소만 변경하여 비교`

전투 단독 검증의 성공은 탐험이나 전체 게임의 재미 검증 완료를 뜻하지 않는다. 탐험과의 연결은 전투 검증 결과와 수정된 탐험 방향을 함께 검토한 뒤 별도 계획한다. 이 로드맵은 최종 게임의 원정·성장·장비 규칙을 폐기하거나 변경하지 않는다.

게임 규칙은 상세 명세의 확정사항을 따른다. 로드맵의 후보·예시로 미정 수치·효과 순서·스키마를 확정하지 않는다. 상세 문서의 구현 상태 표기가 코드보다 오래된 경우에는 관련 코드를 확인하여 이미 있는 기능을 재사용한다.

이번 승인은 로드맵 개정에 대한 것이다. 각 기능의 실제 구현은 필요한 상세 설계를 제시하고 프로젝트 AGENTS.md의 승인·검증 제한을 따른다.

## 4. 단계별 구현과 재미 검증

### C1. 반복 가능한 단독 전투

**목표:** 기존 전투에서 편성과 조건을 바꾸어 빠르게 반복 플레이한다.

**현재 진행:** 맵 배치 도구·전투 연결·승패 판정·결과 확인·재시작과 지면 이동·공격 범위 표시를 구현하고 사용자 정상 동작 확인을 받았다. 이어 Trait 구조와 후면 치명타·방향 차단의 연결을 구현했으며 2026-11-05 사용자가 안내한 Trait 검증 항목이 모두 정상 작동한다고 확인했다. 현재 방향 표시는 보류하고 동시 전멸·실패·취소 등 남은 경계조건 실행 검증과 전투 재미 평가를 유지하므로 C1 전체는 구현 중이다.

**구현 범위**

- 기존 전투 확인 환경을 활용하고 직업 정적 정의를 전투 입력에 연결한다.
- 아군·적 편성, 초기 배치·방향, 필요한 시작 HP와 난수 seed 등 재현에 필요한 조건을 지정한다.
- Trait 기반과 두 기존 효과의 연결을 재사용하고, 추가 능력·전문화·장비 설정은 C2~C5에서 필요한 만큼 확장한다. 처음부터 전체 성장·장비 스키마나 편집 도구를 만들지 않는다.
- 전투의 승패를 명시적으로 확정하고 결과 확인·재시작을 지원한다. 이벤트 호출이나 원정 상태 변경은 요구하지 않는다.
- 이동·공격 가능 범위와 기존 AP·이동력·현재 턴을 읽을 수 있는 최소 표시를 갖춘다. 지면 범위 표시는 구현·사용자 확인을 마쳤으며 현재 방향 표시는 사용자 요청으로 보류한다.
- 재시작은 테스트 입력으로 새로운 전투 상태를 만든다. 진행 중 행동, 이전 참가자·View 연결, 상태·사용 횟수 등이 다음 시도에 섞이지 않도록 한다.

**확정한 시작 계약:** 저장 맵·순서 있는 테스트 직업 목록·정적 직업 데이터·직업별 프리팹·seed를 입력한다. 설정 검증 → 맵 로드·검증 → 시작점 order 정렬과 수치·Trait·설정 복사 → 전원 생성·연결 → 전투 시작 순서다. 시작점 부족으로 생략되는 후순위 용병은 정상 처리하며, 한 진영이 0명이거나 편성이 인원 상한을 넘으면 시작 오류로 처리한다. 방향 차단 Trait의 설정 누락도 생성 전에 거부한다. 원정 상태를 연결하지 않고 최대 HP로 시작한다.

**확정한 종료·재시작 계약:** 정상 시작 후 적만 전멸하면 승리, 아군만 전멸하면 패배, 양쪽 모두 전멸하면 무승부다. 제거 배치와 이미 발행된 이동·공격의 정리가 끝난 뒤 결과를 한 번 확정한다. 결과 화면에서는 전장·생존 유닛·HP·카메라를 유지하고 전투 명령을 막는다. 재시작은 최초 성공 시점의 최종 배치·수치·Trait·출처·설정·규칙·seed를 재사용하며 맵·카메라를 유지한다. 사전 검사에 실패하면 기존 전투·결과를 보존하고, 통과하면 입력 차단 → 기존 행동·View·표시 정리 → 다음 프레임 재생성 순서로 처리한다. 정리 후 실패는 부분 생성물을 제거하고 오류 상태로 남긴다.

**남은 범위와 후속 방향:** 반복 전투 평가와 남은 경계조건 검증을 진행하고, 확인한 Trait 기반을 C2의 기회공격·경계사격 설계에 재사용한다. 현재 방향 표시와 원정 상태·경험치·보상·이벤트 연결은 계속 보류한다.

**기능 확인:** 같은 설정과 seed로 비교 가능한 시작 상태를 재현하고 전투를 끝내거나 재시작할 수 있다. 결과를 중복 확정하지 않으며 정적 정의가 전투 중 상태 변경으로 오염되지 않는다.

**재미 질문:** 같은 전투를 다시 하면서 배치·이동·공격 순서를 바꾸어 더 나은 결과를 만들 수 있는가? 선택의 결과를 판단할 정보가 보이는가?

### C2. 전사·궁수의 이동 반응

**현재 진행:** 직업 기본 수치의 우선권 복사, 이동 선언·허가·실행, 우선권 순 반응, 기회공격과 경계사격을 구현하고 사용자 정상 동작 확인을 받았다. 적 AI는 경계사격을 사용하지 않는다. 아래 기능 확인 항목은 지속적인 회귀·전술 평가 기준이다.

**선행:** C1. 기능 하나를 연결할 때마다 기존 전투에서 시험한다.

Trait 기반과 기존 두 효과를 재사용해 C2의 우선권·기회공격·경계사격을 연결했다. 기능 동작 확인과 전술 평가 완료는 구분한다.

**구현 범위**

- 확정된 이동 반응 규칙에 따라 **전사 기회공격 → 궁수 경계사격** 순서로 구현한다. 이 개발 순서는 같은 이동에 대한 반응 처리 우선순위가 아니다.
- 모든 유닛의 우선권을 전투 입력과 라운드 순서에 연결한다. 높은 우선권부터 배치하고 동률만 라운드 시작에 무작위로 정하며 해당 라운드의 상대적 순서를 유지한다. 여러 반응의 순서에도 같은 기준을 사용한다.
- 각 1칸 일반 이동 선언 직후 실제 위치 변경 전에 반응을 검사한다. 반응이 발동하면 그 step과 남은 예약 경로를 취소해 이동 명령을 종료하며, 취소한 step에는 이동력을 소모하지 않는다. 생존하고 행동 가능하면 새 입력을 받는다. 밀치기·끌기·돌진·도약 등 강제·기술 이동은 이 반응 대상에서 제외한다.
- 조건을 만족한 기회공격·경계사격을 모두 예약하고 우선권 순서로 처리한다. 앞선 반응으로 이동 주체가 사망하면 나머지는 실행하지 않으며 미실행 기회공격의 대상 기록과 경계사격의 준비 상태를 소비하지 않는다. 실제 반응 공격 시에는 공격 대상을 향해 Facing을 변경하고 그 방향을 유지한다.
- 전사 직업 자동 방향 차단의 제거와 Trait 판정 전환은 완료했다. 기본 전사의 기회공격과 방향별 물리 피해 차단의 수호자 Lv2 습득 연결은 후속 구현이다. 정면 50%·측면 10%·후면 0%는 테스트 기준이고 방패의 물리방어 +1과는 별도다. 현재 Warrior 에셋의 명시적 차단 Trait은 수호자 습득 연결 완료를 뜻하지 않으며 수호자 자체의 검증은 C4에서 다룬다.
- 기회 공격의 적용 범위와 경계사격의 준비 상태·발동 영역을 표시한다.
- 검증에 사용하는 적에게 해당 기능의 최소 사용·대응 규칙을 함께 구현한다.

**남은 설계:** 직업·유닛별 우선권 값과 데이터 연결, 반응 예약·실행 중 조건 변화와 실패·취소, 은신·시야 및 다른 효과와의 처리 순서, AI의 새 명령 선택과 표시 계약. 확정된 발동 시점·비용·횟수·범위·만료·경로 취소를 다시 미정으로 취급하지 않는다.

**기회공격:** 인접한 적이 일반 이동으로 인접 상태를 벗어나려 할 때 AP 없이 발동한다. 보유자 한 명이 같은 대상에게 같은 라운드 동안 최대 한 번이며 서로 다른 대상에는 각각 발동한다. 총 횟수 상한은 없고 새 라운드 시작에 대상별 기록을 초기화한다.

**경계사격:** 2 AP를 지불하고 6방향 중 빈 방향도 선택할 수 있으며 실제 Facing을 선택 방향으로 변경한 뒤 턴을 끝낸다. 현재 Hex 중심에서 선택 방향을 축으로 좌우 60°씩 총 120°인 전방 영역의 경계와 기본 공격 사거리를 모두 포함해 검사한다. 인접 칸은 정면·좌우 앞쪽 3칸이다. 적의 이동 전 현재 위치를 기준으로 하므로 영역에 진입하는 step에는 발동하지 않고, 들어온 뒤 다음 일반 이동 선언부터 다시 판정한다. 발동 AP는 0이고 기본 공격의 피해·속성·치명타·방어력·기본 공격 적용 효과를 그대로 사용한다. 실제 공격 한 번 또는 미발동 상태의 다음 자기 턴 시작에 종료하며, 준비 중 외부 강제 이동·강제 Facing 변경에도 즉시 종료한다.

**기능 확인:** 한 번의 이동과 반응에 비용·피해를 중복 적용하지 않는다. 취소 step의 위치·이동력 보존과 잔여 경로 폐기, 대상별 기회공격 기록의 라운드 초기화, 경계 영역 진입과 영역 안 이동의 차이, 동률의 고정 순서와 대상 사망 후 미실행 반응 보존을 확인한다. 취소·View 소실은 실행 계약에 맞춰 검증한다.

**재미 질문:** 적에게 붙기, 거리를 벌리기, 길목 지키기가 서로 다른 선택이 되는가? 반응 공격이 모든 이동을 포기하게 만들지는 않는가?

### C3. 공통 은신과 도적의 암습

**현재 진행:** 공통 은신·암습을 구현하고 사용자 정상 동작 확인을 받았다. 발각 범위는 헥스 거리 20칸 기준이며 반응 공격을 포함한 공격에도 은신 해제를 연결했다. 이전의 남은 설계 목록은 전부 미구현이라는 뜻이 아니며 추가 차폐·수색 같은 후속 기능과 구분한다.

**선행:** C1의 표시·입력과 C2에서 정한 이동 중 처리 경계.

**구현 범위**

- 공통 은신의 확정 진입·비용·감지 시점·해제·이동력 규칙을 구현한다.
- 은신 상태와 배후 조건을 요구하는 도적 Lv1 암습을 연결한다.
- 감지 범위와 발각 여부를 이해할 수 있게 표시하고, 적 AI가 보이지 않는 대상을 그대로 추적·선택하지 않도록 필요한 판단을 함께 구현한다.
- 이동 한 칸과 방향 변경에서 발각·반응·사망을 검사하는 순서를 연결한다.
- 공격 정면·후면 판정, 경계사격의 시야, 은신 감지 구역을 서로 동일한 것으로 가정하지 않는다.
- 투명화는 은신 조건을 만족하며 적 시야와 은신 이동력 -1 페널티를 무시하고 나머지 규칙은 일반 은신과 같다. 실제 구현은 C4에서 암살자 등 필요한 전문화를 검증할 때 추가한다.

**남은 설계:** 기존 은신 시야 형상에 따른 정확한 거리·차폐와 도둑 발각 보정, 암습 사거리·실패·취소, 여러 상태·반응의 동시 처리와 기술 이동의 발각 경계. 적 AI의 마지막 목격 위치 수색·범위 공격 대응은 후속 범위다. 지형 사선·엄폐 시스템을 이번 변경으로 확정하지 않는다.

**공통 은신:** 적의 시야 밖에서 2 AP와 현재 이동력 2를 지불한다. 자원이 남으면 계속 행동한다. 은신 캐릭터나 적의 일반·강제 이동 각 1칸 완료 및 적 Facing 변경 후 발각을 검사하고 시야에 닿으면 즉시 해제한다. 피해를 받아도 즉시 해제한다. 은신 진입 이외의 AP 소비 행동은 조건 판정·효과 처리를 마친 뒤 해제하여 암습 등 은신 조건 행동을 끝까지 처리한다. 이동력 -1은 테스트값으로 턴 시작 지급량에만 적용하며 턴 도중 진입 시 상태 페널티로 현재 이동력을 추가 차감하지 않는다.

**암습:** 은신과 배후 조건에서 2 AP로 자기 턴당 한 번 사용한다. 기본 공격 피해 계산에 추가 공격력 +2를 적용하고 도적의 배후 강제 치명타·치명타 추가 피해와 대상 물리방어를 정상 적용한다. 기존 1.5배 피해·물리방어 무시는 사용하지 않으며 공격·효과 완료 뒤 은신을 해제한다. 추가 공격력 +2는 현재 검증용 수치다.

**기능 확인:** 사용 조건·자기 턴당 횟수·비용·피해·발각 판정이 일관되게 적용된다. 후면 확정 치명타와 암습의 피해를 근거 없이 중복 계산하지 않는다.

**재미 질문:** 배후를 잡는 과정에 경로·타이밍·위험의 판단이 있는가? 도적의 접근과 상대의 대응을 플레이어가 이해할 수 있는가?

**첫 핵심 검증 지점:** C1~C3의 전사·도적·궁수 Lv1 전투에서 공격과 이동, AP 사용과 이월, 배후 접근, 직접 공격과 경계사격, 우선 제거 대상과 보호 대상의 선택을 확인한다. 선택이 반복적이거나 결과가 불명확하면 현재 규칙·수치·배치·정보 표시를 조정하고 재검증한 뒤 전문화와 장비를 확대한다.

궁수 Lv1의 긴 사거리는 기본 수치·공격 특성이며 패시브는 전투 후 특수화살 1개 제작이다. 제작 대상 종료 결과와 화살의 사용·소비·보유·저장 계약은 미정이다. 전투 사이의 제작 연결을 보류한 단독 전투 검증은 해당 패시브 구현 완료로 기록하지 않으며, 기존 재시작·결과 처리가 제작을 이미 지원한다고 간주하지 않는다.

### C4. 대표 Lv2 전문화 비교

**현재 진행:** 개척자·암살자·정령궁수의 주요 Lv2 기능과 이를 지원하는 공통 스킬·쿨타임·스킬바·환경효과·타격 이벤트·투사체를 구현했다. 개별 기능과 최근 투사체 연결에 대한 사용자 정상 동작 확인을 받았다. 현재는 전문화별 전술 차이를 비교할 단계이며 상태이상·Lv5 및 전문화 전체 완료로 기록하지 않는다.

**선행:** C1~C3의 기본 전투 평가. 어떤 선택이 부족한지 확인한 뒤 첫 후보를 정한다.

**구현 범위**

- 경험치 지급이나 레벨업 UI 없이 테스트 설정에서 전문화와 획득 능력을 직접 지정한다.
- 우선 한 갈래의 필요한 능력을 연결하고 비교할 두 번째 갈래를 추가한다.
- 같은 전투에서 편성·배치·난수 조건을 유지하고 전문화 구성을 바꾸어 행동의 차이를 확인한다.
- 기술의 사용 조건·대상·비용·완료·취소·상태 지속·자기 턴당 횟수는 선택한 기능에 필요한 범위부터 구현한다.
- 모든 기술을 표현하는 범용 효과 엔진이나 전체 전문화 완성을 선행 조건으로 삼지 않는다.

**후보 선정 기준**

- 은신 접근과 정면 교전의 차이를 확인하려면 같은 도적의 **암살자와 불한당**을 비교할 수 있다. 암살자를 선택하면 이 단계에서 투명화와 해당 기술 이동의 상세 규칙을 정하고 구현한다.
- 위치 조작이 부족하다면 **개척자의 끌어오기 또는 끌려가기 한 기술**부터 시험할 수 있다. 기술 이동에는 기회공격·경계사격이 발동하지 않는 확정 규칙을 따르고 착지·점유·실패 처리를 먼저 정한다.
- 수호자를 검증하면 Lv2 방향별 물리 피해 차단과 Lv5 정면·좌우 앞쪽 3방향 확장을 구분한다. 기존 후면의 측면 판정과 인접 은신 탐지 패시브는 사용하지 않으며 도적의 배후 판정·AI도 현재 규칙을 따른다. 도둑의 Lv2 비열한 행동 후보는 모래뿌리기(실명)·급소공격(약화)·발걸기(넘어짐)다.
- 신규 기사와 기어스는 확정 콘텐츠로 관리하되 이 추가만으로 C1~C3의 최초 검증 편성을 확대하지 않는다. 기사를 검증할 때 강타 AP·쿨타임·강제 이동 면역과 맹세 위반·특성 몰수의 필요한 데이터·판정 경계를 먼저 설계한다.
- 궁수의 사냥꾼은 정령궁수 계열로 교체한다. 한 기본 공격에 물·불·전기·독 피해 각각 1과 속성별 방어, 치명타 무속성 +2 한 번을 연결했다. Lv2 정령 선택의 다음 기본 공격 특수 효과는 이 네 성분에 추가된다. 한 공격을 네 번의 공격으로 계산하지 않는다.
- 정령궁수의 경로 효과를 위해 환경효과를 전투 기획 범위에 포함한다. 각 Hex의 독립적인 지면·공기 슬롯, 각 슬롯의 단일 상태, 다섯 확정 조합과 기본 덮어쓰기, 같은 슬롯 반응 우선·연쇄 처리를 구현했으며 정령 공격에서 재사용한다. 이는 과거 타일 원소효과 제외를 현재 기획 범위에 그대로 적용하지 않는다는 뜻이며, C1~C3보다 먼저 구현하거나 모든 원소 상호작용을 완성해야 한다는 뜻은 아니다.
- 불한당은 구현 의존성이 상대적으로 적다는 이유만으로 첫 후보에 고정하지 않는다. 현재 전투에서 부족한 선택을 늘리는지를 우선한다.

**착수 전 결정:** 검증할 전문화 또는 개별 기술, 비용·수치·지속·이동·사용 제한·실패 규칙과 비교 조건. 일부 보상만 구현하면 해당 기술 검증으로 기록하고 Lv2 전문화 전체의 완료로 취급하지 않는다.

정령궁수는 불·전기 추가 피해 기본값 1과 같은 대상·속성 합산 후 방어 1회 규칙을 유지한다. 투사체는 실제 이동 구간이 통과한 헥스에 환경을 생성하고, 환경 생성 피해는 즉시 처리한다. 전기 추가 공격 대상은 통과 시 중복 없이 수집하고 도착 시 배치 확정한다. 주대상의 전기 추가 피해는 기본 피해와 합산한다. 쿨타임은 구현했으며 상태이상·환경 지속·추가 전파·Lv5는 별도 설계 범위다. Lv5의 피해 무효화·재충전·범위 사격은 이번 완료 범위가 아니다.

**기능 확인:** 설정한 능력만 참가자에게 적용되고 서로의 상태를 공유하지 않는다. 같은 직업도 다른 전문화 구성을 사용할 수 있으며 매 시도에 상태·횟수를 올바르게 초기화한다. 환경효과를 포함하면 지면·공기가 동시에 존재해도 각 슬롯의 상태는 하나이고, 지정 조합을 양쪽 순서로 적용해 같은 결과가 나오는지 확인한다. 미정 조합을 임의 연쇄시키거나 반대 슬롯을 근거 없이 초기화하지 않는다.

**재미 질문:** 전문화가 이동 위치·공격 대상·AP 사용법을 실제로 바꾸는가? 개인의 운용 변화가 파티 조합과 아군의 행동에도 영향을 주는가?

### C5. 장비 조합 검증

**선행:** 기본 전투의 평가와 해당 효과가 요구하는 기술·상태 처리.

**구현 범위와 내부 순서**

1. 전투 전 테스트 설정에서 용병당 최대 3개를 직접 장착한다. 부위 슬롯 없이 동일 장비 중복을 허용하고 전투 중 구성을 바꾸지 않는다.
2. 계산 계약이 정해진 일반 장비의 단순 수치 효과부터 연결한다.
3. 망치의 공격 후 방어 파괴를 연결하여 후속 공격과 파티 연계의 차이를 확인한다.
4. 필요가 확인된 강화형의 처형·반격·피해 차단·재충전을 선택하여 확장한다. 강화형을 직접 설정하여 시험하며 상점·획득·강화 이벤트를 구현할 필요는 없다.

일반 장비라도 망치는 공격 후 처리 순서가 필요하고 갑옷은 최대 HP와 현재 HP의 관계가 필요하다. 중복 장비는 테스트 입력과 전투 중 상태에서 구별할 수 있어야 하지만 원정 인벤토리·장비 저장 시스템 전체를 먼저 만들지는 않는다.

**착수 전 결정:** 실제 투입할 장비의 수치 적용 범위·중첩·HP 처리·공격 종류별 적용. 복합 효과는 도입할 때 방어 파괴 유지·하한, 0 피해, 처형·처치, 반격 연쇄, 중복 차단 소모와 충전 시점을 정한다.

**유지할 확정 규칙:** 망치는 이번 공격의 피해 계산 후 방어력을 파괴한다. 복수는 장비마다 개별 발동하며 한 번의 큰 피해로 합치지 않는다. 촛농 갑옷의 재충전은 전체 라운드가 아닌 착용자의 자기 턴 5턴을 기준으로 한다. 자비의 처형 기준은 장착 1/2/3개에 3/4/5이며 이를 다른 장비의 공통 중첩 규칙으로 확대하지 않는다.

**기능 확인:** 장비가 직업의 기본 공격 방식·무기 표현을 바꾸지 않는다. 동일 장비의 개별 상태가 섞이지 않고 수치 재계산이 임의 회복·소생·일회 지급을 만들지 않는다. 각 효과의 적용 순서·횟수가 확정 계약을 따른다.

**재미 질문:** 같은 장비 집중과 혼합 장착 사이에 선택이 있는가? 장비가 전문화의 운용을 바꾸는가? 특정 조합이 모든 상황에서 우세하지 않은가?

### C6. 다양한 전투 구성과 조정

**선행:** C1~C5에서 실제로 구현·평가한 기능. 소수의 전투 구성은 앞 단계부터 사용하고 이 단계에서 비교 폭을 넓힌다.

**구현 범위**

- 근접 위주, 원거리 압박, 우회 가능한 초기 배치, 높은 방어력 등 기존 규칙으로 만들 수 있는 소수의 서로 다른 전투 구성을 비교한다.
- 추가한 기능에 필요한 최소 AI·표시·피드백·전투 템포를 보완한다. AI와 사용 정보의 첫 구현을 이 단계까지 미루지 않는다.
- 같은 설정의 반복 비교 뒤 다른 배치·편성·난수 조건에서도 결과를 확인한다.
- 재미가 확인된 전술을 기준으로 다음 전문화·장비·Lv3~5 콘텐츠의 우선순위를 정한다. 모든 직업·레벨을 자동으로 다음 제작 범위에 넣지 않는다.

**착수 전 결정:** 비교할 전투 구성, 이번에 바꿀 수치·행동·표시와 판단할 질문. 최종 플레이타임이나 밸런스 목표값을 근거 없이 확정하지 않는다.

**기능 확인:** 사용한 기능의 전투 시작부터 종료·재시작까지 흐름이 안정적이고 표시·AI·논리 판정이 일치한다.

**재미 질문:** 상황마다 유효한 전술과 기존 기술의 가치가 달라지는가? 한 가지 행동·편성·장비만 반복하게 되지는 않는가? 패배 원인을 이해하고 다른 시도를 하고 싶은가?

## 5. 검증 방법과 다음 단계 진입 기준

기능 구현과 재미 확인은 별도로 기록한다. 규칙대로 동작하더라도 재미가 확인되지 않았으면 다음 콘텐츠 확대를 자동으로 진행하지 않는다.

기본 비교 흐름은 다음과 같다.

`동일 전투의 Lv1 구성 → Lv2 전문화 구성 → 장비를 추가한 구성`

각 비교에서 전투 편성·배치·난수 조건 등 공통 조건을 유지하고 확인하려는 요소를 바꾼다. 테스트용 레벨·시작 HP·능력 지정은 실제 원정의 초기화·경험치·성장 지급 규칙을 확정하는 결정이 아니다.

플레이 후에는 다음 내용을 남긴다.

- 사용한 전투 설정·능력·장비와 변경한 요소.
- 실제로 고민한 선택과 선택하지 않은 대안.
- 결과를 예상할 수 있었는지, 이해되지 않은 피해·발각·반응이 있었는지.
- 반복된 행동, 일방적으로 유리한 조합, 대기·연출 등 흐름을 끊은 지점.
- 다음 시도에서 바꿀 항목과 확인할 질문.

C3 이후에는 Lv1 전술의 선택을, C4 이후에는 전문화 차이를, C5 이후에는 장비 조합의 선택을 평가한다. 문제가 있으면 해당 범위의 수치·배치·정보 전달·규칙을 검토한다. 승인된 게임 규칙을 실질적으로 바꾸는 경우에는 변경 설계를 먼저 제시한다.

현재까지 맵 배치 도구의 정적 점검·데이터 단위 테스트·Fog 및 확대의 MCP 실행 검증·사용자 편집·저장·재로드 확인을 수행했다. 이후 전투 연결·승패·결과·재시작·지면 범위 표시와 Trait 연결을 구현하고 관련 정적 점검·리뷰를 마쳤다. 사용자는 시작점 부족 시 아군 3명 배치, 컴파일, 승패·결과·각 재시작 흐름, 지면 범위 표시와 안내한 Trait 검증의 정상 동작을 보고했다. Trait 관련 자동 테스트의 실행 목록·통과 건수·결과 파일은 별도로 제공되지 않았으므로 사용자 확인과 에이전트의 정적 검토를 구분해 기록한다. 에이전트가 해당 자동 테스트나 Play 검증을 실행한 것은 아니다. 동시 전멸·오류 경로 전체 또는 C1의 재미 평가까지 완료된 것으로 확대하지 않는다. 컴파일을 유발하는 테스트를 포함한 실행 제한은 AGENTS.md를 따른다.

## 6. 공통 책임과 수명

- **정적 정의:** 직업·능력·장비의 공통 설정을 소유한다. 개별 HP·사용 횟수·충전 상태를 저장하지 않는다.
- **특성 보유:** 불변 Trait의 종류와 출처를 보존하고 TraitCollection으로 필요한 종류를 조회한다. 전투 준비 때 정적 정의에서 복사하며, 실행 순서는 TraitTiming이나 목록 순서가 아닌 전투 처리 코드가 결정한다.
- **테스트 편성:** 전투 시작 조건과 비교할 구성을 전달한다. 원정 파티·인벤토리의 별도 운영 시스템으로 확대하지 않는다.
- **전투 상태:** 참가자별 HP·AP·이동력·좌표·방향을 관리한다. 향후 사용 기록·충전 등 효과 상태는 불변 특성 보유 정보와 분리하며 해당 효과를 구현할 때 추가한다.
- **전투 결과:** 전투 자체의 종료 결과를 한 번 확정한다. 현재는 원정 경험치·보상·이벤트 결과를 적용하지 않는다.
- **Unity 표시:** 입력·연출·UI와 Unity 객체의 생성·정리를 담당한다. 기존 논리 step 발행·완료 계약과 메인 스레드 제약을 유지한다.

전투가 설정을 받아 시작하고 결과를 내보내는 경계를 유지하되, 미래 통합을 위한 범용 계층을 미리 완성하지 않는다. 기존 순수 전투 로직을 불필요하게 교체하지 않는다.

테스트 재시작은 별도의 새 시도다. 재시작 때 상태를 초기화하는 것과 실제 원정에서 전투 간 HP·효과를 어떻게 유지하는지는 다른 계약이다. 원정 HP 유지 규칙이나 방어 파괴의 미정 유지 기간을 테스트 초기화로 변경하지 않는다.

정령 부여의 다음 기본 공격 준비, 물리 피해 차단 충전·자기 턴 카운트, 사용 턴의 무속성 범위 사격과 Hex의 환경 슬롯은 개별 전투 상태로 설계한다. 공통 Trait·직업·아이템 정의에 가변 상태를 기록하지 않는다. 궁수의 전투 후 특수화살 제작은 종료 결과와 이후 보유 상태를 연결할 별도 계약이며, 전투 재시작이나 결과 화면 재진입을 제작 계기로 자동 확장하지 않는다. 구체 소유자·필드·저장 및 수명은 해당 기능 설계에서 정한다.

- 범위·경로: 마우스 기준선에 가까운 이동·끌기 경로와 이동 예정 경로 표시를 연결했다. 끌기 사거리는 2~6칸이다. 후방 도약·끌기 2종·암습 선택 시 유효 사거리와 해당 스킬의 연막 판정으로 지면 헥스 선을 표시한다. 선택 중 이동선·기본 공격 대상 마커를 비우고 기존 경로·착지 미리보기는 유지한다. 취소하면 기본 표시로 복귀한다. 경계사격 부채꼴, 자기 대상·옵션 선택은 기존 방식을 유지한다.
- 환경 피해: 불 지면은 불, 전기 지면·전기 구름은 전기, 독 지면·독구름은 독 피해 1을 환경 생성·자기 턴 시작·해당 칸 진입 시 처리한다. 물 지면은 자체 피해가 없다. 연막은 사거리 2 이상 스킬의 연막 칸 자체 및 그 너머 타겟팅을 차단한다. 화상·실명 등 유닛 상태이상은 포함하지 않았다.
- 애니메이션 툴·데이터: 전용 AnimationEventTool 씬에서 캐릭터별 CharacterAnimationProfile의 키·클립·정수 프레임 이벤트를 편집·저장한다. 전사·도적 attack1은 30 FPS의 17프레임 Melee, 궁수는 같은 프레임 Projectile로 저장되어 있다. 세 프로필은 현재 같은 양손 공격 클립을 참조하며, 궁수 전용 사격 클립으로 교체한 상태는 아니다. 툴의 다중 이벤트 저장은 허용하되 전투용 attack1은 AttackHit 정확히 1개를 요구한다.
- 타격 이벤트: 재생 요청별 이벤트를 한 번 소비한다. 프레임 0과 한 업데이트에서 이벤트·클립 끝을 함께 통과하는 경우를 처리한다. 근접은 이벤트 시점에 피해를 적용하고, 투사체는 이벤트 시점에 발사해 도착 시 피해를 적용한다. 공격 종류 구분은 직접 타격/발사 용도이며 사거리·연막 규칙은 스킬 데이터가 결정한다.
- 투사체: 발사 당시 목표점으로 게임 시간 기준 직선·일정 속도 비행한다. HexCharacterView Inspector에 프리팹·발사점·오프셋·속도·목표 높이를 노출했고 미지정 외형은 작은 구체다. 물리 충돌·가로막기·추적 비행은 구현 범위가 아니다. 피해 처리와 애니메이션 종료가 모두 충족된 뒤 공격을 종결하며 일반·반응 공격에 같은 경로를 사용한다.
- 정령 비행 경로: 실제 이동 구간과 헥스의 교차를 검사해 중간 칸 누락을 막고 경계 접촉 칸도 포함한다. 원점은 제외하며 같은 칸의 중복 처리를 막는다. 환경 생성 피해는 통과 시 처리하고, 전기 공격 대상은 통과 시 수집해 도착 시 배치 확정한다. 같은 대상·속성 피해 합산 후 방어 1회 규칙을 유지한다.
- 중단·수명: 타격 전 재생 실패는 피해 없이 중단한다. 타격 후 재생 실패는 애니메이션 완료로 취급하고 남은 비행 처리를 유지한다. 피해 확정 전 공격자·주대상 제거, 투사체 소실, 전투 종료·재시작은 남은 공격을 정리한다. 이미 생성한 환경·피해와 소비한 AP·쿨타임·정령 준비는 되돌리지 않는다. 명시적인 공격 중단이 기존 반응·후방 도약·턴 정리 경로를 거친다.

**검증 및 사용자 확인**

- 사용자 확인: 기회공격·경계사격, 은신·암습, 개척자·암살자 주요 기술, 환경효과 등의 구현 후 정상 동작 확인을 받았다. 이번 타격 이벤트·실제 투사체 연결 후에도 사용자가 “잘 작동해”라고 확인했다. 이는 실제 전투에서의 동작 확인이며 모든 사망·재진입·재시작 조합의 수동 검증 완료를 뜻하지 않는다.
- 스킬바와 선택 스킬 사거리 확대는 각각 독립 정적 코드 리뷰 Pass를 받았다. 당시에는 컴파일·실행 검증을 하지 않았으며 이번 205개 테스트가 스킬바 화면·클릭 또는 범위 표시 전체를 검증한 것으로 기록하지 않는다. 쿨타임·스킬바의 모든 개별 조작에 대한 별도 사용자 확인도 확대 해석하지 않는다.
- 최근 통합 검증: Unity 에디터에서 스크립트·에셋 갱신 후 컴파일 오류 0건을 확인했다. 관련 EditMode 테스트 205/205 통과(실패·건너뜀 0), 독립 코드 리뷰와 후속 수정 부분 재검토 Pass. 전체 프로젝트 테스트 성공이나 PlayMode 자동 검증을 뜻하지 않는다.
- 실행 범위: 애니메이션 데이터·재생기 테스트, BattleProjectilePathTests, BattleSpiritImbuementTests, BattleSpiritImbuementRunnerTests, BattleRunnerReactionTests, BattleAttackTests. 근접 이벤트 전후 피해와 애니메이션 종료 대기, 투사체 생성·도착 전 무피해·도착 후 피해, 반응·콜백 재진입, 통과 셀·중복 방지·중단을 검증했다. 최종 Unity 테스트 job ID는 `e6114299262f4ca285a7837ebfbfa310`이다.
- 발견·수정: 발사 프레임 전체 deltaTime을 비행에 선반영하던 문제와 투사체 소실 시 공격이 종료되지 않는 문제를 수정했다. 기존 빈 이벤트 fixture와 종료 시 피해를 전제한 테스트를 새 계약에 맞췄다. EditMode에서 OnDisable 자동 호출이 보장되지 않는 테스트는 실제 호출 여부를 확인한 뒤 누락된 경우에만 호출하도록 보완했고 기존 assertions를 유지했다. PlayMode의 자동 생명주기 호출 자체를 검증한 것은 아니다.
