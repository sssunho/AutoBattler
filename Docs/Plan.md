# 판타지 탐험 로그라이크 — 기획 요약

개정일: 2026-11-07

세계관과 콘텐츠의 분위기는 `World_Premise.md`를 따른다. 본 문서는 게임의 목표, 원정 진행과 개발 범위를 정의한다.

2026-11-07 개정은 궁수의 전투 후 특수화살 제작, 정령궁수 전문화와 지면·공기 환경효과를 반영한다. 기존의 자유 이동·스토리라인·왕의 길잡이 획득 결말·시간 소진 후 최종 도전, Area·Entrance 및 노드별 잠재 이벤트 후보 규칙은 유지한다. 특별 장소의 영구 기록·해금은 최종 목표와 구분하며 새 종료 구조의 보존 정책은 후속 결정이 필요하다. 축복은 [BlessingSystem.md](BlessingSystem.md), 성장·장비·전투의 상세 규칙은 [MercenarySystem.md](MercenarySystem.md)와 [BattleSystem.md](BattleSystem.md)를 따른다. 아래 과거 전투 요약으로 최신 상세 명세를 덮어쓰지 않는다.

## 1. 게임 개요

Unity 기반 1인 개발 인디게임.

### 핵심 컨셉

**«아직 대부분이 알려지지 않은 판타지 세계에서, 전투와 파티 성장을 거쳐 전설의 보물 ‘왕의 길잡이’를 손에 넣는 탐험 로그라이크.»**

플레이어는 인류가 밝혀낸 세계의 중심부에 있는 대도시를 시작 Node로 삼고, 모험가 파티를 이끌고 원정을 떠난다. 중앙 도시는 전설의 보물 왕의 길잡이를 가져온 자에게 큰 상을 약속한다. 이미 밝혀진 장소들은 이 도시를 중심으로 방사형으로 펼쳐져 있으며, 플레이어는 전투하고 파티를 성장시키면서 새로운 장소로 나아간다.

최종 목표 장소는 하나다. 플레이어는 자유롭게 중간 장소와 경로를 선택하고, 정해진 목표 Node의 최종 난관을 넘어 길잡이를 실제로 획득한다. 목표에 도착하거나 보물을 목격하는 것만으로 성공하지 않는다. 보물을 손에 쥐는 순간 이번 모험을 끝내며, 이후의 귀환·납품·포상 수령을 필수 플레이로 요구하지 않는다.

자유로운 장소 이동 위에 사전에 설계한 고정 스토리라인을 제공한다. 콘텐츠 목표는 최소 3개이며, 각 이야기 때문에 플레이어를 서로 분리된 일방통행 루트에 고정하지 않는다. 스토리라인의 내용·진행 순서·상호 관계·완주 조건은 별도 설계하며, 최소 3개라는 목표를 즉시 구현 범위로 해석하지 않는다.

시간제한은 최종 도전까지 탐험하고 성장할 준비 기간이다. 제한 전에는 언제든 목표 Node로 이동해 도전할 수 있으며, 조기 도전은 별도 보상·점수·이득 없이 플레이어가 선택하는 챌린지로 둔다. 시간이 소진되면 현재 방문의 사건·전투·보상 및 결과 처리를 마치고 최종 도전으로 강제 전환한다. 특별 장소의 발견과 영구 이득은 여정의 별도 성과이며, 그 발견을 최종 목표 달성으로 대신하지 않는다.

짧은 런을 여러 번 반복하는 방향은 유지하되, 기존안의 60~90분·최대 약 2시간과 새로운 목표 플레이타임은 재검토 대상이다. 실제 플레이타임과 게임 안의 준비 기간은 구분한다. 봄에서 겨울로 이어지는 원정의 테마와 흰밀물의 세계관은 유지하지만, 시간 소진 후 최종 도전으로 이어지는 구체적인 서사적 연결은 미정이다. Edge를 따라 Node 사이를 이동할 때 해당 `Edge.weight`만큼 시간을 소모하며, 0도 허용한다. Entrance 전환 자체의 시간 비용은 0이다. 총 시간량과 경로별 weight의 산정 방식은 추후 정한다.

## 2. 핵심 디자인 원칙

새로운 요소는 다음 기준으로 평가한다.

1. **호기심과 발견:** «저 너머에는 무엇이 있을까?»라는 감정을 만들고, 직접 도달했을 때 그 기대에 답하는가?
2. **경로와 도전 시점의 선택:** 어떤 장소를 들르고 언제 최종 목표에 도전할지, 새로운 정보에 따라 계획을 바꿀 여지가 있는가?
3. **유한한 원정과 자유로운 탐험:** 의미 있는 우회와 재방문을 허용하면서도 한 런에 세계 전체를 소진하지 않게 하는가?
4. **의미 있는 비용:** 회복만을 위한 반복 왕복이 최선의 절차가 되지 않으면서, 돌아가야 할 새로운 목적이 있는 재방문은 살리는가?
5. **전투·성장과 모험의 연결:** 전투·영입·성장이 새 장소로 나아가는 과정과 마지막 도전에서 체감되며, 이야기 흐름과 연결되는가?
6. **완결성과 제작 가능성:** 짧은 원정 안에 발견과 선택의 결말이 남고, Unity 기반 1인 개발로 현실적인가?

핵심 의사결정은 «어디로 가고, 무엇을 알아보고, 어떤 준비를 하며, 이번에는 무엇을 남겨둘 것인가?»다. 영입과 성장도 이 여정 안에서 의미를 가진다.

세계는 끊임없이 도망쳐야 하는 재난 현장이 아니다. 위험한 장소뿐 아니라 평범한 생활, 따뜻하거나 우스운 사건과 아름다운 풍경을 함께 제공한다.

흰밀물은 탐험 기간을 제한하는 세계의 주기이며, 최종 적이나 모든 신비의 원인이 아니다. 시간 소진 후 최종 도전이 가능해지는 이유는 별도 설계하며, 이 규칙만으로 흰밀물의 작동 원리를 바꾸지 않는다.

## 3. 전투

다음 목록은 아직 전면 개정하지 않은 과거 전투안이다. 현재 적용할 전투·직업·은신 규칙은 [BattleSystem.md](BattleSystem.md)를 기준으로 하며, 아래 목록을 최신 확정 규칙과 혼용하지 않는다.

- 3D 실시간 오토배틀
- 6각형 그리드 전장
- 최대 5인 파티
- 자동 이동 및 타겟 선택
- 기본 공격
- 공격 등을 통한 마나 획득
- 마나 충족 시 액티브 스킬 자동 발동
- 기본 전투시간 약 30초
- 필요하면 약 15초의 피버타임 적용

위 과거안의 전투 방식과 제외 사항은 현재 헥스 턴제 전투 명세를 대체하지 않는다.

전투는 이벤트가 발생시키는 결과 중 하나다. 선택지가 있는 이벤트의 선택 결과로 전투가 시작될 수도 있고, 선택지가 없는 일방적인 이벤트에서 즉시 전투가 시작될 수도 있다.

전투에서 승리하면 이벤트의 후속 결과를 적용한다. 최종 전투를 포함하여 승리 자체를 원정 성공으로 처리하지 않으며, 왕의 길잡이를 획득하는 결과까지 완료해야 성공한다. 전투에 패배하면 기존 규칙대로 런이 종료되며, 패배한 이벤트의 후속 효과를 적용하지 않는다. 최종 도전의 별도 실패·복귀 정책과 신규 발견 기록·해금 보존 여부는 후속 설계 대상이다.

## 4. 성장 체계

모험가는 레벨 시스템으로 성장한다. 직업별로 각 레벨에 받는 보상 구성을 정하고, 고정 능력의 획득과 플레이어의 선택을 함께 배치한다. 성장의 중심은 새로운 스킬과 특성을 통해 전투에서 할 수 있는 일과 운용 방식을 늘리는 것이다.

성장 요소는 다음 역할을 가진다.

- 레벨 성장: 직업별 레벨 보상과 공용 특성으로 개별 모험가의 능력과 전투 방식을 발전시킨다.
- 아이템: 장착을 통해 모험가의 능력이나 전투 메커니즘을 강화한다.
- 축복: 한 원정 동안 파티 전체에 신별로 고정된 효과를 제공하고, 같은 신의 축복을 다시 받으면 티어가 상승한다.
- 특별 장소의 영구 이득: 한정된 특별 장소의 발견 성과를 보존하면 이후 모든 원정에 적용할 효과를 해금한다. 원정마다 초기화하는 축복과 구분한다.

레벨과 경험치는 파티가 공유하며 전문화·성장 선택·장착 장비는 용병별로 구분한다. 미장착 장비는 파티가 공용으로 보관한다. 프로토타입 시작 레벨은 1, 최대 레벨은 5다. 전투 승리마다 파티 경험치 1을 얻고 최대 레벨 미만에서 다음 레벨에 필요한 경험치는 현재 레벨 L이다. 용병·공유 성장·장착 및 보관 장비는 원정 수명이다. 성장과 장비의 상세 규칙은 [MercenarySystem.md](MercenarySystem.md), 축복은 [BlessingSystem.md](BlessingSystem.md)를 따른다. 확정된 장비 콘텐츠와 미정인 계산·상호작용을 구분하며 문서화는 구현 완료를 의미하지 않는다.

특정 성장 수준에 도달하거나 특정 파티 구성을 완성하는 것은 원정 성공의 공통 필수 조건이 아니다. 성장은 목표까지 가는 여정의 일부이며, 얼마나 성장할지는 경로와 선택에 따라 달라질 수 있다.

### 레벨별 보상의 기본 구조

직업별 레벨 보상표는 각 레벨에 제공할 보상의 종류와 구성을 정한다. 보상은 다음 세 가지로 구분한다.

| 보상 구분 | 획득 방식 | 역할 |
| --- | --- | --- |
| 직업별 고정 보상 | 해당 직업의 지정 레벨에 정해진 능력이나 스킬을 획득한다. | 직업의 핵심 능력과 성장 흐름을 보장한다. |
| 직업 내 선택 보상 | 해당 직업의 레벨 보상에 지정된 후보군에서 플레이어가 선택한다. | 같은 직업 안에서 사용할 기술과 운용을 달리한다. |
| 공용 특성 | 특성 선택 보상이 주어질 때 직업 공통 목록에서 플레이어가 하나를 선택한다. | 직업을 가로질러 개별 모험가의 전투 방식을 구성한다. |

- 한 레벨에 고정 보상과 선택 보상을 함께 배치할 수 있으며, 여러 보상을 함께 받을 수도 있다.
- 어떤 레벨에 어떤 종류의 보상을 몇 개 제공할지는 직업별 레벨 보상표에 명시한다. 모든 레벨에 공용 특성을 하나씩 제공한다는 뜻은 아니다.
- 레벨마다 능력치를 일괄 상승시키는 것을 기본 성장 규칙으로 삼지 않는다. 특정 레벨의 보상으로 이동력 증가처럼 직업의 운용에 필요한 능력치 변화를 명시할 수 있다.
- 직업의 고정 능력과 플레이어가 선택하는 공용 특성을 구분한다. 직업 능력이 지속 효과라는 이유만으로 공용 특성 목록에 포함되는 것은 아니다.

직업별 핵심 능력의 획득 시점을 정해 레벨별 전투 능력을 비교할 수 있게 하고, 직업 내 선택과 공용 특성으로 같은 직업의 운용에 차이를 만든다.

### 공용 특성

공용 특성은 기본적으로 모든 직업이 선택할 수 있다. 특정 직업 전용 목록을 기본 구조로 사용하지 않으며, 일부 특성에는 선택하기 위한 조건을 둘 수 있다. 개별 특성의 조건과 효과는 콘텐츠를 설계할 때 정한다.

이 문서의 공용 특성은 개별 모험가가 획득하는 성장 보상이다. [EventSystem.md](EventSystem.md)의 `Trait`과 `Data/Traits.csv`는 파티의 서사적 성향을 나타내는 태그이므로, 두 개념을 같은 데이터로 취급하지 않는다.

### 레벨별 성장과 직업·전문화

Lv2에서 용병별 전문화를 선택하고 그 보상을 받으며, Lv3에서는 공용 특성을 선택한다. Lv4는 직업 스킬, Lv5는 Lv2에서 선택한 전문화의 강화 보상을 받는 단계다. Lv4 직업 스킬의 실제 내용과 고정 지급·후보 선택 방식은 미정이다.

암살자는 투명화 접근·배후 공격·처치 후 투명화, 도둑은 은신 발각 범위 보정·주의 돌리기·선택 방해 기술·무기 탈취, 불한당은 상태이상 대상 추가 피해·약화·AP 회복·연속 공격으로 전문화한다. Lv2·Lv5의 확정 효과와 보상 구성은 [MercenarySystem.md](MercenarySystem.md)를 따른다. 암살자 Lv5의 처치 후 투명화 패시브는 유지하지만, 방어력을 무시하면서 투명화를 유지하던 액티브 안은 철회되었으며 대체 기술은 미정이다. 도둑의 Lv2는 고정 패시브와 고정 액티브에 더해 모래뿌리기(실명)·급소공격(약화)·발걸기(넘어짐) 중 비열한 행동 하나를 선택한다. 상태효과의 세부 수치·지속·비용은 미정이며 이 선택 구조를 다른 전문화의 공통 규칙으로 확대하지 않는다.

직업의 Lv1 능력은 전사의 기회공격, 도적의 암습과 궁수의 경계사격을 포함한다. 전사 전문화 수호자는 Lv2에서 방향별 물리 피해 차단을 얻으며 정면 50%·측면 10%·후면 0%를 테스트 기준으로 사용한다. 차단 성공 시 해당 물리 피해는 0이고 실패 시 정상 물리방어를 적용한다. Lv5에는 정면과 좌우 앞쪽 총 3방향을 정면으로 판정한다. 기존 후면의 측면 판정·인접 은신 탐지 효과는 이 개편으로 교체한다. 일반 방패의 물리방어 +1은 별도 효과다.

모든 유닛은 우선권을 가지며 라운드 턴 순서는 높은 값부터 구성하고, 동률만 라운드 시작에 무작위로 정해 그 라운드 동안 유지한다. 기회공격과 경계사격은 각 1칸 일반 이동의 선언 직후 현재 위치에서 반응을 검사하고, 발동하면 그 이동과 남은 경로를 취소하며 취소한 step의 이동력을 소모하지 않는다. 강제 이동·기술 이동에는 반응하지 않는다. 여러 반응은 모두 예약해 우선권과 해당 라운드 동률 순서로 처리하고, 대상 사망으로 실행하지 못한 반응은 횟수·준비를 소비하지 않는다.

기회공격은 인접한 적의 인접 이탈에 AP 없이 발동하며 보유자·대상별로 라운드당 한 번이다. 경계사격은 2 AP로 감시 방향을 선택하고 실제 방향을 바꾼 뒤 턴을 종료한다. 경계선을 포함한 전방 120°와 기본 공격 사거리 안의 현재 위치에서 일반 이동을 선언한 적에게 기본 공격 1회를 수행한다. 한 번 발동하거나 다음 자기 턴이 시작되면 종료하고 외부 강제 이동·방향 변경에도 즉시 종료한다. 실제 반응 공격은 대상을 향해 방향을 바꾼다. 자세한 처리 순서는 [BattleSystem.md](BattleSystem.md)를 따른다.

은신은 모든 직업의 공통 기술로, 적의 시야 밖에서 2 AP와 현재 이동력 2를 지불한다. 남은 자원으로 계속 행동할 수 있으며 턴 시작 이동력에는 테스트 페널티 -1을 적용한다. 일반·강제 이동의 각 1칸 완료와 적 방향 변경 후 발각을 검사하고, 적 시야에 닿거나 피해를 받으면 즉시 해제한다. 은신 진입 이외의 AP 소비 행동은 조건 판정과 효과 처리가 끝난 뒤 해제한다. 암습은 은신·배후 조건에서 2 AP로 자기 턴당 한 번 사용하며 기본 공격 계산에 테스트 추가 공격력 +2, 도적 배후 강제 치명타와 정상 물리방어를 적용한다. 투명화는 은신 조건을 만족하며 적 시야와 이동력 -1 페널티를 무시하고 나머지 규칙은 일반 은신과 같다. 시야 거리·차폐 등 남은 계약은 상세 문서를 따른다.

기사는 데스메리온에게 맹세하여 힘을 얻는 신규 기본 직업이며 양손 무기를 사용한다. Lv1에는 강제 이동 면역과 강타(가칭)를 얻는다. 강타의 기본 쿨타임은 3턴이며 기본 AP 비용을 지불한 뒤 남은 모든 AP를 추가로 소모해 피해를 높인다. Lv2에서는 기어스와 대응 특성이 일대일로 연결된 다음 쌍 중 하나를 선택한다.

| 기어스 | 지킬 제약 | 대응 특성 |
| --- | --- | --- |
| 불살의 맹세 | 플레이어가 능동적으로 선택해 적을 직접 죽이지 않는다. 반격 처치는 허용하지만 선택한 공격에 딸린 처형은 위반이다. | 강타 피해 2배 |
| 감시의 맹세 | 특정 방향을 등지지 않는다. 방향 지정·판정 시점은 미정이다. | 강타가 자신을 중심으로 사방 2칸 안의 모든 적을 타격 |
| 검소의 맹세 | 장비를 최대 2개까지만 착용한다. | 강타 쿨타임 1턴, 자기 차례마다 한 번 사용 |
| 퇴마의 맹세 | 마법사와 팀을 이루지 않으며 전투에 마법사가 있으면 먼저 공격한다. 정확한 충족 조건은 미정이다. | 강타 적중 대상에게 침묵 부여 |

기어스를 위반하면 대응 특성을 영구 몰수하며 기사의 기본 Lv1 능력은 유지한다. 강타의 기본 AP 비용·추가 AP당 피해량·정확한 공식·쿨타임 갱신, 침묵 세부와 맹세 위반의 구체 판정·저장 및 영구 몰수의 런 간 범위는 후속 결정이다. 기사 추가는 기존 코드의 직업 enum·수치·보상 데이터 구현 완료를 뜻하지 않는다.

### 궁수와 정령궁수

궁수의 Lv1 기본 패시브는 전투 종료 후 전투에서 사용할 특수화살 1개를 제작하는 전투 외 준비 능력이다. 긴 기본 공격 사거리는 직업의 기본 수치·공격 특성으로 유지한다. 제작이 발생하는 종료 결과, 화살의 종류·효과·사용·소비·보유 한도·중복·저장 구조는 미정이다.

궁수 전문화 사냥꾼은 정령궁수 계열로 교체한다. 정식 명칭은 추후 조정할 수 있으며 고정 보상은 다음과 같다.

| 레벨·보상 | 확정 효과 |
| --- | --- |
| Lv2 패시브 | 기본 공격의 기존 물리 피해를 제거하고 물·불·전기·독 피해를 각각 1씩 가한다. 한 공격의 네 피해 성분에 해당 속성 방어력을 개별 적용하고, 치명타는 무속성 추가 피해 +2를 한 번만 더한다. |
| Lv2 액티브 | 네 정령 중 하나를 골라 다음 기본 공격 1회에 특수 효과를 추가한다. 불은 경로에 불붙은 지면·연막과 최종 대상에 추가 화염 피해·화상, 물은 경로에 젖은 지면과 대상에 젖음, 전기는 경로상의 모든 적에게 전기 피해와 최종 대상에 감전, 독은 경로에 독 지면과 대상에 독을 부여한다. 4속성 기본 피해도 함께 적용한다. |
| Lv5 패시브 | 처음 받는 물리 피해 1회를 완전히 무효화하고 소모되며, 이후 자신의 턴 3회마다 재충전한다. 물·불·전기·독·무속성 피해에는 적용하지 않는다. |
| Lv5 액티브 | 사용한 턴의 모든 기본 공격을 무속성 피해로 바꾸고 매 공격이 착탄 지점 중심 범위 1의 모든 적을 타격한다. Lv2 정령의 경로·상태이상 등 특수 효과는 유지한다. |

범위 1은 착탄 Hex와 인접 Hex를 뜻하는 방향으로 사용하며 아군 피해·장애물·지형 효과 범위는 별도 설계한다. 여러 피해 성분의 무속성 전환·피격 효과 단위, 정령 추가 피해량·상태이상·경로, 액티브 비용과 충전 시점 등 미정 사항은 상세 문서를 따른다. 특수화살 제작과 정령 부여를 같은 아이템이나 소비 규칙으로 확정하지 않는다.

정령궁수의 경로 효과를 위해 환경효과를 전투 기획 범위에 포함한다. 각 Hex에는 서로 독립적인 지면 슬롯 1개와 공기 슬롯 1개가 있으며 각 슬롯은 동시에 상태 하나만 보유한다. 지정된 조합은 적용 순서와 관계없이 같은 반응을 내고, 그 밖에는 새 효과가 대상 슬롯을 덮어쓰며 반대 슬롯은 유지한다. 반응이 반대 슬롯의 결과도 지정하면 해당 상태로 교체한다. 전기가 흐르는 지면·전기 구름을 후보에 포함하며, 다섯 확정 조합과 연쇄 반응 등 미정 규칙은 [BattleSystem.md](BattleSystem.md)를 따른다.

### 예시: 공용 특성 목록 — 미확정

다음은 특성의 방향을 설명하는 예시이며 실제 특성 목록, 효과와 수치는 아직 확정하지 않았다. 도적의 전용 특성 목록이 아니다.

| 특성 이름 예시 | 효과 예시 |
| --- | --- |
| 치명적인 마법 | 마법에 치명타가 발생할 수 있다. |
| 치명적인 치명타 | 치명타 대미지가 증가한다. |

현재 [BattleSystem.md](BattleSystem.md)는 모든 속성의 공격에 치명타를 허용한다. ‘치명적인 마법’을 실제로 채택하려면 마법 공격의 기본 치명타 가능 여부와 특성이 추가하는 효과를 함께 정해야 한다. 이 예시 자체가 기존 치명타 규칙을 변경하지는 않는다. 치명타 조건이 겹칠 때의 처리와 대미지 증가량도 예시만으로 확정하지 않는다. 과거 ‘불량배’ 공용 특성 예시는 이번 도적의 불한당 전문화와 구분하기 위해 현재 예시에서 제외한다. 불한당의 추가 피해를 강제 치명타 효과로 바꾸거나 별도 네 번째 도적 전문화를 추가하지 않는다.

### 레벨 성장의 미정 사항

- 실제 콘텐츠에서의 레벨업 빈도와 시작 경험치·초과 경험치·최대 레벨 이후 처리
- 아직 정하지 않은 직업·전문화의 보상, Lv4 직업 스킬의 지급 방식, 공용 특성의 목록·효과·선행조건
- 암살자 Lv5 대체 액티브, 직업·전문화의 비용·수치·범위·상태효과·실패와 취소 등 상세 규칙
- 특성의 중복 습득, 선택 가능한 후보가 없는 경우와 선택 변경·재선택 처리
- 레벨업과 보상 선택·적용 시점, 전투·이벤트와의 연결 및 결과 처리 순서
- 중도 영입 용병의 이전 레벨 보상 적용 절차

### 장비·거래·강화

용병마다 장비를 최대 3개 장착한다. 왼손·오른손·방어구 같은 부위별 슬롯은 없으며 같은 종류와 완전히 동일한 장비의 중복 장착을 모두 허용한다. 동일 장비 세 개로 효과를 집중할 수 있다. 장비를 바꿔도 직업의 기본 공격 방식과 무기 표현은 유지한다. 도적에게 대검 장비를 장착해도 단검 전투를 유지한다.

장비별 효과와 수치는 고정이고 무작위 옵션·수치를 붙이지 않는다. 전투 중에는 변경할 수 없으며 전투 밖에서는 장소 제한 없이 장착·해제·파티원 간 교환이 가능하다. 미장착 장비는 수량 제한 없는 파티 공용 인벤토리에 보관한다. 장착·보관 장비 모두 원정 종료 시 초기화하고 다음 원정으로 이월하지 않는다.

상점에서 골드로 장비를 구매하고 보유 장비를 판매해 골드를 얻을 수 있다. 판매 재고는 유한하며 구매한 수량만큼 감소한다. 원정 중 보충하지 않고 재방문해도 복구되지 않는다. 상점별 목록·초기 수량·생성 시점·가격·되사기·판매품의 재고 편입, 특수 장비의 상점 판매 여부와 시작 장비는 미정이다.

강화 기회는 기본적으로 이벤트에서 제공한다. 플레이어가 장착하거나 보관 중인 강화 가능한 장비 한 개를 직접 선택하면 그 장비에 정해진 특수 장비로 바뀐다. 결과 선택 분기나 무작위 결과는 없으며 동일 장비가 여러 개여도 선택한 한 개만 강화한다. 기존 능력을 삭제하거나 낮추지 않고 고정 특수효과를 더하며, 능력치 증가 자체를 금지하지 않는다. 장비당 강화는 한 번이며 특수 장비는 추가 강화할 수 없다. 특수 장비를 보상으로 직접 얻는 것도 가능하고 중복 장착·원정 수명 규칙은 동일하다.

| 일반 장비 | 기본 효과 | 고정 강화형 | 강화형 효과 |
| --- | --- | --- | --- |
| 장검 | 물리공격력 +1 | 성검 | 최종 물리공격력 보너스 +2, 적 물리방어력 무시 |
| 망치 | 공격 피해 계산 후 물리방어 1 누적 파괴. 이번 공격에는 파괴 전 방어력 적용 | 방패파괴자 | 공격당 물리방어 2 누적 파괴, 적 물리방어를 0으로 만들면 대상 1턴 기절. 피해 계산 후 누적 파괴 순서 유지 |
| 단검 | 치명타 대미지 +1 | 자비 | 기존 +1 유지. 공격 피해 적용 후 살아 있는 대상의 현재 체력이 3 이하면 처형. 자비 2개는 4 이하, 3개는 5 이하 |
| 방패 | 물리방어 +1, 방향 차단 없음 | 복수 | 기존 +1 유지. 물리 피해를 받으면 자신의 물리방어력만큼 공격자에게 물리 피해. 장착한 복수마다 개별 발동 |
| 갑옷 | 체력 +2 | 촛농 갑옷 | 기존 +2 유지. 전투 시작 시 다음 피해 1회를 막는 효과 충전. 발동으로 소모하면 착용자 기준 5턴 후 재충전 |

성검 1개의 최종 물리공격력 보너스는 +2이며, 방패파괴자 1개의 공격당 최종 물리방어 파괴량은 2로 확정한다. 강화 시 일반 장비의 값 1을 각각 2로 대체한다. 표의 효과는 기획 확정이며 출시 밸런스 검증 완료를 뜻하지 않는다.

자비의 기준치 중첩과 복수의 장비별 발동은 개별 장비 규칙이다. 물리방어력 4에 복수 3개라면 물리 피해 4를 세 번 가하고 12를 한 번 가하는 방식으로 합치지 않는다. 촛농 갑옷의 5턴은 전체 라운드가 아닌 착용자의 자기 턴이며 추가 자기 턴도 센다. 이 규칙으로 새로운 추가 턴 기술을 도입하지 않는다.

그 밖의 중첩 계산, 파괴 유지 기간·하한과 0 도달 판정, 처형·반격·무효화의 발동 범위·연쇄·순서, 촛농 갑옷의 중복 소모와 정확한 재충전 시점은 미정이다. 강화 비용·조건·빈도, 미리보기·취소·대상 없음 처리와 이벤트 결과 적용 순서, 장비 개체·재고의 저장 계약 및 체력 장비 교체 시 현재 HP 처리도 별도 설계한다. 이벤트 중심 강화가 다른 경로의 전면 금지를 뜻하지는 않는다.

### 축복의 기본 구조

- 각 신의 축복은 단계별 효과가 고정되어 있다. 신별 후보 풀에서 축복 효과를 추첨하거나 선택하는 구조를 사용하지 않는다.
- 처음 받으면 해당 신의 1티어를 얻고, 같은 신에게 다시 받으면 한 단계 상승한다. 이전 효과에 새 단계의 효과가 더해진다.
- 축복과 티어는 해당 원정 동안만 유지하며, 다음 원정에는 초기화한다.
- 이벤트는 축복 조건에 쓰이는 태그를 제공한다. 관련 이벤트와 결과 처리가 모두 끝난 뒤 별도의 축복 판정·획득 단계로 연결한다.
- 각 축복 조건은 원정당 한 번만 획득 기회를 제공한다. 조건 사용 여부는 태그와 별도로 기록하며, 사용한 조건이 계속 참이거나 다시 충족되어도 재사용하지 않는다.

신별 효과, 최고 티어 수와 미정인 처리 경계는 축복 상세 문서를 따른다. 특정 신의 효과 예시를 전체 축복의 확정 규칙으로 적용하지 않는다.

## 5. 주점

주점은 기본적으로 새로운 모험가를 만나는 장소다.

- 시작 대도시에서 파티 구성과 영입을 담당하는 장소
- 최대 약 5명의 모험가 후보 제시
- 골드를 지불하여 영입
- 골드가 허용하면 여러 명 영입 가능

주점에 지나치게 많은 성장/관리 기능을 넣지 않는다.

현재 기획에서는 벤치를 사용하지 않는다. 파티가 최대 인원에 도달한 뒤 새로운 모험가를 어떻게 영입할지는 추후 결정한다.

장비 상점 재고는 원정 중 보충하지 않으며 재방문해도 복구되지 않는다. 영입 후보 갱신과 마을의 회복·재정비 기능 및 반복 이용 규칙은 별도 미정 사항이다. 노드 재방문 자체로 무료 회복이나 후보 갱신을 부여하지 않는다.

## 6. 게임 오프닝

초반 3~5분 안에 기본 조작과 원정의 목적을 보여준다. 시작 Node는 대도시이며, 주점에서 파티를 구성한다. 중앙 도시의 보물 회수 의뢰와 왕의 길잡이를 찾을 이유를 간결하게 전달하고, 작은 전투와 성장을 거쳐 준비 기간에 어떤 경로를 탐험할지 판단하는 상황으로 연결한다.

```text
시작 대도시의 주점 → 모험가 파티 구성 → 작은 사건과 첫 전투 → 보상/강화
→ 월드맵·왕의 길잡이 목표·남은 준비 기간 공개 → 첫 경로 선택
```

첫 전투는 고블린 습격, 도적 공격, 술집 난투 등 새로 모인 파티가 겪을 법한 작은 사건으로 구성할 수 있다. 이 사건을 원정 전체의 필수 갈등으로 이어 붙이지 않는다.

Opening Event는 시작 Node의 최초 방문에 발생하며 한 런에 하나 포함하는 특수 Standalone Event다. 최초 방문에는 Opening만 발생하고, 이후 특별한 State·Tag·Arc의 계기로 새 조건이 열리지 않는 한 다른 이벤트가 발생하지 않도록 데이터를 구성한다. 시작 Node라는 이유로 일반 이벤트를 런타임에서 일괄 금지하지 않는다. Opening은 재실행하지 않으며, 다른 이벤트의 발생에는 실제 재진입과 기존 후보 이력 규칙을 적용한다. 왕의 길잡이라는 최종 목표는 유지하되 중간 경로와 경험할 이야기의 순서를 고정하지 않는다.

원정은 봄에 시작한다. Opening Event와 시작 장소 내부의 사건 처리에는 원정 시간을 차감하지 않으며, 월드맵 공개 후 노드 사이를 이동할 때 해당 Edge의 weight에 따라 시간을 차감한다. weight가 0인 이동에는 시간이 소모되지 않는다.

## 7. 월드맵과 진행 구조

### 7.1. 세계와 Location

고정 판타지 월드맵과 노드 기반 이동을 사용한다. 탐험 공간은 Area, 그 공간에 소속된 Node와 Node 사이의 명시적인 연결인 Edge로 구성한다. Area는 Node의 소속 공간을 나타내는 parent이며, Area 자체를 Node로 취급하지 않는다. 주요 랜드마크의 위치와 장소 사이의 지리적 연결은 고정되어, 플레이어가 세계를 기억할 수 있게 한다.

원정의 시작 Node는 인류가 밝혀낸 세계의 중심부에 있는 대도시다. 인류가 지금까지 밝혀낸 장소들은 이 도시를 중심으로 방사형으로 펼쳐져 있으며, 원정은 알려진 세계에서 출발해 미지의 장소를 찾아가는 여정이다.

현재 탐험 화면의 이동 대상은 현재 Area에 소속된 Node로 제한한다. 현재 Node에서 직접 이동할 수 있는 이웃 Node와 연결 Edge는 보여주지만, 목표까지 이어지는 전체 경로는 미리 공개하지 않는다. 같은 Area라는 이유만으로 모든 Node·Edge를 공개하거나 서로 연결하지 않는다. 플레이어는 같은 Area 안에서 명시된 Edge와 통행 조건을 따라 이동한다. 마을의 상점·주점 같은 시설과 던전의 방·구역에도 이 구조를 적용한다.

다른 Area의 Node는 현재 탐험 화면의 이동 대상 Node로 표시하거나 이동 명령의 목적지로 직접 선택할 수 없다. 다른 Area에 있는 목표의 위치 정보 안내와 직접 이동 가능 여부는 구분한다. 다른 Area로 이동하려면 현재 Area의 Entrance Node를 목적지로 선택하여 도착해야 한다. Entrance는 지정된 다른 Area의 Node로 전환하며, 전환 후에는 도착한 Area에 같은 정보 공개 규칙을 적용한다. Area 사이를 일반 Edge 이동으로 직접 연결하지 않는다.

사건이나 목적지가 그래프에 없는 지리적 연결을 임의로 만들지 않는다. 노드 사이의 경로는 실제 그래프 위에서 선택하는 이동 경로이며, 필수 사건의 다음 장소에 도달하도록 묶인 별도 진행 단위가 아니다.

Location에는 마을, 숲, 폐광, 주점, 신전, 요새와 여러 미지의 장소가 포함될 수 있다. 모든 Location이 초자연적이거나 영구 이득을 제공하는 것은 아니다. 영구 이득을 주는 특별 장소는 한정된 일부 Location이며, 원정 목표 지정은 장소 자체와 구분되는 해당 원정의 역할이다. Goal Node를 별도 노드 타입으로 두지 않는다. Area·Node·Edge·Entrance의 전환 대상과 기존 Location 데이터를 연결하는 구체적인 스키마는 미정이다.

고정된 장소에서 겪는 사건과 실제 여정은 런마다 달라질 수 있다.

**«세계는 고정되어 있지만, 그 세계에서 벌어지는 모험은 매번 달라진다.»**

프로토타입에서는 일러스트 기반 2D 월드맵을 사용한다. 노드 간 이동의 자유와 캐릭터를 직접 움직이는 자유 이동 오픈월드는 구분한다.

### 7.2. 이동과 재방문

이미 지나온 Node로 돌아갈 수 있다. 플레이어는 현재 Area 안에서 연결된 길을 따라 재방문하거나 갈림길로 돌아가 목적지를 바꿀 수 있다. 재방문 허용은 노드 사이의 모든 통행 조건을 무시한다는 뜻이 아니다. 실제 이동 가능 여부는 명시적인 Edge와 해당 경로에 정의된 조건을 따른다.

반복 원정에서 이미 밝혀진 구간을 통과하는 방식과 그때의 이동 시간 처리는 미정이다. 아래는 Node·Edge 이동의 기본 규칙이며, 이미 밝혀진 구간에 적용할 별도 이동 처리를 확정하지 않는다.

이동 명령의 목적지는 현재 Area의 Node로 제한한다. 플레이어가 지정한 목적지가 Entrance이면 다음 순서로 도착을 처리한다.

1. 이동한 Edge의 weight를 차감하고, Entrance에 실제 진입하여 방문을 기록한다.
2. 입구 Node의 방문·이벤트와 결과를 처리한다. 일반 이벤트에는 기존 첫 방문·재방문 규칙을 적용하며, 특별 장소 발견만으로 자동 종료하지 않는다. 길잡이 획득 성공이나 전투 패배로 원정이 끝났다면 전환하지 않고 멈춘다.
3. 종료되지 않고 일반 탐험이 계속되면 추가 입력 없이 지정된 다른 Area의 Node로 한 번 전환한다. 최종 도전 진행 중에는 일반 Area 전환을 실행하지 않는다. 전환 비용은 0이며 현재 Area와 위치를 변경하고 새 Area에 정보 공개 규칙을 적용한다.
4. 전환 도착 Node에도 실제 진입과 방문을 기록하고, 최종 도전 진입이라면 특수 콘텐츠를, 그 외에는 첫 방문·재방문 규칙으로 이벤트를 처리한다. 입구 이벤트에서 변경된 State·Tags와 런 공통 소비도 반영한다. 도착지가 다시 Entrance여도 자동으로 재전환하지 않는다.
5. 도착지 이벤트와 결과까지 처리한 뒤에도 종료되지 않고 일반 탐험 중이라면 시간 소진을 판정한다. 이미 진행 중인 최종 도전에 다시 진입하지 않는다.

이 전환 한 번과 도착지 처리는 목적지 Entrance에 이르는 Edge의 도착 처리에 포함한다. 이동으로 시간이 0이 되어도 이 범위까지 처리하지만, 그 후 시간이 소진된 상태에서 새로운 Edge 이동은 시작하지 않는다. weight가 0인 Edge도 예외가 아니다.

이동 경로에서 Entrance를 경유하는 경우에는 Area 전환만 생략하며, 해당 Node의 방문 이력과 이벤트는 기존 진입 규칙에 따라 판정한다. 경유 Node의 이벤트로 이동이 잠시 멈춰도 그 Node가 이동 명령의 목적지로 바뀌지 않으며, 해당 Node 처리 후 시간 소진을 판정한다.

현재 서 있는 Entrance를 다시 선택했을 때의 처리와 이전 Area로 돌아오는 방식은 미정이다. 화면을 열거나 닫는 행위 자체는 Node 재진입이 아니다. 입구 이벤트가 정상 완료되고 일반 탐험이 계속되면 전환을 자동으로 계속한다. 최종 도전 진행 중에는 이 일반 전환으로 돌아가지 않는다. 돌아간다는 선택지 등으로 전환을 취소하는 처리는 현재 지원하지 않으며 도입하려면 별도의 취소 규칙이 필요하다.

회복을 위한 반복 왕복은 금지된 행동이 아니라, 남은 원정의 기회를 얼마나 사용할지 판단하는 행동으로 다룬다. 새로운 단서 확인이나 준비를 바꾼 재도전을 일률적으로 막지 않는다.

Node 사이의 이동에는 통과한 각 `Edge.weight`만큼 원정 시간을 소모한다. 같은 Edge를 다시 이동할 때도 해당 비용을 적용하며, weight가 0이면 재이동에도 시간이 들지 않는다. 재방문과 회복을 위해 양수 weight의 Edge를 오가는 경우에는 그 이동 시간이 기회비용을 만든다. 시간 비용이 없는 시설·방·구역 사이의 내부 연결은 weight 0으로 표현한다. Edge별 weight를 거리와 어떤 방식으로 환산할지는 추후 정한다. Entrance 전환 자체는 시간 비용 0으로 처리하며, Area 사이에 일반 Edge를 추가하지 않는다.

### 7.3. 최종 목표와 특별 장소

최종 목표는 정해진 한 장소에서 왕의 길잡이를 획득하는 것이다. 목표 지정은 해당 Node의 역할이며 별도 Node 타입을 요구하지 않는다. 목표 장소는 길잡이를 지닌 채 행방불명된 왕의 마지막 행선지를 중심으로 구상한다. 구체적인 지명·지형·왕의 행적과 최종 난관은 미정이다.

왕의 길잡이는 옛 문명의 왕가가 소유했던 신비로운 도구로, 왕실의 도로와 숨겨진 통로를 드러낸다. 중앙 도시는 이를 확보해 옛 문명을 계승한다는 정통성을 얻으려 한다. 길잡이를 지닌 자가 이 대륙의 왕이 된다는 전승은 평범한 모험가가 왕의 유산을 손에 넣는 상승감을 준다. 왕권이 마법적으로 보장되는지, 계승 자격이나 사회적 믿음인지, 사람들이 실제로 복종하는지는 정하지 않았다. 상세 로어는 [WorldLore.md](WorldLore.md)를 따른다.

시간제한 전에는 언제든 목표 Node로 이동해 최종 도전을 시작할 수 있다. 특정 성장 수준이나 모든 스토리라인의 완주를 공통 진입 조건으로 추가하지 않는다. 이야기에서 얻은 정보·동료·장비의 최종 사건 반영과 개별 조건은 조기 도전 가능 원칙에 맞춰 설계한다. 조기 도전에 별도 보상·점수·이득을 붙이지 않는다.

목표 위치는 안내하되 전체 경로를 미리 공개하지 않는 기존 방향을 유지한다. 현재 Node에서 바로 이동할 수 있는 이웃과 Edge를 보여주고 이후 연결은 탐험으로 알아낸다. 다른 Area의 목표 위치 안내는 직접 이동 명령과 구분하며, 일반 이동으로 접근할 때는 Entrance를 거친다. 구체적인 안내·접근 UI와 조기 도전의 이동 시간 처리는 미정이다.

목표에 출발점에서 제한 시간 안에 도달 가능한 경로가 최소 하나 존재하도록 구성한다. 실제 Edge의 weight·통행 조건과 Entrance 전환을 포함해 검증하되 경로 전체를 공개하지 않는다. 우회·재방문으로 시간을 소진하면 별도의 강제 최종 도전 전환 규칙을 따른다. 이 강제 전환을 그래프 단절이나 잘못된 배치의 대체 처리로 사용하지 않는다.

특별 장소의 발견·기록·영구 이득은 최종 목표와 별개의 탐험 성과로 유지한다. 미해금 특별 장소 중 하나를 런 목표로 추첨하거나, 전체 해금 후 이미 발견한 장소를 목표로 바꾸던 이전 규칙은 단일 최종 목표로 대체한다. 특별 장소를 발견한 사실만으로 왕의 길잡이를 획득하거나 원정에 성공한 것으로 처리하지 않는다.

### 7.4. 준비 기간과 흰밀물

한 런의 시간제한은 최종 도전까지 탐험하고 파티를 성장시킬 준비 기간이다. 봄에 출발해 겨울과 흰밀물을 맞는 테마를 유지하되, 흰밀물 도래를 곧바로 원정 종료로 처리하던 이전 규칙은 사용하지 않는다.

흰밀물 안에서는 마법처럼 원래 왔던 길로 되돌아가 새로운 곳으로 계속 나아갈 수 없다는 세계관은 유지한다. 이 설정과 시간 소진 후 최종 도전 전환을 어떻게 연결할지는 미정이다. 강제 이동이 흰밀물의 보편적인 순간이동 능력이라고 정하거나, 최종 난관을 흰밀물 자체로 바꾸지 않는다. 계절을 실제 아트·환경 변화로 표현할지도 미정이다.

Node 사이의 이동에는 통과한 Edge.weight만큼 시간을 소모하며 0도 허용한다. 노드 내부의 이벤트·전투·조사·대화·거래·휴식·회복에는 별도 시간을 차감하지 않는다. 같은 Edge를 다시 이동해도 해당 weight를 적용하며 Entrance 전환 자체는 비용 0이다. 회복과 재정비는 남은 준비 기간을 되돌리지 않는다.

시간이 소진되어도 현재 도착 방문의 이벤트·전투·보상 및 결과를 모두 완료한다. 목적지 Entrance라면 입구 이벤트, 비용 0의 전환 한 번, 도착 Node의 이벤트와 결과까지 포함한다. 아직 원정이 진행 중이면 마지막에 소진을 판정하고 최종 도전으로 전환한다. 중간 경유 Node에서 이 조건을 만족하면 남은 일반 이동 경로를 계속하지 않는다.

강제 전환 방식은 목표 Node로 이동시키는 방식과 목표 이벤트를 발생시키는 방식 중 추후 결정한다. 전환 판정 이후에는 weight 0을 포함한 일반 탐험 이동을 새로 시작하지 않는다. 강제 전환 자체의 위치 변경·이동 비용·UI·재진입 방지는 별도 설계 대상이며, 이미 최종 도전 중인 경우 다시 전환하거나 최종 사건을 중복 실행하지 않아야 한다.

정확한 총 시간량, Edge별 시간 산정과 최종 도전 진입 후 복귀·실패 처리는 미정이다. 소진은 그 자체로 실패나 종료 결과가 아니며, 이미 확정된 성공·전투 패배를 덮어쓰지 않는다.

### 7.5. 경로 선택의 의도

목표까지 전진하는 일, 곁길을 조사하는 일, 새로운 단서를 따라 되돌아가는 일과 회복을 위한 재정비 사이에 선택이 생겨야 한다.

한 런에 세계 전체를 탐험할 수 없도록 하되, 제시된 목표에 제한 시간 내 도달할 수 있는 경로는 최소 하나 보장한다. 최단 경로만 정확하게 선택해야 겨우 목표에 도달하는 구조를 기본으로 삼지는 않으며, 의미 있는 우회와 재방문에 사용할 여유를 검증한다. 경로 전체를 모르는 상태의 선택이 무작위 추측에만 의존하지 않도록, 방향을 판단할 정보의 종류와 공개 수준은 후속 논의한다.

플레이어가 목적지와 실제 여정을 선택하도록 만들며, 선택적 장소나 사건을 모두 소비해야 원정을 마칠 수 있는 구조로 만들지 않는다.

## 8. 이벤트와 사건군, 원정 종료

### 8.1. 원정의 이야기와 이벤트

**자유로운 중간 여정과 전투·성장 위에 사전에 설계한 스토리라인을 제공한다.** 최소 3개는 콘텐츠 목표이며, 각 이야기의 구체적인 내용·순서·상호 관계·완주 조건은 별도 설계한다. 스토리라인 때문에 장소 이동을 서로 분리된 일방통행 루트로 고정하지 않는다. 최종 목표는 왕의 길잡이 하나이며, 이야기 완주를 최종 도전의 공통 필수 조건으로 새로 정하지 않는다.

이벤트는 개발 단계에서 정적으로 제작한다. 런 시작 시 사용할 Arc와 일반 Standalone Event를 선정하여 런 공통 정규 이벤트 풀을 구성하고, 각 Node에 위치상 발생 가능한 이벤트의 후보 목록을 미리 연결한다. 이 풀은 이번 런의 이벤트 포함 여부와 소비 상태를 관리하는 논리적인 덱이며, 방문할 때마다 전체 덱을 순회하는 방식은 사용하지 않는다.

노드별 목록은 현재 조건과 무관한 잠재 후보의 목록이다. 런 시작 시 Tags, State, Arc 상태·Stage가 맞지 않는 이벤트와 아직 열리지 않은 Arc 후속 이벤트도 위치상 가능하면 포함한다. 현재 유효한 후보나 실제 발생할 이벤트, 여러 장소에서 가능한 이벤트의 발생 장소 하나를 런 시작에 확정하는 것은 아니다. Opening과 최종 도전 콘텐츠는 정규 잠재 후보 목록에서 제외하고 특수 규칙으로 처리한다. 특별 장소의 발견을 이벤트와 연결하는 방식은 후속 명세에서 정한다.

여러 Node에 연결된 동일 이벤트는 같은 Event ID 또는 공유 참조를 사용하며, 노드마다 독립적으로 복제하거나 소비하지 않는다. Tags나 State가 변할 때 방문하지 않은 Node의 목록을 교체하지 않으며, 실제 진입 시 해당 Node의 목록을 최신 상태로 검사한다. 구체적인 목록·참조 데이터 형식은 후속 명세에서 정한다.

이벤트는 Node의 실제 진입을 계기로 발생하는 서사 사건이다. 일러스트와 본문을 제시하고, 선택지 또는 자동 진행을 거쳐 결과 문구와 Effect를 처리한다. 전투와 그 밖의 승인된 결과를 발생시킬 수 있다. 상점 거래, 모험가 영입 등 일반 시설 이용 UI는 이벤트와 구분하며, 이벤트가 없는 방문에도 시설을 이용할 수 있다. 서로 다른 사건의 연결에는 State와 Tags를 사용하고, Arc 내부의 진행에는 Arc Stage도 사용한다. 다음 Event ID를 직접 지정하는 고정 체인을 전제로 하지 않는다.

축복과 연결된 선택지도 Result에서 축복을 직접 지급하거나 티어를 올리지 않는다. Result가 반영한 태그·상태를 바탕으로 별도의 축복 시스템이 미사용 조건을 검사한다. 연결 규칙은 [EventSystem.md](EventSystem.md), 축복 조건과 티어의 상세 규칙은 [BlessingSystem.md](BlessingSystem.md)를 따른다.

현행 이벤트 데이터와 결과 계약, 새 원정 설계와의 차이는 `EventSystem.md`를 따른다. 이벤트는 장소에서 겪는 서사와 결과를 담당하고, 원정 시스템은 목표 지정·시간·종료와 신규 발견 기록의 확정을 담당한다. Area·Node·Edge·Entrance, 특별 장소·영구 해금·발견 기록을 연결하는 구체적인 데이터 형식은 후속 결정이 필요하다. 원정 시간은 이벤트 결과가 아니라 Unity 이동 런타임에서 관리하며, Edge 이동에는 weight를 적용한다. 이번 문서 개정으로 현행 JSON·CSV나 Unity 구현의 마이그레이션까지 완료된 것은 아니다.

### 8.2. Arc

Arc는 시작, 진행과 결말을 가진 선택적 퀘스트 라인이다. 상하위 분류를 두지 않으며, 이 문서에서 Arc는 이 사건군만을 뜻한다.

- 한 런에 Arc가 없거나 여러 개 포함될 수 있다. 플레이어가 포함된 Arc를 전부 시작하거나 완료할 필요는 없다.
- 여러 이벤트로 구성되지만 고정된 단일 체인일 필요는 없다.
- Introduction의 정상 완료 가능한 모든 Result에는 Arc를 `Active` 또는 `Completed`로 전환하는 설정이 필요하다.
- 선택, 이동 경로, State와 현재 진행 단계에 따라 일부 중간 사건을 건너뛸 수 있다.
- Arc의 완료는 해당 사건군의 종결이다. 그것만으로 원정을 성공 처리하거나 종료하지 않는다.
- 원정 목표의 정보나 단서 획득에 관여할 수 있지만, 모든 Arc를 원정 목표 Location에 종속시키지는 않는다.

예: 오크 침공 Arc

```text
오크 정찰대 → 불타버린 농장 → 붙잡힌 오크 → 오크 야영지 → 오크 족장
```

이 예시는 사건의 연결을 설명하며, 모든 중간 장소를 반드시 순서대로 방문해야 한다는 뜻은 아니다. 사건의 구체적인 분기와 발생 조건은 별도로 정의한다.

### 8.3. Standalone Event

Standalone Event는 Arc에 속하지 않는 독립 사건이다.

- 다른 Arc의 진행 상태를 직접 변경하지 않는다.
- State와 Tags를 통해 다른 사건의 조건에 간접적인 영향을 줄 수 있다.
- Opening Event는 시작 장소의 도입을 담당하는 특수 Standalone Event다.

### 8.4. Location 도착과 재방문

Node의 실제 진입을 이벤트 발생의 기본 계기로 삼는다. 경유와 Entrance 전환 도착을 포함한 실제 진입에서 해당 Node의 잠재 후보 목록만 대상으로 현재 State, Tags, Arc 상태·Stage, 선택지 조건과 런 공통 소비 상태를 검사하여 유효 후보를 구한다. 첫 방문에도 일반 이벤트가 반드시 발생하지는 않는다. 유효한 후보가 없으면 정상적인 무이벤트 방문으로 처리하며, 장소를 탐색하거나 시설을 이용하고 연결된 다른 노드로 이동할 수 있다. 후보가 없다는 이유로 콘텐츠 구성 오류로 보거나 임시 이벤트를 생성하지 않는다.

정규 이벤트는 정상 완료 시 런 전체에서 소비되어 같은 런에 한 번만 실행된다. 다른 Node에 같은 이벤트의 참조가 남아 있어도 다시 유효 후보가 되지 않으며, 모든 노드별 목록에서 참조를 물리적으로 삭제할 필요는 없다. 이미 해결한 이벤트와 그 보상을 단순 재방문만으로 다시 제공하지 않는다. 일반적인 재방문은 새로운 탐험 기회로 취급하지 않으며 일반 이벤트를 다시 추첨하지 않는다.

재방문에는 **해당 노드의 과거 탐험 기회에서 후보가 아니었던 이벤트가 현재 State, Tags, Arc 조건으로 새롭게 유효해진 경우에만** 새로운 탐험 기회를 부여한다. State나 Tag가 변경되었다는 사실만으로는 충분하지 않다. 이전에 사용하지 않은 진입 Edge를 탔다는 사실도 공통 이벤트 기회를 부여하지 않으며, 기존 `NewEntryEdge` 규칙은 사용하지 않는다.

노드별 잠재 후보 목록, 방문 시점의 유효 후보, 실제 선택된 이벤트, 해당 노드의 과거 후보 이력과 런 공통 소비 상태는 구분한다. 잠재 목록에 연결되었다는 사실이나 멀리서 조건이 열렸다는 사실만으로 방문 후보 이력에 기록하지 않는다. 유효한 탐험 기회에 선택 대상 후보가 있으면 별도의 무이벤트 확률 판정 없이 일반 이벤트 1개를 처리한다. 하나의 노드 진입에서 여러 조건이 동시에 충족되거나 여러 후보가 열리더라도 일반 이벤트는 최대 1개만 발생한다. 실제 선택된 이벤트뿐 아니라 그 기회에 유효했던 후보 전체의 이력을 관리하여, 선택되지 않은 기존 후보를 반복 왕복으로 소진하지 못하게 한다. 과거 후보가 잠시 무효가 되었다가 다시 유효해진 경우도 새 후보로 취급하지 않는다. 이후 다시 기회를 얻으려면 과거 탐험 기회에 없었던 새 유효 후보가 필요하다. 후보 이력의 구체적인 데이터 구조와 갱신 시점은 미정이다.

현재 이벤트의 결과로 다른 이벤트 조건이 열려도 같은 진입에서 일반 이벤트를 연속 실행하지 않는다. 다음 실제 재진입에서 조건과 후보 이력을 검사한다. 화면을 열고 닫는 행위는 Node 재진입으로 계산하지 않는다. Entrance를 경유할 때 Area 전환을 생략해도 방문 이력과 이벤트 판정은 생략하지 않는다.

Entrance 자체에도 이벤트를 배치할 수 있다. 목적지 Entrance는 입구 이벤트와 결과를 처리한 뒤 전환하고, 변경된 상태로 도착지의 방문·이벤트를 처리한다. 입구와 도착지는 서로 다른 Node이므로 각각 일반 이벤트 1개가 발생할 수 있으며, 같은 Node 진입에서 연속 실행하지 않는 규칙과 충돌하지 않는다. 평범한 입구는 한쪽에만 사건을 배치하여 빈도를 조절할 수 있다. 자동 전환 처리 중에는 시설 이용 UI를 끼워 넣지 않으며, 상점 같은 시설은 인접하거나 내부의 별도 Node에 배치하는 것을 권장한다.

최종 목표 Node의 도전은 정규 이벤트의 무작위 선택·재방문 후보 이력이나 정규 풀 고갈 때문에 막히지 않도록 특수 콘텐츠로 처리한다. 도착만으로 성공하지 않으며 마지막 난관과 왕의 길잡이 획득 결과를 연결한다. 특별 장소의 일반 발견은 최종 도전·획득 성공과 구분하고, 발견만으로 Entrance 전환이나 탐험을 중단하지 않는다. 시작 Node의 Opening은 기존 특수 진입 규칙을 유지한다. 현행 Goal 데이터와 새 최종 도전 계약의 대응은 `EventSystem.md`를 따른다.

### 8.5. 최종 도전과 원정 종료

왕의 길잡이를 찾는 최종 목표 장소는 하나이며, 그곳의 최종 난관을 해결하여 보물을 실제로 획득하면 성공한다. 도착, 보물의 단순 목격이나 전투 승리만으로 자동 성공 처리하지 않는다. 최종 사건의 결과가 길잡이 획득까지 연결되도록 구성하고 검토한다. 성공 결말의 중심 감정은 **«마침내 찾았다»**다.

보물을 손에 쥐는 순간 이번 모험을 끝낸다. 도시 귀환·납품·포상 수령은 필수 플레이가 아니며, 실제 즉위·왕국 통치·후속 정치 결과나 보물을 도시에 넘길지 왕위를 주장할지 고르는 엔딩 분기를 추가하지 않는다. 구체적인 엔딩 화면·문구·효과는 미정이다.

현재 종료 기준은 다음과 같다.

- `GoalSuccess`: 최종 사건의 왕의 길잡이 획득 결과를 정상 완료한다.
- `BattleDefeat`: 기존 전투 패배 규칙으로 종료하며 패배한 사건의 후속 효과를 적용하지 않는다.
- 시간 소진은 종료 사유가 아니라 최종 도전으로 강제 전환하는 계기다. 기존 `TimeExpired` 종료 규칙은 대체한다.

시간 소진은 각 Edge의 현재 도착 처리를 모두 마친 뒤 판정한다. 현재 방문의 사건·전투·보상·결과를 중간에 끊지 않으며, 목적지 Entrance는 입구 이벤트 → 비용 0의 Area 전환 한 번 → 도착지 이벤트까지 처리한다. 입구나 도착지에서 성공·전투 패배가 확정되었다면 남은 처리와 전환을 중단하고 그 결과를 유지한다. 경유 Entrance는 전환만 생략하고 해당 Node의 사건·결과 뒤 판정한다. 소진 판정 뒤에는 선택해 두었던 남은 경로나 weight 0인 일반 이동을 계속하지 않고 최종 도전으로 전환한다.

제한 전에는 언제든 목표 Node로 이동해 도전할 수 있다. 일찍 도전했다는 이유로 보상·점수·이득을 더 주지 않는다. 최종 도전 진입 후 복귀 가능 여부, 전투 패배 외 실패의 정의와 처리, 별도 중도 포기 기능은 아직 정하지 않았다. 특별 장소 발견 후 자유롭게 종료하던 이전 규칙을 새 성공 조건으로 사용하지 않는다. 축복 평가·지급과 종료가 겹치는 정확한 후처리 경계도 별도 결정한다.

원정이 종료되어도 미완료 Arc의 상태를 강제로 변경하지 않는다. Pending·Active 상태와 종료 당시 진행 내역을 그대로 기록하며, 종료 자체로 Completed나 Abandoned로 바꾸지 않는다. 연대기·후일담과 영구 지도에 확정하는 장소 발견 기록은 구분한다.

런 공통 정규 이벤트 풀의 고갈은 종료 조건이 아니다. 최종 도전은 일반 이벤트의 무작위 선택이나 남은 정규 후보의 존재에 의존하지 않도록 구성한다. 목표 경로의 단절이나 도달 불가능한 배치는 구성 오류로 검토하며 강제 전환으로 숨기지 않는다.

### 8.6. 발견 기록과 영구 해금

이번 원정의 신규 발견과 이전 원정에서 확정한 영구 발견 기록은 구분한다. 특별 장소의 발견·영구 이득 체계는 여정의 별도 성과로 유지한다. 왕의 길잡이 획득 성공과 시간 소진 후 최종 도전이라는 새 구조에 맞춘 기록 확정·무효화 시점 및 조건은 후속 결정이 필요하다. 이전의 ‘특별 장소 발견 여부에 따라 흰밀물·자발적 종료 때 확정 또는 무효화’ 규칙을 새 종료 흐름에 그대로 적용하지 않는다.

보존된 장소는 이후 런에도 지도에 밝혀진 지역으로 남으며 `발견자: ○○원정대`와 같이 발견 원정대를 표시한다. 목표 안내나 인접 Node 공개만으로 영구 발견 기록을 만들지 않는다. 이전 원정에서 확정한 지도·발견자·영구 해금은 현재 원정의 실패 때문에 지우지 않는다.

성과를 보존한 특별 장소는 이후 모든 런에 적용되는 영구 이득을 해금한다. 예를 들어 요정의 샘 발견으로 `전투 종료 시 살아 있는 모든 용병은 체력 1 회복`을 얻는 방식이다. 실제 장소 목록·효과·수치는 미정이며 모든 장소가 영구 강화를 제공하지 않는다. 특별 장소의 수와 이득은 유한하며 전체 해금 후 추가 영구 강화를 계속 지급하지 않는다. 전체 해금 여부로 왕의 길잡이라는 최종 목표를 변경하지 않는다.

준비 기간의 특별 장소 발견만으로 탐험을 끝내거나 별도 후속 모드로 전환하지 않는다. 성공·전투 패배 등 새 종료 결과별 신규 발견 기록과 해금의 보존 정책, 전체 해금 이후의 신규 기록 확정 조건, 발견 판정과 저장 계약은 미정이다.

## 9. 의도적으로 제외·보류한 요소

현재 핵심 범위에서는 복잡한 TFT식 종족·직업 시너지, Heroes식 전략 월드와 복잡한 성장 재화 시스템을 제외하거나 보류한다.

자유 이동 오픈월드는 사용하지 않는다. 이는 월드맵의 노드 재방문을 금지한다는 뜻이 아니라, 노드 기반 이동을 유지한다는 뜻이다.

고정 영웅·주인공과 벤치 시스템에 대한 기존 제외 범위는 유지한다. 현재 전투 방식은 [BattleSystem.md](BattleSystem.md)의 헥스 턴제 전투를 따르며, 과거 오토배틀러 안의 제외 문구를 최신 전투 규칙에 적용하지 않는다.

현재 확정된 골드 사용처는 주점의 모험가 영입과 상점의 장비 구매다. 보유 장비를 판매하여 골드를 얻을 수 있다. 회복·재정비 비용과 그 밖의 사용처는 미정이다.

새 시스템은 탐험과 발견의 경험에 필요한지부터 판단한다. 성장의 세부 종류나 관리 기능을 늘리는 것이 원정 구조의 검증보다 앞서지 않게 한다.

## 10. 개발 범위 원칙

한 번에 거대한 세계를 완성하기보다, 서로 다른 경로와 준비·도전 시점이 의미 있는 선택을 만드는 작은 지역부터 검증한다. 한 런의 콘텐츠 양과 전체 세계의 규모는 분리한다.

장소의 특징, 발견 장면, 도중의 사건과 전투·성장 리소스가 함께 제작 범위를 결정한다. 모든 Location에 독자적인 전투와 긴 Arc를 붙이지 않는다.

모험가와 성장 콘텐츠의 제작량은 직업별 레벨 보상표, 선택 후보군과 공용 특성의 규모에 맞춰 검토한다.

많은 모험가를 얕게 만드는 것보다 적은 모험가의 성장 전후를 확실하게 만드는 원칙을 유지한다. 장소 역시 작은 장식보다 기억에 남는 특징과 탐험상의 역할을 우선한다.

아트는 Unity Asset Store와 AI 생성 리소스를 적극적으로 활용한다. 이동·목표·시간 규칙을 검증하기 위해 모든 장소의 최종 아트를 먼저 완성할 필요는 없다. 봄에서 겨울로 이어지는 계절 변화도 우선은 시스템을 설명하는 테마이며, 실제 환경·조명·식생 변화로 구현할지는 미정이다.

## 11. 프로토타입 우선순위

### 11.1. 새 원정 구조의 검증

새 구조의 핵심 가설은 다음과 같다.

**«자유롭게 장소를 탐험하며 전투와 파티 성장으로 준비하고, 전설의 보물을 손에 넣는 마지막 도전에서 그 성과를 확인하는 것이 재미있다.»**

일러스트와 전투 없이 노드 이동·텍스트 이벤트·선택지만 사용한 시험에서는 읽는 재미와 선택·이동의 진행감이 약했다. 이는 전투를 포함한 전체 게임의 재미를 검증한 결과가 아니다. 새 흐름에서는 이야기·전투·체감 가능한 성장·결말의 연결을 함께 확인한다.

검증할 흐름은 다음과 같다.

- 소수의 Area, 명시적인 Node·Edge와 되돌아갈 수 있는 갈림길, 단일 최종 목표 Node
- 자유로운 중간 경로 이동과 사전 설계 스토리라인의 연결. 장소 선방문·이야기 중단·동시 진행의 세부 처리는 먼저 설계
- 현재 Area의 이웃·연결 표시와 Entrance 이동, 다른 Area 목표의 안내와 직접 목적지 선택의 구분
- 목적지 Entrance의 입구 이벤트 → 비용 0의 전환 한 번 → 도착지 이벤트 → 시간 판정 순서, 경유 시 전환만 생략, 전환 도착 Entrance의 자동 재발동 방지
- 입구 Result가 바꾼 상태와 런 공통 이벤트 소비를 반영한 도착지 처리, 양쪽 Node의 독립적인 방문·후보 이력
- 마지막 이동에서 시간이 소진되어도 도착 범위의 사건·전투·보상·결과를 마치고 최종 도전으로 전환. 확정된 성공·전투 패배를 시간 소진으로 덮어쓰지 않는 처리
- 시간 소진 판정 뒤 남은 일반 경로나 weight 0 이동으로 탐험을 연장하지 않고, 이미 진행 중인 최종 도전을 중복 실행하지 않는 처리
- 제한 전의 자율 도전과 시간 소진 후의 도전. 조기 도전에 별도 보상·점수·이득을 붙이지 않는 규칙
- 단순 도착·목격·전투 승리와 실제 길잡이 획득을 구분하고, 획득 결과 완료 시 모험을 끝내는 흐름
- 특별 장소의 발견과 최종 목표를 구분하고 발견만으로 성공·종료하지 않는 처리. 영구 기록·해금은 새 종료 구조의 보존 계약을 정한 뒤 검증
- Edge.weight에 따른 시간 차감과 weight 0 이동, 회복·재정비 왕복의 비용
- 런 시작 시 노드별 잠재 후보 구성, 초기 조건 불충족 이벤트·Arc 후속 사건의 포함, 진입 시 최신 상태로 해당 Node 목록만 검사
- 여러 Node의 동일 이벤트가 공유하는 런당 1회 소비, 원격 조건 변화만으로 목록이나 방문 후보 이력을 갱신하지 않는 처리
- 첫 방문 후보 0개, 새 유효 후보가 생긴 재방문, 후보 전체 이력을 통한 왕복 소진 방지, 같은 진입의 정규 이벤트 연속 실행 방지
- 이벤트 없는 시설 이용과 화면 열기·닫기를 Node 재진입으로 세지 않는 처리

총 준비 시간과 Edge별 weight의 임시 수치는 확정 밸런스가 아니다. 이미 서 있는 Entrance의 재선택·복귀, 남은 시간보다 비싼 Edge의 이동 허용, 최종 도전의 강제 전환 방식·접근 UI·이동 비용·복귀·실패 후 처리와 축복 평가의 정확한 시점은 별도 결정 후 검증한다. 최소 3개 스토리라인이라는 콘텐츠 목표를 이번 프로토타입에서 모두 구현한다는 뜻은 아니다. 이벤트 길이·빈도·선택지 축소와 한 스토리라인 우선 구현의 구체 범위·일정은 아직 확정하지 않았다.

확인할 핵심은 다음과 같다.

1. 보물을 찾아 떠날 이유와 마지막에 무엇을 얻는지 쉽게 이해하는가?
2. 자유로운 우회·재방문과 이야기의 연결이 전투·성장·새 장소로 나아가는 경험을 만드는가?
3. 준비를 더 할지 일찍 도전할지 스스로 판단하며, 조기 도전의 추가 보상 없이도 챌린지가 성립하는가?
4. 마지막 방문의 결과를 충분히 경험하고 그 성과로 최종 도전에 진입하는가?
5. 보물을 실제로 손에 넣는 순간 «마침내 찾았다»라는 성취를 느끼는가?

### 11.2. 전투와 성장의 부분 검증

전투의 현재 구현·확정 규칙은 [BattleSystem.md](BattleSystem.md), 용병의 공유 성장과 전문화 보상은 [MercenarySystem.md](MercenarySystem.md)를 기준으로 검증한다. 과거 오토배틀러의 자동 이동·마나·자동 스킬을 이번 프로토타입의 기본 요구사항으로 사용하지 않는다.

공통 은신과 투명화, 도적 전문화의 Lv2·Lv5 효과와 보상 구분을 확인하되 미정인 수치·발각·해제·처리 시점을 임의로 확정하지 않는다. 전투만의 재미나 모의 승리·패배 결과를 전체 모험의 재미 검증으로 대신하지 않으며, 실제 전투·성장과 원정 진행을 연결해 점검한다.

`EventSystem.md` 개편 시에는 본 문서의 목표·재방문·종료 구조를 기준으로 하고, 위 미정 항목에서 필요한 결정을 먼저 확정한다. 기존 이벤트 명세의 런 진행 규칙과 새 구조를 그대로 혼용하지 않는다.

세계관의 미정 사항은 `World_Premise.md`를 따른다. 게임의 원정 종료 절차를 정하더라도 흰밀물의 원리, 정확한 귀환 지점이나 세계 초기화를 자동으로 확정하지 않는다.
