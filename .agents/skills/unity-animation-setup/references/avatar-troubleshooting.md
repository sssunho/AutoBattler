# Avatar 및 Rig 경고 진단

Rig 경고, 단위 차이, Copy From Other Avatar 실패가 나타날 때 읽는다. 정상인 공급자 리그에 아래 복구를 예방적으로 적용하지 않는다. 진단 요청이면 읽기만 수행하며, 복구는 승인된 수정 범위에서 진행한다.

## 원인 분리

1. 이번 임포트에서 발생한 경고 원문과 대상 파일을 확보한다. Console 조회가 비어 있다면 Importer 진단 또는 Editor 로그의 임포트 시점 이후 구간을 확인한다. 경고의 발생 시점과 파일이 일치하지 않으면 과거 경고와 새 실패를 구분한다.
2. 기준 모델과 실패 모션의 Rig 종류, Avatar 설정, 실제 Source Avatar, 단위 관련 Importer 값, 본 이름·계층과 대표 본의 로컬 위치·스케일을 비교한다. 같은 파일명만으로 호환성을 판정하지 않는다.
3. Source Avatar가 유효하고 Humanoid이며 클립의 humanMotion이 참이어도 본 Transform 불일치 경고가 남을 수 있다. 이 플래그들은 로그·단위 확인을 대체하지 않는다.

이 프로젝트의 과거 Mixamo 임포트에서는 기준 모델과 모션의 대표 다리 본 위치가 약 40.6 대 0.406으로 달랐다. 기준 모델의 파일 단위 처리와 저장된 humanoid skeleton 정보가 불일치했던 사례다. 이 수치를 정상값이나 모든 Rig 경고의 원인으로 사용하지 않는다.

## 단위 불일치가 확인된 경우

1. 기존 GUID, Avatar 참조와 authored human mapping을 보존할 복구 자료를 확보한다. 새로 생성한 자동 매핑인지 공급자가 수정한 매핑인지 구분한다.
2. 원본 단위에 맞게 기준 모델의 Importer 스케일 설정을 교정한다. Transform 크기를 맞추려고 캐릭터 프리팹이나 모든 모션에 임의의 배율을 적용하지 않는다.
3. 재임포트 후 모델 Transform과 Importer에 남은 humanoid skeleton 정보가 함께 갱신되었는지 확인한다. 스케일 플래그만 수정하고 기존 Avatar 캐시가 자동으로 맞아졌다고 가정하지 않는다.
4. **자동 생성된 매핑의 오래된 skeleton 데이터가 원인으로 확인될 때만** 현재 Unity 버전이 지원하는 방법으로 기준 Avatar를 재생성한다. 과거 복구에 사용한 humanDescription의 human·skeleton 배열 초기화는 authored 매핑을 잃게 할 수 있으므로 일반적인 초기화 절차로 사용하지 않는다. 필요한 매핑 손실이 승인 범위를 벗어나면 먼저 변경 범위를 설명한다.
5. 기준 모델을 먼저 재임포트하고 새 Avatar를 다시 로드한다. 호환되는 의존 모션의 Source Avatar가 올바른지 확인하고 필요한 경우 다시 지정한 뒤 재임포트한다.
6. 동일한 대상·로그 구간 기준으로 경고 재발 여부, 단위, Avatar 유효성, 클립 로딩과 참조 보존을 확인한다. 같은 원인으로 실패하면 진단 근거를 남기고 무작정 재생성을 반복하지 않는다.

## 다른 원인

- 필수 본 누락·잘못된 매핑·기준 자세 문제는 해당 리그의 실제 구조를 조사한다. Humanoid가 적합하지 않은 리그는 Generic 유지 등 별도 선택을 제안한다.
- 공급자별 Avatar를 잘못 섞은 경우 올바른 기존 참조를 복원한다. 모든 모델을 하나의 Y Bot Avatar로 통일하지 않는다.
- 재생 중 공격 방향이나 몸의 움직임만 어색하다면 Rig 경고와 동일시하지 않는다. Root Transform 추출, offset, Animator의 Apply Root Motion, 게임 코드의 이동·회전 제어를 구분해 조사한다. Bake Into Pose 전부 ON을 자동 처방하지 않는다.

설정과 로그만 확인했다면 Rig 임포트 문제의 해결 범위만 보고한다. 실제 게임 캐릭터의 자세나 재생 품질을 확인한 것으로 확대하지 않는다.
