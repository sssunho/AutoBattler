# Unity Animation Setup

애니메이션을 프로젝트에서 사용할 수 있도록 임포트하고, 요청한 설정만 적용한다. 외부 원본과 기존 Unity 에셋을 구분하여 기존 참조와 공급자 설정을 보존한다.

## 작업 범위와 도구

- 현재 `AGENTS.md`의 설계 승인·변경·검증 제한을 따른다. 이미 승인된 설계를 다시 승인받지 않는다. 진단이나 검토 요청은 읽기 전용이다.
- 임포트 요청만으로 다운로드·구매, Animator Controller 연결, 캐릭터의 `Apply Root Motion` 변경, Scene 배치, 게임 코드 수정, Play Mode 검증을 수행하지 않는다.
- Unity 작업은 연결된 Unity MCP를 우선 사용한다. 현재 도구와 리소스를 발견하고 `mcpforunity://custom-tools`, 연결 인스턴스, 프로젝트 경로와 Editor 상태를 확인한다. 여러 인스턴스라면 대상 프로젝트를 명시적으로 선택한다. 과거 세션 ID나 HTTP 주소를 재사용하지 않는다.
- 변경·재시도 직전에 대상 Editor가 Play Mode, 컴파일 또는 에셋 갱신 중인지 다시 확인한다. 진행 중이면 중복 변경을 보류하고 편집 가능한 상태를 확인한 뒤 적용한다. 요청 없이 Play Mode를 전환하지 않는다.
- 도구가 실제로 지원하는 Importer 조회·설정 기능을 확인한다. 이름이 `modify`라는 이유만으로 ModelImporter 변경이 가능하다고 가정하지 않는다. 파일 조사·압축 해제·복사에는 파일시스템 도구를 사용할 수 있다.
- `execute_code`는 메모리 내 C# 컴파일을 수행한다. 이 프로젝트의 컴파일 금지에서 예외가 아니다. 명시적 컴파일 허용이 없으면 기존의 컴파일 없는 MCP 기능을 사용한다. 사용할 수 없다면 조사는 계속하되, 불가능한 작업과 필요한 허용 범위를 정확히 알린다. 도구 제한을 우회하려고 Editor 스크립트를 추가하거나 UI 조작으로 전환하지 않는다.

## 입력과 변경 계획

1. 원본 경로와 대상 `Assets/...` 경로, 선택할 파일·클립, 요청한 설정을 확인한다. 폴더 전체가 대상인지 일부가 대상인지 구분한다. 이미 제공된 경로나 설정을 다시 묻지 않는다.
2. 외부 ZIP·FBX 신규 임포트, 기존 Unity 에셋 설정 변경, 읽기 전용 진단 중 해당 흐름을 선택한다. FBX의 클립 서브에셋과 독립 `.anim`을 구분한다. `.anim`에 ModelImporter 옵션을 적용하지 않는다.
3. 파일·클립 수, Rig 종류, Avatar 출처, 단위·스케일, take·프레임 범위, 루프, 마스크, 이벤트, additive 설정을 조사한다. FBX 하나에 여러 클립이 있을 수 있으며 기준 모델은 모션 수에서 분리한다.
4. 원본→대상 매핑, 수정할 설정과 보존할 설정, Avatar 의존성, 이름 충돌, 검증 방법을 변경 계획에 포함한다. ThirdParty 원본 직접 수정과 프로젝트용 복사는 요청에 맞게 선택한다. 목적지가 지정되지 않았고 선택에 따라 참조·관리 방식이 달라지면 그 차이를 설명하고 확인한다. 복사를 기본 승인으로 해석하지 않는다.

## 프로젝트 Root Transform 프리셋

새 애니메이션을 프로젝트 기준으로 설정하거나 사용자가 같은 설정을 요청하면 다음 값을 적용한다. 기존 에셋은 승인된 변경 항목만 수정한다. 사용자가 별도 값을 지정하면 그것을 우선한다.

| 항목 | Based Upon | Bake Into Pose |
| --- | --- | --- |
| Root Transform Rotation | Original | ON |
| Root Transform Position (Y) | Original | OFF |
| Root Transform Position (XZ) | Original | OFF |

이 값은 프로젝트의 선택이며 모든 모션에 보편적으로 올바른 값은 아니다. 기존 RM·InPlace 변형의 설정 차이를 먼저 확인하고, 일괄 적용이 해당 차이에 미치는 영향을 변경 계획에 드러낸다. 명시적으로 승인된 일괄 설정을 임의로 예외 처리하지 않는다. `Apply Root Motion`은 별도 컴포넌트 설정이다.

실제 필드 대응, 클립 보존 방법, 재임포트 순서는 [import-settings.md](references/import-settings.md)를 읽는다.

## 외부 ZIP·FBX 임포트

- ZIP은 `Assets` 밖의 작업 폴더에 먼저 푼다. 압축 항목의 절대 경로·상위 경로 탈출과 Windows의 대소문자 무시 충돌을 검사한다. 관련 없는 코드·씬·문서를 함께 `Assets`로 복사하지 않는다.
- 폴더 구조와 파일명을 유지하는 것을 우선한다. 평탄화·이름 변경이 필요하면 매핑과 충돌을 확인한다. 다른 내용의 기존 파일을 묵시적으로 덮어쓰지 않는다. 동일 원본 재실행은 중복 에셋을 만들지 않는다.
- 새 원시 FBX는 원본 모델·스켈레톤과 단위를 조사한 뒤 적합한 Rig를 선택한다. 인간형이라고 판단되는 애니메이션은 Humanoid 후보로 삼되 Generic·비인간형 리그를 강제로 변환하지 않는다. 기준 Avatar가 필요한 경우 원본과 호환되는 것을 사용한다. 공급자가 다르다는 이유만으로 Y Bot을 재사용하지 않는다.
- 공급자가 설정한 `.meta`, Avatar, Mask 등 Unity 에셋 묶음이면 기존 에셋 흐름의 보존 규칙도 적용한다. 최초 반입에서는 GUID 충돌 여부와 묶음 내부 참조를 확인한다. 이미 프로젝트에 등록된 에셋을 복제할 때는 새 GUID와 참조를 관리하는 Unity 복제 기능 등을 사용하고, 같은 GUID가 두 경로에 등록되도록 `.meta`를 그대로 복사하지 않는다.
- 새로 설정하는 순수 애니메이션 FBX는 Material Import를 끄고 카메라·라이트를 제외하는 것을 기본 후보로 삼는다. 기준 캐릭터 모델이나 기존 공급자 설정에 무조건 적용하지 않는다. 프레임 레이트와 정밀도를 임의로 낮추지 않는다.
- 루프 설정이 없는 새 입력은 idle·이동의 반복 여부와 공격·전환 등의 종료를 구분한다. 이름은 후보 판단에만 사용하고 매끄러운 루프를 확인했다고 주장하지 않는다. 공급자의 명시적 루프 설정은 요청 없이 덮어쓰지 않는다.

## 기존 Unity 에셋 설정 변경

- 실제 대상 Importer와 클립 설정을 기준으로 시작한다. 기존 Avatar 연결, 클립 이름·take·프레임, 마스크, 이벤트, 곡선, additive, mirror, 루프, offset을 요청 없이 초기화하지 않는다. `defaultClipAnimations`로 기존 사용자 설정 전체를 교체하지 않는다.
- Kevin Iglesias 같은 패키지에는 모델별 Avatar, 외부 Mask, RM·InPlace 변형, 별도의 포즈가 함께 있을 수 있다. 파일·폴더 이름만으로 additive 또는 부분 신체 애니메이션이라고 단정하지 않는다.
- 프로젝트용 복사는 선택 에셋과 필요한 의존성의 범위를 확인한다. 복사본이 공급자 Avatar·Mask를 계속 참조할지 함께 복제할지 정하고 참조 유효성을 확인한다. 기존 컨트롤러가 원본 클립을 사용 중이어도 임포트 작업만으로 복사본에 다시 연결하지 않는다.
- 기존 `.meta` 삭제·재생성이나 GUID 변경을 일반적인 수정 방법으로 사용하지 않는다. Unity가 생성한 전체 Importer를 보존하고 필요한 필드만 수정한다.

## 검증과 완료 조건

- 변경 전후의 대상 목록·GUID·클립 식별자와 설정 차이를 비교한다. 복사한 원본 바이트는 해시 등으로 확인한다. 새 GUID를 의도적으로 만든 복사본과 원래 에셋의 참조 보존을 구분한다.
- 재임포트 후 저장된 설정을 다시 읽어 요청값, 클립 수·프레임 범위, Avatar·Mask 의존성, 클립 로딩을 확인한다. Humanoid는 Avatar의 유효성·인간형 여부와 클립의 humanMotion을 확인한다. 짧거나 정지한 포즈를 일반 모션과 같은 길이 기준으로 탈락시키지 않는다.
- 이번 임포트 구간의 Console 경고·오류를 확인한다. MCP Console이 비어 있어도 성공으로 단정하지 않는다. 필요하면 Importer 진단이나 Editor 로그의 해당 구간을 대조한다. 기존 메시지를 지워서 성공으로 보이게 하지 않는다.
- Rig 경고 또는 100배 크기 차이처럼 단위 문제가 의심되면 [avatar-troubleshooting.md](references/avatar-troubleshooting.md)를 읽는다. 유효한 Avatar만으로 Rig 경고 해결을 판정하지 않는다.
- 연결 중단·타임아웃 후에는 실제 결과를 재조회하고 미완료 대상만 재시도한다. 동일 원인으로 실패하면 반복 재임포트를 중단하고 원인과 남은 대상을 보고한다. 진행 기록·백업은 `Assets` 밖에 두며 이번 작업이 소유한 변경만 복구한다.
- 결과에는 대상 폴더, 모델 수와 모션·클립 수, 적용값, 보존한 중요한 설정, 새 경고와 미완료 항목을 간결하게 보고한다. 설정 검증과 실제 재생 확인을 분리한다. 재생하지 않았다면 정상 자세·게임 동작까지 검증했다고 쓰지 않는다.
