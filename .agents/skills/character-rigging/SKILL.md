# Character Rigging

기준 리그 구조와 대상 캐릭터의 실제 형상에 맞게 리깅·가중치를 다룬다. 실제 파일과 수치·시각 검증을 근거로 한국어로 보고한다.

## 범위와 도구

- 현재 사용자 지시와 적용되는 `AGENTS.md`를 따른다. 진단·검토는 읽기 전용이다. 변경 전 대상·출력 경로·보존 요소·검증 방법을 정리하며, 이미 승인된 설계나 작업 허용을 다시 요청하지 않는다.
- 신규 리깅, 전체 리그 갱신, 손가락 추가, 국소 가중치 보정 중 요청된 범위를 구분한다. 모델 재디자인, 메시·토폴로지·UV 수정, 애니메이션 제작과 텍스처 후처리는 별도 요청 범위다.
- Unity Scene·GameObject·Component·셰이더·머티리얼·임포터는 요청 없이 변경하지 않는다. Unity 컴파일·빌드와 이를 유발하는 검증은 명시적으로 허용된 경우에만 수행한다. Unity `execute_code`도 컴파일을 수행하므로 이 제한에 포함된다.
- 실제 사용할 수 있는 Blender MCP와 연결 상태를 확인한다. 연결된 경우 장면과 선택 오브젝트를 읽고, 연결되지 않으면 로컬 파일로 가능한 검사를 진행하며 열린 장면을 확인했다고 주장하지 않는다.
- 미저장 Blender 작업을 버리거나 문서를 임의로 교체하지 않는다. 같은 문서를 다른 작업자와 동시에 수정하지 않는다. 별도 headless 프로세스에서 검사할 수 있으면 현재 열린 장면을 보존한다. 서브에이전트 사용은 이 스킬의 필수 조건이 아니다.

## 대상 식별과 기준 선택

- 프로젝트 루트를 먼저 확인한다. 참고 자료 안의 `Art/...`, `Assets/...`, `Captures/...` 경로는 프로젝트 루트 기준이고, 이 문서의 링크는 스킬 폴더 기준이다.
- 메시 이름·정점/면 수·크기·변환·Armature·재질 이미지 연결·이미지 경로/해상도·UV 레이어를 확인한다. 활성 오브젝트나 파일명만으로 같은 캐릭터라고 판단하지 않는다.
- 원본과 메시 좌표·토폴로지·UV·변환·재질 연결·골격 rest transform 및 필요한 Action/키프레임을 기록한다. 기존 캐릭터의 보정은 현재 Unity FBX와 실제 데이터가 일치하는 최신 편집본에서 시작한다. 오래된 구조 기준으로 최근 손가락·턱 보정을 덮어쓰지 않는다.
- 기준 리그를 사용하거나 손가락·Humanoid를 다룰 때 [기준 구조와 Humanoid](references/rig-and-humanoid.md)를 읽는다. 골격 구조 재사용과 가중치 재사용을 구분하며, 기준이 없거나 충돌할 때 다른 리그를 추측해서 만들지 않는다.

## 리깅과 가중치 수정

- 신규 리깅은 기준 이름·부모 계층·로컬 축·rest pose 규칙을 유지하며 관절 위치와 뼈 길이를 대상 체형에 맞춘다. 어깨·팔꿈치·손목·골반·무릎·발목과 팔·손의 기준 방향을 확인한다. 메시의 체형이나 UV를 리그에 맞춰 임의로 바꾸지 않는다.
- 인간형 신규 리깅과 전체 갱신은 양손 손가락 리깅을 기본 포함한다. 손가락 제외 또는 국소 보정 요청은 그 범위를 따른다. 골격·보조 뼈를 바꾸어야 하면 호환성 영향을 설명하고 적용되는 설계 승인 절차를 따른다.
- 가중치를 생성·수정할 때 [부위별 가중치와 변형 품질](references/weight-quality.md)을 읽고 관련 부위를 확인한다. 자동 가중치는 출발점이며, 누락 0·정규화·최대 영향 수만으로 올바른 변형을 판정하지 않는다. 프로젝트 기본 최대 영향은 정점당 4개다.
- 턱과 실제 목을 구분한다. Jaw가 없는 리그의 하악·턱은 Head를 따라 형태를 유지하고, Neck–Head 전이는 실제 목에 둔다. 턱을 고정한 뒤 새로 급해진 목 경계도 확인하며, 높이만으로 턱을 Neck에 묶거나 목 전체를 Head로 치환하지 않는다.
- 가중치 문제의 원인 판단이나 유사 사례가 필요할 때만 [리깅 실패·보정 사례](references/rigging-cases.md)의 관련 항목을 읽는다. 사례의 정점 번호·좌표·마스크·각도·허용 오차를 다른 캐릭터의 보정 규칙으로 복사하지 않는다.
- 국소 보정은 바뀐 정점·가중치를 기록하고 보호 영역을 비교한다. 포즈·키프레임·뼈 위치·메시·UV를 그대로 둔 상태에서 효과를 확인한다. Preserve Volume이나 다른 포즈로 잘못된 가중치를 숨기지 않는다.

## 변형 검증

- 작업 범위에 맞는 T 자세, 팔 내림, 팔꿈치·고관절·무릎 굽힘, 머리 회전을 검사한다. 턱·목 보정과 신규 전체 리깅은 머리의 좌우 회전과 숙임·젖힘을 양방향으로 확인하고 사용 모션의 회전 범위도 살핀다. 기본 자세나 작은 회전만으로 통과시키지 않는다.
- 같은 카메라·조명·포즈의 전후를 비교한다. 앞·옆·뒤와 문제 부위 근접 화면에서 잡아당김·평탄화·함몰·부피 감소·경계 꺾임·갑옷 관통을 직접 확인한다. 전신 화면만으로 완료 판정하지 않는다.
- 형상을 유지해야 하는 부분은 길이·거리 변화를 수치로 검사한다. 관절은 정상적인 접힘을 고려하여 모서리 길이·면적이 급변한 위치를 시각적으로 확인한다. 턱 개선으로 목 경계에 새 변형이 집중되지 않았는지도 비교한다.
- 승인된 실제 모션이 있으면 그 모션을 기준으로 확인한다. 없거나 재생할 수 없으면 진단 자세와 실제 애니메이션 검증을 구분한다. 이전 `MedievalKnight_Idle_Relaxed`를 새 리그에서 검증된 표준 모션으로 간주하지 않는다.
- 수치와 직접 본 시각 결과가 모두 있어야 변형 검증 완료로 보고한다. 가중치가 올바른 뒤에도 남는 문제는 체형·관절 위치·스키닝 방식·애니메이션 문제로 구분하며, 근거 없이 개선 불가능하다고 단정하지 않는다.

## 저장·FBX·보존 검사

- 사용자 지정 결과 경로를 우선한다. 미지정 시 별도 결과 파일을 제안하며 원본과 기존 결과를 보존한다. 기존 파일 덮어쓰기가 승인됐다면 원본 백업과 대상 확인 후 적용한다.
- 편집 가능한 별도 `.blend`를 남긴다. 신규 리깅의 진단 포즈는 기준 자세로, 기존 포즈 보정은 작업 전 포즈와 애니메이션으로 복원한다. 요청하지 않은 Action·키프레임·진단 손잡이를 결과에 남기지 않는다.
- FBX 출력이 요청되면 대상 메시·Armature, 단위·축·리프 뼈·애니메이션 포함 여부·텍스처 연결을 확인한다. Blender 제약이 Unity에서 그대로 실행된다고 가정하지 않는다. 베이크나 Unity 측 처리가 필요하면 승인된 범위와 구분한다.
- 저장본을 다시 열어 가중치·골격·메시·UV 보존을 검사한다. FBX를 출력했다면 가능한 경우 별도 작업 환경에서 재임포트해 가중치·골격·스케일·재질 연결을 비교한다. 기존 idle을 다룬 작업에서는 Action/키프레임을, 기존 리그 보정에서는 손가락 보정을 보존한다. T 자세본과 idle 적용본을 함께 만들었다면 두 파일의 가중치 일치도 확인한다.
- 기존 스킨 가중치 보정의 파일 비교에는 [compare_skin.py](scripts/compare_skin.py)를 별도 Blender background 프로세스에서 사용할 수 있다. 동일 포맷·오브젝트 이름·정점 대응을 전제하며 bone envelope 스키닝은 지원하지 않는다. 대응이 달라지면 같은 정점이라고 추정하지 않는다. 기본 수치 허용 오차는 0.000001, 최대 영향은 4개이며 필요하면 `--tolerance`·`--max-influences`를 승인 범위에 맞게 지정한다. 결과의 실제 비교 항목과 `not_checked`를 읽고, 비본·비변형 본 그룹의 수동 검토 요청을 무조건 가중치 오류로 해석하지 않는다. 이 검사로 시각 변형·Action 보존·Unity 재생 검증을 대체하지 않는다.
- Unity 반영이 승인된 경우 기존 GUID·하위 에셋 참조·머티리얼·클립을 보존한다. 조회 가능한 Avatar의 `isValid`·`isHuman`, 손가락 매핑과 스킨 본을 확인하되 사용 가능한 도구와 컴파일 제한을 지킨다. Blender 검사만으로 Unity Humanoid 호환성이나 모션 재생을 검증했다고 쓰지 않는다.
- 결과 파일 링크, 변경 범위, 보존 결과, 수치·시각·FBX·Unity별 실제 검사, 리뷰에서 수정한 문제와 남은 변형/미검증 항목을 보고한다.

비교 도구를 호출할 때 실제 Blender 실행 파일, 이 스킬 폴더와 입력 경로를 확인해 다음 변수에 대입한다. Blender 로그와 함께 `report_type: character-rigging-skin-comparison`인 JSON이 표준 출력으로 나온다. 검사 실패를 정상 종료로 오인하지 않도록 `--python-exit-code 1`을 포함한다.

```powershell
& $blenderExe --background --factory-startup --disable-autoexec --python-exit-code 1 --python "$skillDir/scripts/compare_skin.py" -- --before $beforePath --after $afterPath
```
